# A managed project: what makes one, and what is never yours to write

**What makes a project managed.** Two marks, and both are required: its runs bucket holds Fugaro's creation fact (a project Fugaro created), **and the GCP project carries the label `fugaro_managed=true`**. Both are written by the creating run, in the user's own terminal, not through the agent, and by nothing else: **never write that label yourself**, with `gcloud` or any other tool, and never remove it — it is a write on the project, and putting a project into managed mode or taking it out is the user's decision, not yours. The label can only narrow: a project missing it, carrying another value, or that cannot be read at all is not managed whatever its creation fact says, so its runs keep the ordinary typed confirmations — a label alone never makes a project managed. If a command refuses a project that way, read the refusal to the user and stop; `docs/gcp-setup.md` has the one line that writes the label, for the user to run. Only a project created with a budget can be applied.

**Applying one.** A managed project's agent-authored root is applied by `fugaro managed apply <root>` — a directory of this checkout, applied as the project's deployer account — and **it is refused when the project's recorded budget cannot be read**, which no flag reaches past: read that refusal to the user, then stop. A refused delete in a managed project names no flag: say which address needs the owner's approval, and stop.

**A managed project's deletes.** A managed project records, in one object at the root of its runs bucket, the addresses whose deletes and replacements its owner approves. Its writer is the owner's command, run in their own terminal window, not through the agent; it refuses an agent's session. That is a speed bump, not a boundary: your session holds the owner's credentials, so never write that object yourself, by this command or any other:

```bash user-runs
# approve the addresses a run may delete or replace
fugaro allow-delete <address>...
```

**Creating a managed project.** With init's `--create-project --managed`, the monthly budget amount is required: no default; without one nothing is created. Amount and currency are the user's decision, in their own terminal window, not through the agent: ask, never pick. `--billing-account` is the account charged; alerts fire at 50%, 90%, 100%. Both are recorded in its creation fact. On an existing project init warns `--managed` was not applied. Without `--managed` the budget is optional and nothing is recorded. `fugaro restore` refuses an agent session: say so, stop, never rebuild it by hand (`docs/gcp-setup.md`).
