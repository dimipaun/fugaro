# The `governance:` block

The guardrails a run is held to, and the one block of `fugaro.yaml` that is not a topic to ask about: **never raise it, never fill it in, and never ask the user what their guardrails should be.** Fugaro's defaults already bound a run, so a repository that writes nothing is bounded, and a block written in a repository's own file can only tighten them. Say what it is if the user asks, or if the `fugaro.yaml` they hand you carries one and they want it explained.

Each key bounds one stage at a time, and a run that passes one ends with a checkpoint report on the record and the draft pull request that carries it — never a silent kill:

| Key | What it bounds |
|---|---|
| `governance.stage_budget` | a stage's share of the run's per-run cap: `implement`, `review` and `fix`, the fix rounds' share being a fraction of the implementation's own |
| `governance.stage_tokens` | a stage's token ceiling, the same three keys |
| `governance.stage_timeout` | a stage's wall-clock ceiling, itself under `timeouts.stage` |
| `governance.max_subagents` | the most distinct sub-agents one stage may start; a run a plan graph dispatched at `trivial` or `small` is bounded at 3 whatever this says |
| `governance.review_ratio`, `governance.review_floor_calls` | review's calls against the implementation's: review that spends more than `max(floor, ratio × implement calls)` stops |

Read the keys, their defaults and their units from `fugaro validate --json` and the schema, never from memory.

`governance.tiers` is the adjacent block and is not one of these bounds: a tier's expected cost and minutes are what a run of that tier is expected to use, and nothing there moves a cap.

Two rules decide whether a value written here does anything: a value looser than the one in force is dropped with a warning that names the key, and the project layer is the one layer that may loosen, because it is where the block a run starts under comes from. That loosening is the owner's, in their own terminal, never yours: the key goes in their local layer file and `fugaro config publish FILE` publishes it. No key in the block moves the per-run cap, which stays the ceiling every stage bound sits under; a run with no per-run cap is stopped by none of the gateway's figures, since a fraction of nothing is not a budget, though its `governance.stage_timeout` still fires.

The defaults that stop runs are in the business-licensed half of the binary: a job image built without it warns once and ignores the whole block, and the keys decode and nothing stops on them.
