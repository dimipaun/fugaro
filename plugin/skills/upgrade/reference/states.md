# What fugaro upgrade prints

Each checkout starts with a line `== ` and its directory, then one line per step: the step (`pin:`, `plugin:` or `cloud:`), its state and a reason. A `summary:` closes the run with one line per checkout. A `checkout:` line means the path itself was refused (not a checkout, not a Fugaro checkout) or was the same checkout as an earlier path.

## States

| State | Meaning | What you tell the user |
|---|---|---|
| `current` | nothing to do | that it is up to date |
| `done` | the step changed something | what changed (the reason says) |
| `stale` | only with `--check`: the step would change something | what would change and why |
| `skipped` | not run here, by rule; the reason names the rule | the reason, in plain words |
| `failed` | the step stopped, and this checkout's later steps did not run | the reason, and the rerun line in the summary |
| `not run` | a step after a failed one | nothing: it runs on the rerun |

## pin

- `pinned to vX.Y.Z` (`current`): the repository's `.claude/settings.json` already pins this release.
- `the pin moves to vX.Y.Z` (`stale`): the pin names an older release or none, or the file does not wire the plugin yet; `fugaro upgrade --local` writes it and shows the diff.
- `newer than this fugaro` (`failed`): a newer `fugaro` pinned the repository. The user upgrades the binary (`brew upgrade dimipaun/tap/fugaro`); the pin is never moved down.
- `the marketplace is the fork` (`stale` or `failed`): the settings name another marketplace repository than `dimipaun/fugaro`. Only the user decides whether it is theirs.
- a JSON error (`failed`): the settings file is not valid JSON and is never rewritten; the printed settings are for the user to merge by hand.

## plugin

- `installed X.Y.Z` (`current` or `done`): the version Claude Code has for this checkout. After `done`, running sessions need a restart.
- `installed X.Y.Z` (`stale`), the reason also naming this fugaro's own version: Claude Code has an older plugin than the binary.
- `not installed on this machine` (`skipped`, with `--check`): `fugaro upgrade --local` installs it.
- `newer than this fugaro`: Claude Code's marketplace follows the plugin repository's default branch, which can be ahead of the binary; the user upgrades the binary.
- `claude is not on PATH` (`skipped`): the user types the printed slash commands in Claude Code.
- `never replaces it` (`failed`): Claude Code on this machine has a `fugaro` marketplace from another source; the user decides whether to remove it.
- `cannot tell` (`skipped`): Claude Code's record could not be read; `fugaro upgrade --local` finds out.

## cloud

- `base images to move` (`stale`): the local project config records an older base image, or none, for a kind the workflows use. The user runs the cloud command (SKILL.md step 4).
- a custom base image (`stale` with `--check`, `failed` without): a development or hand-pushed base image stops the refresh; the fix it printed comes first.
- `records this release's base image` (`current`): nothing to move. `--check` reads no build record, so a build that failed after the base moved does not show here.
- `--local` (`skipped`): the reason names the command for the cloud step.
- `a coding agent's session` (`skipped`): always, in this session; hand the user the cloud command (SKILL.md step 4).
- `no local project config selects this checkout` (`skipped`): this machine is a teammate's; there is nothing to do here.
- `not onboarded` or `no fugaro.yaml` (`skipped`): the repository has no job image yet; setting it up is a separate task (the `setup` skill).
- `on this release's base image` (`done`) or `no base image to copy and no image to rebuild` (`current`): only when the user ran it in their own terminal.
- `stopped at step N` (`failed`): the refresh stopped; its reason names the steps that finished and the rerun line.
