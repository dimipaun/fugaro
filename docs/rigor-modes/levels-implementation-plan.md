## Conventions every task follows

The approved plan's §4 list, unchanged (this repository has no `CLAUDE.md` and no `.claude/rules/`): documents and pins move together; goldens are regenerated, never hand-edited (`website/content/cli-reference.md` by `go run ./internal/clidoc`, held by `TestCliReferenceIsCurrent`); nothing is decided by a task; no secret-shaped literals; hermetic tests, no live cloud action; no task edits `.github/workflows/`; refusals are immutable; every Go command runs with `GOFLAGS=-p=2` and a `-timeout`; test-first and mutation-proven (a red step that passes before the change is not a red step). One pull request per task; targeted tests only. Reviewer classes are the approved plan's: **senior (in-loop)**, or **operator** for security-sensitive work, which a person or a local session does and a Fugaro run never picks up (§5's last constraint). **The repository's own safety rules (no real secret in code, nothing destructive to shared resources, no live cloud action by an agent) are outside every level** and a persona's wording cannot lower them (reconciliation §4 item 2). Wherever a 2026-10-20 document says Critical mode is "byte-identical to today", LV1.2 restates it as reconciliation §3b item 1 says (the owner's answer of 2026-10-22).

## Global constraints and review focus

- **Readiness is one deterministic rule inside `runner.Decide`** (D7). `Decide` takes the resolved level (T3.5) and never the persona text; a source guard pins that `outcome.go` references no persona symbol. *Pinned by LV2.2.*
- **A floor is never lowered by a task, a follow-up, a label or a job variable** (D8, LD3). *Pinned by T1.5 and LV3.2.*
- **Hotfix is reached only by an operator** (D12): `fugaro run --rigor hotfix` with the base branch's `rigor.hotfix` opt-in. It is refused as a project, repo, per-repo or area default, on a follow-up (`--pr N`), and from a comment. *Pinned by LV3.1 (the defaults) and the amended T5.1/T5.2.*
- **Hotfix still never deploys and never merges** (D13). *Pinned by LV4.3 and the existing D13 tests.*
- **A persona text is data, not code:** embedded Markdown with stable wording tests; no template that interpolates repository content. *Pinned by LV2.1.*
- **The hand-back sections come from the agent's own hand-back file, never from the task text.** A first run's file is `pr.md`; a follow-up never writes `pr.md` (its system prompt replaces that line with `followup.SystemPromptLines`, `internal/runner/prompts.go`) and writes `followup.md` (`followupFile`, `internal/runner/followup.go`) instead, so a follow-up's hand-back is the same sections in `followup.md`. When the file is missing, the runner's fallback body embeds the task (`## Task`, `rawPRText`); no presence check reads that body, so a task carrying a "Revert plan" heading satisfies nothing. *Pinned by LV4.2 and LV5.1.*
- **One repository may sit in two areas** (LD4's members-with-paths); a path two areas of one layer match resolves by D23 (strictest). *Pinned by LV3.1.*
