# Model A/B testing: the implementation plan

## Status

**Plan only; nothing is implemented; no task is approved.** It builds [spec.md](spec.md) as amended by
[reconciliation.md](reconciliation.md). **No decision D550–D573 is answered yet**, so the plan is
written on the recommendations; an answer that differs re-slices the plan before any task starts.
Answering a decision is not approving a task: each task below needs the owner's own explicit go.

Written 2026-10-29 against `origin/main` at `c192e8766`. Decisions are cited as `D#`, findings as `F#`,
resolutions as `R#`.

The shape the recommendations give: a sampled first run of a code task launches a **champion** (the
run as today, which alone reaches the developer) and a **challenger** (the same task at the same commit
with another coder model, run as a **shadow** that pushes nothing and opens nothing). Both records
carry a pair. Reports score pairs from records (hard signals, per mode), and a later slice adds a
blind judge run. No code ever changes a default.

## Conventions every part follows

- `CLAUDE.md`: targeted tests only (`internal/runner` and `internal/cli` take ~25 minutes in full;
  `-timeout 40m` for runner), `gofmt -l .` prints nothing, `go vet ./...`, comments explain why.
- `.claude/rules/ee.md` and `ee/README.md`: nothing outside `ee/` imports `ee/`; every new file
  under `ee/` starts with the two-line SPDX notice; the core builds and tests with `ee/` deleted
  (`internal/eeboundary`). **No licence notice anywhere** (ee-reorg D523, as answered); an untagged
  build that sees `ab:` keys writes the D522 capability statement only.
- Config and wire formats decode strictly and have schemas in `schemas/`; a new key is refused by
  older binaries, which is the fail-closed behaviour this plan relies on (an older runner refuses a
  task with `ab`, so it can never run a challenger as a publishing run).
- Hermetic tests: `internal/gcpfake`, `internal/testutil`, `t.TempDir()`; no secret-shaped literal;
  no real person, organisation or project name; no prices in docs or fixtures (fixtures use invented
  model IDs and the test price table).
- **No agent performs any live step.** Checks 210–212 are written by agents and **run by the owner**
  on a sandbox installation, never on a production installation.
- A CLI change that touches a documented command changes `plugin/skills` in the same PR; the CLI
  reference is regenerated by the tagged generator (ee-reorg D536), never edited by hand.
- Steps operators must take go into the release notes' `### For operators` in the same PR
  (`docs/releases/README.md`).
