# Diagnose spec: reconciliation

**Status: reconciliation of [spec.md](spec.md) against `origin/main` (commit f71be3b32's parent, read 2026-11-07). Where the two disagree this file wins.** The spec is the owner's (Dimi Paun). Nothing here is implemented and no task is approved. **Independent review rounds have NOT run** (the author is a fork that cannot spawn reviewers); every cited path and symbol was grepped on `origin/main`, nothing else was checked.

**Numbers.** This work reserves **D1600–D1619** and **Checks 410–419** (verified free on `origin/main`: no `D16xx` and no `Check 41x` appears under `docs/`). Siblings: no-prompt (#1906, D1540–D1559), composite commands (#1907, D1560–D1579), roles (#1908, D1580–D1599).

**The command's name.** The spec writes `fugaro diagnose`. D1600 (owner) keeps that name for what it does today, so this document writes the agent command as **`fugaro troubleshoot`** (D1604 picked the word).

## 1. Findings

**F1. Wrong (name). `fugaro diagnose RUN` already exists and means something else.** `internal/cli/diagnose.go` `newDiagnoseCmd` (`Use: "diagnose RUN"`) explains a **cloud** run (`<repo-slug>/<run-id>`): status, last test run, review findings, the agent's last message, the newest log lines, cost, pull request. It has a `--json` mode that the console (`console/src/main/ipc.ts`, operation `run.diagnose`; `console/src/main/launch.ts`) and the skills read. *Consequence:* the owner ruled (D1600) that `diagnose` stays as it is and the agent command takes a new name; the console, the exact-argv fence and the skills need no change for it.

**F2. Gap (the dependency is a plan, not code). There is no local command-run ID and no command log today.** `docs/cli-output-console-graph/` (the spec's "in progress") is **plan only**: its F6 says "The CLI keeps no log of its own runs", and `internal/logtail` / `fugaro logs` read a cloud run. A grep of `internal/cli` finds no log writer and no `Something went wrong` line. *Consequence:* the spec's "Depends on" block is not built; this plan takes the output plan's log task as an **external dependency** (and its run-ID shape is decided here, D1609) rather than building a second log store.

**F3. Rule (log location and retention, which an owner answer here collides with).** The output plan's owner answers (2026-11-06) are **D1351** logs under `<UserDir state>/fugaro/logs` (`localcfg.UserDir`, `internal/localcfg/platformdirs.go`), **D1352** only mutating and step commands log, **14 days or 50 files per command name**, mode 0600 in a 0700 directory, redacted, a write failure never fails the command. The owner's D1603 answer today (2026-11-07) was "under the existing Fugaro config dir; last 20 logs or 30 days". Config is `~/.config/fugaro` by `UserDir`'s rule, and logs are not config. **D1603 is `amended after review`**: the command logs follow D1351/D1352 (one store, one retention rule, already ruled), and D1603's answer applies to what this plan adds — the **source tree** (a cache: `<UserDir cache>/fugaro/source`, rebuildable) and the **diagnosis outputs** it writes (state dir, same 0700 rule). *Open for the owner: confirm the amendment (item O1).*

**F4. Gap (redaction is exact-value only).** `internal/agent/redact.go` `Redact` / `RedactFunc` replace **listed secret values** (and their encodings in `encodedForms`) by `[REDACTED]`; its own comment says output is "best-effort redacted, not guaranteed clean". `diagnose.go` calls `agent.RedactFunc(secrets)` with the environment's credentials. The spec says "secrets are removed when the log is written, so logs are safe to attach to an issue": a Terraform or gcloud stream holds tokens the CLI never held (a bearer token printed by a failing call, a signed URL, a key in an error body), and `internal/infra/tf/tf.go` `TF.Out` is raw today (the output plan's F6). *Consequence:* a **pattern layer** (token shapes, `Authorization:` headers, signed-URL query strings, private-key blocks, emails and absolute home paths for the issue report) is **new work and a gate**: nothing may be attached to an issue, or sent to a model, until it passes both the exact-value and the pattern pass; the claim "no secrets appear" is a goal with a test corpus (T-DG2), not a guarantee, and the issue report says "redacted, review before posting" (D1605).

**F5. Gap (prompt injection, the new trust boundary).** A command log holds text the user does not control: Terraform and gcloud error bodies, repository file names, PR and API responses. An agent that reads it **and** has a shell, the network and the user's credentials can be steered by that text. The owner's D1602 answer closes it by construction: the agent gets **Read/Grep/Glob only**, on the source tree and the evidence files; Fugaro itself fetches tags and writes the "changes since your version" file; a fix command is printed and never run; nothing the agent says is executed. *Consequence:* the tool allow-list is a security-sensitive task with a mutation check (T-DG7), and the output is treated as untrusted text (printed, not interpreted).

**F6. Gap (data egress).** Diagnose sends a redacted log, the doctor output, the effective configuration and any source it reads to a **model provider**. Jobs already have the rule (`allow_data_to` on an account, `internal/localcfg/localcfg.go`; the Vertex default; the Terms/OAuth wording in `docs/project-claude-accounts.md`), and a local user's own credentials have the provider's own terms. *Consequence:* the command prints, before it sends, one line naming the provider and what class of data goes (not a prompt: the typed command is the consent, D1606's compatibility with the no-prompt spec), and the project's account is used **only** when its `allow_data_to` covers this repository (D1601).

**F7. Rule (credentials).** The spec's order is the jobs' order and reads the project's token from Secret Manager over the user's gcloud login. The owner's D1601: **the user's own local credentials first** (this checkout's Claude login or environment key, the names in `claudeLoginCredentialEnv`, `internal/cli/accounts_add_login.go`), then the project's account from Secret Manager **held in memory only and never written to disk**, only when `allow_data_to` covers the repository, then a clear error naming the one fix. Two consequences: the spec's own failure case (the cloud is what is broken) works because the first choice needs no cloud; and `docs/project-claude-accounts.md`'s "Neither is the agent's: `fugaro secrets set` reads a value only from stdin" stays true, because diagnose reads a secret to hand it to **one child process's environment**, which the T-DG5 test pins.

**F8. Gap (source tree, integrity).** Tags are `vX.Y.Z` (`docs/release.md`); the public repository is `github.com/dimipaun/fugaro`; the GitHub tag-archive URL form (`https://github.com/dimipaun/fugaro/archive/refs/tags/vX.Y.Z.tar.gz`) was **not fetched here** (UNVERIFIED, U1). `docs/release.md`'s verification covers `checksums.txt` and its sigstore bundle, which cover the **release archives**, not a source tarball, so the tarball fallback has no signature to check. *Consequence:* decision D1610 states the trust root (TLS to GitHub, plus the tag's commit recorded) and why it is enough: the source is only ever **read** by a tool-restricted agent, so a wrong tree can mislead a diagnosis but cannot execute anything.

**F9. Gap (versions that have no tag).** `internal/cli` holds `Version` (overridden in tests, `version_flag_test.go`); a `dev` build or a build off a branch has no matching `vX.Y.Z`. "The source used always matches the installed Fugaro version" is unsatisfiable for them. *Consequence:* D1611 (open).

**F10. Gap (no agent troubleshooting guide, no skill).** `docs/` has no troubleshooting page and `plugin/skills` holds `parallelism`, `routing`, `setup`, `upgrade`, `working`; the skill lint caps a file at `maxSkillBytes` (24 KiB, `plugin/skills_lint_test.go`) and checks every named command and flag against the CLI. The spec's "troubleshooting guide kept in the repo and written for agents" is **new** (`docs/troubleshooting-for-agents.md`, embedded in the binary so the guide always matches the version; D1612) and a plugin sentence naming the command arrives only once the command exists (the lint fails a command the tree lacks).

**F11. Exists (the failure line is partial).** The converge commands print their failures today as the error plus context; there is no run-ID line. The output plan's reporter task prints a failure block with the log path (D1352 / T6: **only commands that write a log** print the path, so a failed read command prints no diagnose line). The spec's acceptance ("a failed `fugaro update` prints its run ID and the diagnose command") is met for logged commands and only those.

**F12. Exists (a settings pattern for a per-stage model).** `internal/settings/registry.go` already holds `agent.model` and `agent.models.<stage>` with `Owner: "models"`. The spec's "model changed with the normal settings command" is a **new registry key** following that pattern (D1607), default Sonnet (`claude-sonnet-5-5`).

**F13. Rule (no-prompt compatibility).** The command asks nothing: typing it is the consent (spec; `docs/no-prompt-policy/` D1540, D1544). It reads no value at a terminal; with no credentials it fails at once naming the fix. Cost: the project's account fallback and any `allow_data_to` refusal are refusals, not prompts.

**F14. Gap (cost bound).** A local agent run is not a job, so the job budget (`internal/budget`) does not bound it, and the user's own credentials may be a metered API key. *Consequence:* D1613 (a per-invocation cap).

**F15. Gap (what runs the agent locally).** `internal/cli/exec.go` has a `--claude` binary option for the in-job runner; how a **local** agent child is started with a tool allow-list and a one-process environment is not established in the CLI today (UNVERIFIED, U2). The plan's T-DG7 owns it and its test.

**F16. Gap (the agent's read confinement and flags: U2 resolved as a requirement).** The in-job runner `internal/agent/agent.go` builds its argv with `--dangerously-skip-permissions` always, so it must **not** be reused. The review job's pattern is the model (`internal/agent/agent_test.go`: `--setting-sources`, `--strict-mcp-config`). Claude Code's Read/Grep/Glob are not confined to the working directory by themselves (to be verified against the pinned `claude` version in T-DG7). *Consequence:* T-DG7 restricts tools with `--tools Read,Grep,Glob` (not `--allowedTools`, which only pre-approves), runs with no setting sources and `--strict-mcp-config`, and stops reads outside the two folders by an OS sandbox or deny rules, with a test that a read outside them is refused; it weighs running the local `internal/gateway` so the child holds no credential and D1613's cap is enforced by the gateway.

**F17. Wrong (the model key is not a registry row).** `internal/settings/registry.go` holds fixed rows mirroring `config.ModelRoles` (`coder`, `reviewer`, `background`) and `TestRegistryCoversEveryConfigField` pins that every config field has a row. A diagnose key is therefore a **new field** in `internal/config/config.go` (and the policy format), a schema change in `schemas/`, and a registry row; and the spec is silent on which value applies outside a checkout (D1607).

**F18. Wrong (run-ID shape).** The output plan names a log `<command>-<UTC timestamp>-<pid>.log` and its retention deletes files matching that exact pattern; a different local ID shape would never be cleaned and would clash. D1609 aligns to the stem.

**F19. Exists (the binary knows its commit).** `internal/cli/releaseinfo.go` holds `Commit`, set by `.goreleaser.yaml` to `{{ .FullCommit }}`; this is a stronger anchor than a tag (D1610).

**F20. Gap (model output is untrusted).** The diagnosis and the issue report are model output: both redaction passes (exact list now including the credential handed to the child) run on them again, terminal control characters are stripped (`internal/safetext`), and a printed fix command is shown as runnable only under D1614.

**F21. Gap (unpacking is not read-only).** The tarball path unpacks into a directory: entries that escape it (`..`), symlinks, device files and oversize archives are refused, the cache-folder checks of the output plan's log rules apply, and `git` runs with hooks and `fsmonitor` off. D1610's "only ever read" covered the agent, not the unpack.

**F22. Gap (the `allow_data_to` gate has no repository).** The gate (D1601) is per repository; a failed `fugaro update` has none. Outside a checkout the project-account fallback **fails closed**, the error names which account (default or per-stage) it would have used, and a test pins it.

**F23. Follow-ups, not decided here.** (a) A project subscription OAuth token on a teammate's laptop against the account's terms (the owner's D894 line); (b) `fugaro doctor` inside the evidence collector makes cloud calls and may hang exactly when the cloud is broken: the collector runs it with a short timeout and notes a timeout as evidence.
