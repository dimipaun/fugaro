# A built-in catalog of provider-model prices

*Status: 2026-10-14, draft for the owner's review. Nothing here is built. Related: [m10-multi-model.md](m10-multi-model.md) (§5 pricing and budget accounting, §13 assumptions), [mixed-credentials.md](mixed-credentials.md) (the Claude-through-OpenRouter opt-in), [shared-config.md](shared-config.md), [layered-config.md](layered-config.md), [../multi-model.md](../multi-model.md) (the user doc). The plan is [../plans/2026-10-14-provider-price-catalog.md](../plans/2026-10-14-provider-price-catalog.md).*

**What is verified, and what is not.** Every claim below about *Fugaro's existing behavior* was read from this branch's code, with the file and line named. Every claim about *OpenRouter* was read from its public documentation or its public APIs on **2026-10-14** (no credentials were used; the API responses quoted here were fetched from `openrouter.ai` directly), and the URLs are named. Claims that could not be checked either way are marked **UNVERIFIED** and are items in §10, with Check 44 of [../gcp-live-checklist.md](../gcp-live-checklist.md) as the live check that settles them. A number quoted from the owner's ruling is marked as the owner's; a number quoted from an API response is marked as measured on 2026-10-14 and will drift as OpenRouter's lists change.

## 0. Summary and recommendation

1. **Fugaro ships a price catalog for the models OpenRouter serves.** A generated, embedded data file (`internal/pricing/catalog/catalog.json`) records, per model, the price range over the endpoints OpenRouter may route to. A project needs no hand-typed `model_prices` for those models. `fugaro budget prices` still shows every price the budget will use, where it came from and when it was checked; an owner's `model_prices` entry still wins (§3 D4).
2. **The catalog records a range, not a price, because OpenRouter's public price is the cheapest endpoint's.** `/api/v1/models` lists `deepseek/deepseek-v4.1-flash` at $0.02016 input / $0.891 output per million tokens, which is the cheapest of the 33 endpoints `/api/v1/models/deepseek/deepseek-v4.1-flash/endpoints` returns; the dearest ZDR-eligible one is $0.60 / $2.40 (measured 2026-10-14, §1). Per model the catalog stores **four** price points: the minimum and the maximum over the zero-data-retention (ZDR) eligible endpoints, and the minimum and the maximum over **all** endpoints, each with input, output and cache read (owner ruling 1, 2026-10-14).
3. **Two switches on the provider route select which point the gateway charges**, both in the owner's local config (`providers.<name>`): `require_zdr` (default **true**) selects the ZDR set, and `price_policy: cheapest | highest` (default **cheapest**, matching OpenRouter's own default routing, which prefers the lowest price) selects the end of the range.
4. **`cheapest` can undercharge, and this design says so plainly rather than hiding it.** OpenRouter may serve an endpoint dearer than the one priced. For the model above the measured spread is 29.8x on input and 13.3x on output over the ZDR set, and 3.2x / 4.3x over the four providers the owner's account allows (measured 2026-10-14, §1). What bounds it: the per-run and daily dollar caps (which are the reason a cheap charge is not free money), the provider-reported cost (`usage.cost`), which is **recorded and never settles** and which `diagnose` already compares against the charge — a persistent gap is the signature of exactly this undercharge — and `price_policy: highest`, which charges the top of the range and is the safe setting. §6 states all four.
5. **A stale catalog can never silently under-price.** The file carries a `checked_at` date; past the existing 90-day staleness threshold the run charges the **highest** bound of the selected tier instead of the policy's bound, logs a WARN and records `catalog_stale` in `result.json` (§7).
6. **`require_zdr` prices a tier; it does not enforce routing.** Fugaro cannot add OpenRouter's per-request `provider` object (the gateway never rewrites a body, and `provider` is a refused key on a routed call — `docs/multi-model.md` §7), so ZDR routing is enforced account-side only, and Fugaro cannot read the account's privacy setting: `GET /api/v1/key`'s documented response has no data-policy field (§8), so `fugaro doctor` says exactly that and names what to check. This is the honest limit of the switch; it is not a gap this design can close.
7. **Provider pinning is out of the first slice.** Sending OpenRouter's `provider` routing object (so the price is exactly one provider's) needs a body rewrite, which M10 forbids; it is named in §9 as a later option only.
8. **Nothing in the money path changes shape.** The catalog is compiled into the existing `pricing.Table` at runner start, per route, so the gateway's lookup, reservation, settlement, fee and `reported` bookkeeping are untouched; the only new failure is the one that already exists (a model with no price on a provider route is refused, `internal/gateway/forward.go:543`).

## 1. The problem, with numbers

`/api/v1/models` (public, no key) returns one price per model:

```json
{"id": "deepseek/deepseek-v4.1-flash", "canonical_slug": "deepseek/deepseek-v4.1-flash-20260910",
 "pricing": {"prompt": "0.00000002016", "completion": "0.000000891", "input_cache_read": "0.0000000054"}}
```

Those are dollars **per token**, as strings; per million tokens that is $0.02016 / $0.891 / $0.0054. `/api/v1/models/deepseek/deepseek-v4.1-flash/endpoints` returns 33 endpoint rows (32 distinct `tag`s; BaseTen's `baseten/fp8` appears twice with identical prices) and the cheapest of them, `open-inference/fp4`, is exactly what the models list quoted. So the list price is the **cheapest endpoint across all providers**, which is what the models list is for and is not what a given account will pay.

`/api/v1/endpoints/zdr` returns every endpoint with a zero-data-retention policy (946 endpoint rows over 356 models when read on 2026-10-14); each row carries `model_id`, `provider_name`, `tag` and its own `pricing`. Matching the two by `(model_id, tag)` gives this model's price range (USD per million tokens, measured 2026-10-14):

| tier | endpoints | input | output | cache read |
|---|---|---|---|---|
| ZDR-eligible | 25 | 0.02016 – 0.60 (29.8x) | 0.18 – 2.40 (13.3x) | 0.0039 – 0.034 |
| all | 32 | 0.02016 – 0.60 (29.8x) | 0.18 – 2.40 (13.3x) | 0.00294 – 0.034 |
| the owner's account's four providers (DeepInfra, Fireworks, Parasail, Together) | 5 | 0.14 – 0.45 (3.2x) | 0.42 – 1.80 (4.3x) | 0.0042 – 0.009 |

(The owner's ruling quotes "up to about 2.4x" for this model; that is the owner's figure for a smaller provider set. The measured rows above are what the public APIs say on 2026-10-14, and they are the numbers the file will carry. The account's own provider preference — the four named providers, or an account-side allow-list — is **not readable** from the API key, §8, so the catalog cannot record it.)

So today an owner who wants a correct cap for this model must hand-type one `model_prices` entry that is **too high for every call** or **right for one endpoint nobody pinned** — the "the real prices, and that OpenRouter reports usage the way the gateway reads it, are assumed until Check 25" caveat in `docs/multi-model.md` §2, and the served-model warning at the end of that doc (`deepseek/deepseek-v4.1-flash` is served while the embedded placeholder row is `deepseek/deepseek-v4-flash`, `internal/pricing/table.go:79-87`, a different model at `priced_as: max`, about 100x too high). The catalog replaces that hand-typing with a generated, reviewable, per-tier range, and the two switches choose what to charge from it.

## 2. What exists today (verified in the code)

- **The price table.** `pricing.Embedded()` (`internal/pricing/table.go:47-70`) builds a `*Table` from hand-written Go rows: `Source` = the Anthropic pricing page and `CheckedAt` = `"2026-09-30"` (`table.go:4-7`), plus one provider placeholder row (`providerRows()`, `table.go:79-87`) marked `Unverified` with its own `PriceSource`/`PriceCheckedAt`. There is **no** `go:embed` price data file anywhere in the repo; the six existing embeds are listed in the plan.
- **Owner prices.** `model_prices` → `pricing.Overrides` (`internal/pricing/overrides.go`), carried to a job as `FUGARO_MODEL_PRICES` (≤ 32 KiB, `overrides.go:51`); `Table.With` (`pricing.go:212-250`) replaces a model's rates whole and clears `Unverified`. `Rates.CacheRead` is a **multiplier of `InputPerM`**, not a price (`pricing.go:36-41`); `fugaro budget prices` already multiplies it back out for display (`internal/cli/budget.go:1231`).
- **The embedded table's staleness.** `priceStaleAfter = 90 * 24 * time.Hour` (`internal/cli/budget.go:41`); `budget prices` prints the source, the check date, the age and a warning past it (`budget.go:1238-1241`). `fugaro validate` and `diagnose` show pin warnings (`config.PinWarnings`, `internal/config/pins.go:37`).
- **Provider routes are local-config only.** `config.ModelProvider` (`internal/config/providers.go:28-47`: `kind`, `base_url`, `auth`, `secret`, `route_fee_pct`, `models`, `allow_data_to`) lives on the local config's `providers` map (`internal/localcfg/localcfg.go:78-80`). A repository's `fugaro.yaml` cannot set it (`TestRepoCannotAddProvider`, `internal/config/model_providers_test.go:183`), the project layer has no `providers` field (`internal/config/layer.go:49-94`), and the shared installation config refuses the section outright (`sharedForbidden`, `internal/cli/sharedcfg.go:155`; `localcfg.Config.Shared()` strips it, `internal/localcfg/shared.go:30-43`). A provider's fields reach a **job** only through `FUGARO_MODEL_PROVIDERS`, compact JSON written by `fugaro init --repo` (`runner.ProvidersEnv`, `internal/runner/providers.go:32-52`) and decoded strictly (`DisallowUnknownFields`, `providers.go:64-66`; ≤ 16 KiB). `docs/multi-model.md` §2 already states the consequence: a provider-list change takes effect only after `fugaro init --repo` is re-run.
- **The gateway's money path.** A request's model resolves to a route by pattern (`internal/gateway/route.go:144-151`); the fee is added to the reservation (`forward.go:557`) and the settlement (`forward.go:770`). An unpriced **pinned** model is priced at the table maximum and flagged `priced_as: max` (`forward.go:531-535`), but if it is routed to a provider the call is **refused**: `model %s is routed to %s but has no price: set model_prices` (`forward.go:543-554`); `config.CheckPins` refuses the same pin at bootstrap with `%s has no price: add it under model_prices in the project config` (`internal/config/pins.go:29-32`). A serving model dearer than the pin charges the dearer of the two rates, also `priced_as: max` (`forward.go:748-751`).
- **Reported vs charged.** The provider's `usage.cost` is parsed into `usageAcc.reported` (`internal/gateway/sse.go:176-182`), recorded on the charge (`ledger.go:84-94`) and in `result.json` as `cost.reported_usd`, and **never** prices the call (`forward.go:778`, comment: "a record for comparison: it never prices the call"). `diagnose` sums the charge per route, strips the fee with `pricing.WithoutFee` and warns when reported exceeds the fee-stripped charge by more than 10% (`internal/cli/diagnose.go:245-293`); the runner logs the same gap once (`reported_gap`, `internal/runner/gateway.go:370-383`).
- **The runner builds the one table.** `spendFromEnv` reads `FUGARO_MODEL_PRICES` and does `pricing.Embedded().With(o)` (`internal/runner/spend.go:116-125`); with the budget on and no overrides it falls back to the plain embedded table (`internal/runner/policy.go:108-113`); the gateway is started with `Prices: s.Prices` (`internal/runner/gateway.go:57`) and the same table answers `CheckPins` (`gateway.go:346`).
- **`fugaro doctor` checks** are `doctorCheck{ID, OK, Problem, Fix, Severity}` (`internal/cli/doctor.go:39-45`) where `""` fails doctor, `"warning"` fails only with `--strict` and `"info"` never fails; the provider-adjacent checks today are `fugaro-yaml`, `claude-accounts-stored` and `oauth-token-allowed`.

## 3. Decisions

**D1. The catalog records a per-model range over endpoint sets, not a single price.** Per model: `zdr` (min, max) and `all` (min, max), each with `input_per_m`, `output_per_m`, `cache_read_per_m` in USD per million tokens as decimal **strings**, plus the endpoint count and, for each extreme, the `tag` that holds it. The values are **per-dimension extremes** (the lowest input over the set, the lowest output over the set, the lowest cache read over the set), not one endpoint's three numbers: that is what "the price range over the endpoints" means, it is what the owner's ruling asks for, and it compiles exactly (see D7). *Veto alternative:* record the cheapest and dearest **endpoint** (three numbers from one row each). It reads better but bounds nothing: Decart's $0.18 output and OpenInference's $0.02016 input are on different endpoints, and a per-endpoint record would price output at $0.891 while the true worst case in the set is $2.40.

**D2. The catalog is a generated JSON file embedded in the binary.** `internal/pricing/catalog/catalog.json`, written by `internal/pricing/catalog/gencatalog` (a `main` package) through `scripts/gen-price-catalog.sh`, read at runtime by `internal/pricing/catalog/catalog.go` via `//go:embed`, decoded strictly, and validated by a test that runs on every build. Reasons: it carries hundreds of numbers and four price points each — a Go literal set would be unreadable in review, and the repo already has a generated-artifact idiom (`internal/budget/rules/rules.json.tmpl` + a golden test, `internal/recipe/catalog/*.yaml`). A price in the job's environment is not an option: `FUGARO_MODEL_PROVIDERS` is capped at 16 KiB and `FUGARO_MODEL_PRICES` at 32 KiB, and a per-project calibration of every model is exactly the hand-typing this design removes.

**D3. Two switches, on the provider route, in the owner's local config.** `require_zdr` (bool, default **true**) and `price_policy` (`cheapest` | `highest`, default **cheapest**). They sit on `config.ModelProvider` beside `route_fee_pct`, so they reach a job the same way every other provider field does (§2), and they are the owner's alone: a repository cannot set them. The default-true spelling follows the repo's existing idiom (`*bool` + an `On()` accessor: `PRSettings.EarlyDraft`/`EarlyDraftOn`, `internal/config/config.go:99-115`). The **scoping answer** the owner asked for: `providers.<name>` exists **only** in the local operator config today, so "the shared project layer" is not an option in this slice — the project layer has no provider fields and the shared bucket config refuses the section by name (`internal/cli/sharedcfg.go:155`). If the config-transitions work (Check 42) later lets the shared project layer carry a provider route, these two switches follow it with the same ceiling semantics as `allow_data_to`, and nothing in this design depends on which layer spells them.

**D4. Resolution order: owner override, then the catalog by tier, else the existing refusal.** `model_prices` for a model still replaces the whole row (owner ruling 4) and still clears provenance flags. With no override, a model claimed by a route the catalog covers is priced from the catalog's selected tier; a model with no entry in either is refused exactly as today (bootstrap `CheckPins`, gateway backstop). The catalog entry is keyed by the **exact** upstream ID (no aliases, no `:` variants), which is also what a pin must name (`pricing.IsAlias`, `alias.go:30-44`).

**D5. The catalog compiles into the `pricing.Table` at runner start; the gateway is not touched.** `catalog.Apply(table, routes)` returns a table with one row per (route, model the route claims), its rates taken from that route's switches, and `spendFromEnv`'s `.With(overrides)` runs **last**, so an override still wins. Why not teach the gateway to look the catalog up live: the money path would grow a second lookup branch, a second provenance state and a second way for `validate`/`budget prices`/`CheckPins`/the gateway to disagree; compiling once means one code path prices every call, and the existing gateway tests (reservation, settlement, fee, partial, `reported`) keep testing the code that charges. A model **no** route claims gets **no** catalog row — so a direct vendor route (`base_url: https://api.deepseek.com/anthropic`, `docs/multi-model.md` "Direct to the vendor") is priced by `model_prices` only, never from OpenRouter's marketplace prices, and the same model ID can be catalog-priced on one route and owner-priced on another. The catalog covers a route only when its `base_url` host is `openrouter.ai` (or a loopback host, so the hermetic fake is testable) — an inference, stated here, not a knob; *veto alternative:* an explicit third field (`price_catalog: auto | openrouter | off`), rejected for the first slice as a knob whose only other setting is a wrong answer.

**D6. `cheapest` undercharges, by design and within measured bounds.** OpenRouter's default routing "load balanc[es] based on price, while taking uptime into account" and may fall back to another provider (`allow_fallbacks` defaults to **true**; both read from the provider-routing guide, 2026-10-14). Charging the cheapest endpoint therefore charges **less than the call costs** whenever a dearer endpoint serves it. This is accepted, stated in the docs, and bounded by four things (§6): the caps (a cap counts a charge the run cannot exceed; an under-charge makes a cap stop a run later, not never), the provider-reported cost recorded beside the charge and surfaced by `diagnose` (a persistent gap is the symptom), `price_policy: highest` (the safe setting, the top of the selected tier), and the run's own measurement discipline (`reported` vs `charge` in `result.json` and in the log). `cheapest` is the default because it matches OpenRouter's own default and because the alternative over-charges every call by the range's spread for a bound that most calls never reach; the docs say which to pick and when.

**D7. Cache read is a price in the file and a multiplier in the engine.** The endpoints API reports `input_cache_read` per endpoint (absent on some, e.g. the Qwen rows measured on 2026-10-14 carry `null`). The catalog records the tier's minimum and maximum cache-read **price**, and compiles each bound into `Rates{CacheRead: bound.cache_read_per_m / bound.input_per_m}`, so the effective cache-read price charged is exactly the recorded bound (for `zdr`/`cheapest`, $0.0039 / $0.02016 = 0.193 of input). The combination is an envelope, not a real endpoint; D1 chose that on purpose. A tier with **no** endpoint reporting a cache read records `cache_read_per_m` as absent, and the compiled multiplier is left **above 1** rather than at 0: with no reported price the existing rule applies — a route that reports no cache fields charges all input at the full input rate (`docs/multi-model.md` §6) — and `pricing.defaultCacheRates` already raises a provider row's 0 multiplier to 1 so a cache token is never free (`pricing.go:256-271`). Cache **writes** are not in the ruling and are not read: catalog rows set the existing defaults `CacheWrite5m = 1.25` and `CacheWrite1h = 2` (`overrides.go:20-25`), a deliberate over-count, since Claude Code on a provider route is the case where a write may exist and the catalog cannot see it.

**D8. What the generator includes, and what it skips.** The generator takes an **explicit allowlist** of model IDs (in the script, so growing it is a reviewable diff), not all 462 models: for the first slice the DeepSeek family (`deepseek/deepseek-v4.1-flash`, `deepseek/deepseek-v4-flash`, `deepseek/deepseek-v4-pro`), one Qwen and one Moonshot row (`qwen/qwen3.8-flash`, `moonshotai/kimi-k3`) for the families the owner might use, and the Claude IDs (`anthropic/claude-sonnet-5.5`, `anthropic/claude-opus-5.5`, `anthropic/claude-fable-5.1`) **only** because of the explicit opt-in in [mixed-credentials.md](mixed-credentials.md) §4 — a row for `anthropic/<id>` prices the provider route, never the direct route (§5). It **skips**: `~vendor/model-latest` alias rows (19 of 462, identifiable by `canonical_slug`/`alias_target`); every `:` variant (`:batch` — 77 rows with their own prices — and `:free` — 14), which `pricing.IsAlias` already refuses as a pin; a model whose endpoints price anything the token table cannot express (`web_search`, `image`, `audio`, `internal_reasoning`, `input_audio_cache`, `input_cache_write_1h` when it is not expressible as a multiplier), because a per-image or per-request charge cannot be priced by `Rates`; and a model with no ZDR endpoint (it gets no `zdr` tier, and a `require_zdr` route refuses the pin rather than pricing an empty set). The endpoints' `discount` field is **UNVERIFIED** (no public documentation for it was found on 2026-10-14; DeepInfra's row showed `0.3`, its siblings `0`), so the generator records the price the API published and the live check records whether the settled charge matches it; if `discount` turns out to be an unapplied discount the generator must apply it, which is a one-line change plus a regenerated file.

**D9. A tier the model has no endpoints for refuses the pin, loudly.** `require_zdr: true` on a model the catalog knows with zero ZDR endpoints, or a model with no catalog row at all and no override, fails at bootstrap with a message naming the switch, the model and both ways out (`require_zdr: false`, or `model_prices`), and keeps the gateway's existing refuse as the backstop. No path prices an empty set, and no path silently falls back to "all".

**D10. Staleness charges the safe end.** `checked_at` in the file; past `priceStaleAfter` (90 days, the existing constant) the compiled bound is forced to the selected tier's **maximum** regardless of `price_policy`, with a WARN per run (`budget: price catalog stale`) and `cost.catalog_stale: true` in `result.json`. A stale catalog therefore can never under-price, and it never refuses a run for a reason that has nothing to do with the repository. `fugaro validate`, `fugaro budget prices` and `fugaro doctor` say the same thing before any run.

**D11. The two switches must survive version skew in the job's environment.** `FUGARO_MODEL_PROVIDERS` is decoded with `DisallowUnknownFields`, so a value written by a newer CLI and read by an older runner is a **hard bootstrap failure**, not a silent default. Two rules: `ProvidersEnv` **omits** both keys when they hold their defaults (a `*bool` nil for `require_zdr`, `""` for `price_policy`), so a job written by the new CLI and run by an older image is byte-identical to today and keeps today's behavior (owner prices, or the placeholder row — the placeholder is deleted in the same change, §5); and a **non-default** value is refused by `fugaro init --repo` when the workflow's base image predates the release that reads the field, naming the release — the same gate shape `cloneSince`/`imagePredates` already use in `internal/cli/recipes_skew.go`. The runner must also treat an absent key as the default, which falls out of the same rule and is pinned by a test. This is the one place this feature touches the wire between CLI and runner, and it is why it is written down here rather than discovered in a failed run.

**D12. `fugaro doctor` is honest about what it cannot check.** Two checks (§8): `provider-price-catalog` (warning when the catalog is stale, info otherwise, with the age, the source and the exact regeneration command) and `provider-zdr-unverified` (info, fired when any provider sets `require_zdr` true, saying that Fugaro prices the ZDR tier, that ZDR routing is enforced by the account's privacy setting only, and that Fugaro cannot read that setting — `GET /api/v1/key`'s documented response carries no data-policy field — so this is the owner's own check; Check 44 records the answer).

## 4. The catalog file

`internal/pricing/catalog/catalog.json` (generated; shown here with the measured 2026-10-14 numbers):

```json
{
  "version": 1,
  "checked_at": "2026-10-14",
  "sources": [
    "https://openrouter.ai/api/v1/models",
    "https://openrouter.ai/api/v1/models/{id}/endpoints",
    "https://openrouter.ai/api/v1/endpoints/zdr"
  ],
  "models": {
    "deepseek/deepseek-v4.1-flash": {
      "context_tokens": 1048576,
      "max_output_tokens": 943718,
      "endpoints": 32,
      "zdr_endpoints": 25,
      "input_per_m":       {"min": "0.02016", "max": "0.6",  "min_of": "open-inference/fp4", "max_of": "baseten/fast"},
      "output_per_m":      {"min": "0.18",    "max": "2.4",  "min_of": "decart/fp4",         "max_of": "baseten/fast"},
      "cache_read_per_m":  {"min": "0.0039",  "max": "0.034","min_of": "novita/fp8",         "max_of": "wafer"},
      "zdr_input_per_m":      {"min": "0.02016", "max": "0.6", "min_of": "open-inference/fp4", "max_of": "baseten/fast"},
      "zdr_output_per_m":     {"min": "0.18",    "max": "2.4", "min_of": "decart/fp4",         "max_of": "baseten/fast"},
      "zdr_cache_read_per_m": {"min": "0.0039",  "max": "0.034","min_of": "novita/fp8",        "max_of": "wafer"}
    }
  }
}
```

Rules that make it reviewable and safe to parse:

- **Keys sorted**, models sorted by ID, `json.MarshalIndent` with two spaces and a trailing newline. Generation from the same inputs and the same `-date` is byte-identical (pinned by a test).
- **Prices are decimal strings**, produced by shifting the API's per-token decimal string six places (exact decimal arithmetic, never `float64`), so a diff shows a price change and never a float-formatting wobble. The loader parses them with `strconv.ParseFloat`.
- `min`/`max` are the per-dimension extremes over the set; `min_of`/`max_of` name the endpoint `tag` holding each extreme (ties broken by the lexicographically smallest tag, so a tie cannot make the file flap between runs). A `:` variant or alias can never appear as a key.
- `context_tokens` and `max_output_tokens` are the **minimum** over all endpoints (`context_length`, `max_completion_tokens`), so nothing is reserved or allowed above what every eligible endpoint accepts; `0` means the model reports none, and `pricing`'s `DefaultContextTokens`/`DefaultMaxOutputTokens` apply (a larger reservation, never a smaller one). `image_tokens` is not recorded: images are refused on a catalog-priced model (the existing `providerRows()` default), stated in the docs, and a later refinement.
- The file is **not** authoritative by itself: the loader (`catalog.Load()`) validates it and returns an error, and the runner refuses the run with `the built-in price catalog is malformed: …` rather than pricing from a half-read catalog. The compile-time test makes that unreachable in a released binary.
- A `checked_at` that does not parse, or a `version` other than 1, is a load error (never a silent "fresh" or "stale").

## 5. The generator

`scripts/gen-price-catalog.sh` → `go run ./internal/pricing/catalog/gencatalog`. No credentials of any kind; three public GETs per model (`/api/v1/models` once, `/api/v1/endpoints/zdr` once, `/api/v1/models/<id>/endpoints` per allowlisted model — using the `links.details` value when the API gives one, since that names the canonical slug).

- **Inputs:** `-models <json> -zdr <json> -from <dir>` read saved snapshots instead of the network (the test path), `-allow <file>` the model allowlist (default: the list in the script), `-date YYYY-MM-DD` the `checked_at` to write (required when fetching: the generator never reads the wall clock, so a run is reproducible), `-o <path>` the output.
- **Determinism:** no map iteration in the output path; the ZDR match is `(model_id, tag)` (verified: every ZDR row's tag is present in that model's endpoints, and provider names alone are ambiguous — BaseTen serves three tags and one of them appears twice); duplicate `tag`s with identical prices collapse (a real case), duplicate `tag`s with *different* prices are a hard error naming the model and tag rather than a silent pick; a model on the allowlist that the API no longer serves is a hard error naming it, so a rename can never quietly shrink the file.
- **Review workflow:** the script prints a summary diff (models added/removed, per-dimension min/max deltas, the endpoint counts, the old and new `checked_at`) and writes the file; the PR shows both. `internal/pricing/catalog/testdata/openrouter/*.json` holds the snapshots the checked-in file was generated from, so a reviewer can re-run the generation offline (`scripts/gen-price-catalog.sh --from testdata/openrouter -date 2026-10-14`) and get the identical bytes.
- **When it runs:** by hand, at the owner's discretion, and as the release checklist's own line (design D2's sibling: `docs/release.md` gains "regenerate the provider price catalog and read the diff", the same shape as its `cloneSince` lines). Nothing regenerates it in CI: a price must never change because a workflow ran.

## 6. Money: what is charged, and how the undercharge is bounded

**The charge.** For a routed call whose model the catalog prices at the selected tier and bound, `Rates` are `{InputPerM: bound.input, OutputPerM: bound.output, CacheRead: bound.cache_read / bound.input, CacheWrite5m: 1.25, CacheWrite1h: 2}`, and everything downstream is unchanged: `Model.WorstCase` bounds the reservation, `check` enforces `max_output_tokens`, `Rates.Cost` prices the reported usage and rounds to µ$, `pricing.WithFee` adds `route_fee_pct` to the reservation **and** the charge, and the ledger records `used`, `ByModel`, `ByRoute`, `Reported`, `overruns`. The catalog's prices are the **model** prices; the route fee is the owner's, added on top, exactly as `docs/multi-model.md` §1 asks the owner to discover from their account. A fallback to a dearer **model** (not endpoint) is still caught by the existing `priced_as: max` (`MaxOf(pin, serving)`), which is a different and already-handled case.

**The four bounds on `cheapest`.**

1. **The caps.** `budget.per_run_usd`, the daily caps and `max_run_tokens` are all computed from the charge; an under-charge makes a cap bind later, never never. The reservation is an upper bound on any call the request allows, so a run cannot exceed a cap on the reserved path (the reason `route_fee_pct` multiplies the reservation too). The risk is therefore **accounting accuracy across a capped batch**, not an unbounded bill — and the account-side credit limit on the OpenRouter key remains the real backstop for a hostile run (`docs/multi-model.md` §7).
2. **The provider's own number.** `usage.cost` is parsed, recorded per stage (`StageReport.Reported`) and in `result.json` as `cost.reported_usd`, and shown by `fugaro diagnose <run>` beside the charge with the fee stripped (`WithoutFee`) — and it **never settles**. With `cheapest`, a persistent `Reported:` above `Cost:` is the undercharge showing up in the data the owner already reads; `fugaro diagnose` warns above a 10% gap and the runner logs `reported_gap` once per run. What that measurement needs is exactly what M10 left unverified: whether the Anthropic-compatible endpoint returns a `usage.cost` at all — Check 25's question, carried into Check 44 (§10, U3).
3. **`price_policy: highest`.** The safe setting: every call is charged the top of the selected tier. For the measured example that is $0.60 / $2.40 rather than $0.02016 / $0.891; the docs say to use it whenever the cap must be an upper bound (a costly batch, a first run against a new model) and `cheapest` when the charge is a close estimate and the caps are the guard.
4. **The reported-vs-charged discipline in the docs.** `docs/multi-model.md` §6 already tells the owner to read `Reported:` beside `Cost:`; this design adds the one sentence that makes it actionable: with `cheapest`, a lasting gap means the routing picked a dearer endpoint, and the answers are `price_policy: highest` or `model_prices` for the endpoint actually served.

**What the catalog does not do.** It does not raise a charge after the fact (the table settles, always), does not adopt `reported` (M10's decision, unchanged, and phase 3's question), and does not know the account's provider preferences (§8), so a `cheapest` row can be below even the ZDR set's minimum when the account allows only four providers — the owner's "about 2.4x" case is a *narrower* range than the catalog's, and the catalog is therefore conservative in the wrong direction for exactly those accounts. That is the strongest argument for `highest` on an account with a narrow provider allow-list, and it is stated in the user doc.

## 7. Staleness, and never under-pricing silently

| Surface | What it says / does |
|---|---|
| `fugaro budget prices` | New `CATALOG` column; a catalog-priced row prints its tier, bound, endpoint count and the catalog's `checked_at`; a stale catalog prints the existing 90-day warning naming the **catalog** source and date (distinct from the Anthropic table's) and the regeneration command |
| `fugaro validate` | A warning per catalog-priced pin naming the tier and bound, and (for a `cheapest` row) one note: the charge is the cheapest of N eligible endpoints; `price_policy: highest` charges the range's top |
| `fugaro diagnose <run>` | The pin-warning line gains the tier/bound; `Reported:` beside `Cost:` as today, with the fee stripped; a stale catalog is named when `cost.catalog_stale` is set |
| The run | `checked_at` older than `priceStaleAfter` ⇒ the compiled bound is the selected tier's **maximum**, a WARN `budget: price catalog stale` per run, and `cost.catalog_stale: true` in `result.json` |
| `fugaro doctor` | `provider-price-catalog`: OK with the age and the source; `warning` past 90 days, naming `scripts/gen-price-catalog.sh` as the fix |

The invariant: **no path prices a provider-model call lower because the catalog is old.** The stale case over-counts (the tier maximum) and says so in three places; the fresh case charges what the owner asked for (the policy's bound) and annotates it. A price the catalog has no row for is still the existing refusal, never a silent maximum (`forward.go:543`).

## 8. `require_zdr` is a price tier, not a routing policy

This is the design's most important honesty point, and it is the one a user will otherwise get wrong.

- **What Fugaro can do.** Price the call against the ZDR-eligible set (the owner's switch, default true), and warn when that is not the set the account actually allows.
- **What Fugaro cannot do.** Make OpenRouter route ZDR-only. ZDR enforcement is the per-request `provider.zdr` field or the account's privacy settings — `zdr` is documented as a boolean in the `provider` object, enforced per model group at account and guardrail level, "OR"-ed with the request setting, so the request field can only ever *add* enforcement (ZDR guide and provider-routing guide, both read 2026-10-14). Fugaro's gateway never rewrites a body and refuses `provider` as a routed key (`docs/multi-model.md` §7, `routedKeys` in `internal/gateway/forward.go`), so the account setting is the only enforcement it can rely on.
- **What Fugaro cannot read.** The account's ZDR / data-collection setting. `GET /api/v1/key`'s documented response is `label`, `limit`, `limit_reset`, `limit_remaining`, `include_byok_in_limit`, `budgets`, `effective_budget`, `usage*`, `byok_usage*`, `is_free_tier`, `free_model_daily_requests` and a deprecated `rate_limit` (limits reference, read 2026-10-14). There is **no** data-policy field, and guardrail-level ZDR is set on guardrails, which the key response does not enumerate. **UNVERIFIED:** whether an undocumented field or a second endpoint exposes it. Check 44 step 2 records the answer from the owner's own key; if one exists, doctor's check becomes a real check and this section is corrected.
- **Consequence, stated plainly to the user.** `require_zdr: true` (the default) means "price this route as if only ZDR-eligible endpoints can serve it". It is the right default because it is the conservative price and matches the account policy the owner intends; it is not a data-policy guarantee, and the docs must not imply one. The doctor check says exactly this, at `info`, whenever a provider sets it.

## 9. Out of the first slice

- **Provider pinning.** OpenRouter's `provider` object (`order`, `only`, `ignore`, `sort`, `max_price`, `zdr`) would make the price exactly one provider's (or bound it with `max_price`, which "will prevent your request from running if the price is not available"). It needs the gateway to rewrite or add a body field, which M10 forbids for a money-relevant reason (the body is the agent's; a rewritten body is a new correctness surface), so it is named here and nothing more. If it is ever wanted, the honest shape is a per-route constant body fragment rather than a general rewrite, and it must be priced by the same catalog.
- **Reading the account's provider preferences** (to narrow `zdr` to the four providers the owner actually allows). Nothing documented exposes them (§8). If Check 44 finds an endpoint, narrowing the catalog's ZDR set per account becomes possible and makes `cheapest` much tighter.
- **Applying `discount`** (D8): one line, once its semantics are known.
- **Image and per-request pricing** in `Rates`; the catalog skips such models rather than guessing.
- **A cache-write price** from `input_cache_write`; the first slice uses 1.25/2.
- **Adopting `reported` as the settled charge**; M10's phase 3 question, untouched.
- **Catalog rows for every OpenRouter model** (462 today); the allowlist grows by reviewable diff.

## 10. Open, and what the live check settles

- **U1. Whether the account's ZDR setting can be read from an inference key** (§8). Doctor's wording depends on it; Check 44 step 2.
- **U2. Whether `require_zdr: false` still routes ZDR-only when the account enforces ZDR** (the "OR" rule read from the docs, not observed). Check 44 step 5 records the serving provider with the switch off.
- **U3. Whether the Anthropic-compatible endpoint returns `usage.cost`** (M10 §13 item 1, restated). Without it, bound 2 of §6 is unavailable and `highest` is the only safe setting; Check 44 records whether `reported_micros` is nonzero in the `model call` log lines.
- **U4. What `discount` means** (D8). Check 44 compares the settled charge with the catalog's price for the usage it observes.
- **U5. Whether the prices the generator reads are the prices charged** (including whether a chosen endpoint's price is the one billed, and whether `input_cache_read` appears in a billed response). Check 44 steps 3-4.
- **U6. Whether a stale catalog's forced maximum is ever wrong in the other direction** — a price drop that makes the tier's recorded maximum exceed the true cost. It over-counts by construction; nothing to verify except that the warning fires.

## 11. Phases

**Phase 1 (this design's slice):** the catalog file, the generator, the compile-into-table step, the two provider switches, staging/doctor/`budget prices` surfaces, the user docs, and Check 44. Phase 1 never changes what a call is charged for a model the owner priced by hand.

**Phase 2:** grow the allowlist; apply `discount` if U4 says so; read `input_cache_write`; narrow the ZDR set per account if U1 finds a readable setting.

**Phase 3 (needs the owner's decision):** provider pinning via a per-route body fragment; `reported` as the settled charge; image pricing.
