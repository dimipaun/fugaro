## Conventions

`CLAUDE.md` and the rules it loads: `.claude/rules/credentials-service.md` does not apply (the identity is read through `access.Caller`, no credential is stored or written); `.claude/rules/terraform.md` does not apply (no Terraform change; the launcher grant is troubleshoot-issue T-IS17's). Hermetic tests only (`internal/testutil`, `gcpfake.NewGCS` for the shared store, `t.TempDir()`, an injected clock, environment, agent-marker seam, version and `Caller`); no network, no real home, no GitHub. **No secret-shaped literal** in a test, doc or fixture: sample addresses are `user@example.test`. No live cloud action by an agent; every check below is owner-run. Docs are tested: edit a doc, run `go test ./internal/cli/ -run Docs`, keep the pinned fact. Comments explain why. A documented command change updates `plugin/skills` in the same PR (T-IM7). The one JSON shape a reader outside the binary consumes (`mine --json`) is versioned and its field names are new. Run targeted tests, never whole `internal/cli`. **Release notes:** nothing runs after deploy; the operator line stays "run `fugaro update`" (F16).

### T-IM4: the identity (SECURITY-SENSITIVE)
- **Files:** `internal/issues/identity.go` (new), `internal/issues/identity_test.go` (new). **Interfaces:** consumed `access.Caller` through an injected seam, `localcfg.UserDir(getenv, goos, cache)`; produced `ResolveIdentity(ctx, deps) (Identity, error)` (not `Resolve`: update-plan T-RU4 owns `issues.Resolve` in the same package) with `Identity{Address, Digest, Source}` and `Source` one of `verified`, `cached`, `none`. A verified lookup (bounded by its own short timeout, a constant under the 20 seconds `access` allows) returns the address, lower-cased, and rewrites the cache (user cache dir, mode 0600 in a 0700 directory, a `format` field, strict decode, atomic); a failed lookup returns the cached address with `Source: cached`; neither returns `none`; with `deps.NoLookup` (a coding agent's session, F10) it never calls the seam and returns the cache or none. `Digest` is the first 16 hex characters of the SHA-256 of the lower-cased address (F7), the one function the store's key layout and `mine` share. **No upload, claim or dismissal reads the cache:** `VerifiedOnly(ctx, deps)` is the entry those paths use and refuses a cached answer. **Tests:** `TestIdentityVerifiedWritesCache`, `TestIdentityOfflineUsesCache`, `TestIdentityNoCacheNoneWhenOffline`, `TestIdentityRefusesServiceAccountAndWritesNoCache`, `TestIdentityNoLookupNeverCallsTheSeam`, `TestVerifiedOnlyIgnoresCache`, `TestIdentityCacheIsPrivateAndStrict`, `TestIdentityDigestIsStableSixteenHexAndCaseInsensitive`. **Command:** `go test ./internal/issues/ -run 'TestIdentity|TestVerifiedOnly' -count=1`. **Depends on:** nothing. **Commit:** `issues: the caller's identity, cached for display reads`. **Red step:** `TestVerifiedOnlyIgnoresCache` fails while one function returns a cached address everywhere; **mutation check:** make `VerifiedOnly` fall back to the cache and the test must fail. **Reviewer tier:** `opus + mandatory independent review`. Not OWNER-RUN.

### T-IM5: the offline snapshot
- **Files:** `internal/issues/snapshot.go` (new), `internal/issues/snapshot_test.go` (new). **Interfaces:** consumed `localcfg.UserDir(..., cache)`, T-IM1's `MineRow` (through its own plain struct so the file imports nothing from T-IM1); produced `WriteSnapshot(dir, installation, rows, now)` and `ReadSnapshot(dir, installation) (Snapshot, error)` for the last successful `mine`, **one file per installation** (named by a digest of the runs bucket URL, so offline `mine` in project B never prints project A's rows; user cache directory, mode 0600, `format: 1`, strictly decoded, atomic write; a decode failure or an unknown format is "no snapshot", never an error). ## Checks (reserved Checks 470–479; all OWNER-RUN)

- **Check 470, the shared lookup across machines and people.** On a project with the issue store: the owner (a non-operator launcher login) saves an issue on machine 1 (`fugaro issue sync`), then on machine 2 with the same Google login types `fugaro issue mine` and confirms the issue is listed with its number; a second person types `fugaro issue mine` after hitting the same failure and uploading, and both see "also hit by 1 other" and the same number. Measures F7 and U1 (whether a launcher can list `issues/reporters/` and `issues/occurrences/`).
- **Check 471, offline.** After one online `fugaro issue mine`, the owner turns the network off and types `fugaro issue mine` again: rows appear with "offline: shared state as of <time>", in a few seconds. Then with a cleared cache directory, it prints local rows only and says so. Measures F9 and U3 (how long the credential lookup takes with no network).
- **Check 472, the listing at size.** On the project with the most issues available, the owner types `time fugaro issue mine --json` and records the issue count and seconds, and whether `truncated` is true. Measures U2 and whether the 500-issue and 1000-name caps are right.

## Considered and declined

- **Refreshing GitHub from `mine`** (the spec's own lines). Declined by D1784: the owner goes by `resolved_in` alone.
- **One global names listing of `issues/occurrences/`.** Declined after review round 1 (F7): name order is issue-number order, so a cap drops the newest issues, and one launcher could fill it for everyone; a per-reporter index replaces it.
- **Printing other reporters' names.** Declined (F15): counts only; the update plan prints names to the admin for a reason `mine` does not share.
- **Suggesting the shared record's command.** Declined (F8): only this machine's own command, as update-plan O4 ruled.
- **A `mine`-written `resolved`.** Declined (D1784): only `fugaro update` writes it.
