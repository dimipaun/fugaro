# Field-by-field management audit of the three configuration layers

Read-only audit of /Users/dimi/git.lattica/Fugaro at `main` 3e1b02570 (binary used for help: built from the same tree). Rows come from the real settings registry (`internal/settings/registry.go`, 447 rows, dumped through a throwaway copy of the tree so no repo file was touched), cross-checked against the Go types of `config.Config`, `config.ProjectLayer`, `localcfg.Config` and `projectpolicy.Policy` (reflection walk) and against the schemas. The `settings` column is the output of the real `settingsWriteRow` over every row, plus hermetic probes of `settings set` in a temp copy; `command` is from reading each writer (cited). Nothing was written to config or cloud.

Legend. settings: `S` = `fugaro settings set/unset` writes it (`S (concrete name)` = wildcard row, you type the real name, e.g. `workflows.web.commands.test`). command (C): the named command writes it. manual-only: neither exists, so it is a text-file edit (or an RTDB node edit). Flags: C-not-S = a command writes it but `settings` refuses; MISATTRIBUTED = settings or the registry names a command that does not actually write the key; BROKEN = settings lists it writable but the write fails or lands in the wrong place; NO-WRITER / NOT-REACHING-NODE / NOT-REACHING-RUN as named; UNREGISTERED = real config field with no registry row.

### Doc vs code contradictions

- docs/project-layer.md:226 and :422-428 say `fugaro settings set KEY --layer project` writes a project-layer key and print the §5 scope table whose keys are `agent.review_rounds`, `git.pr.labels`, ... The registry gives those keys layer `project` (internal/settings/registry.go yamlRow/scopeLayers), but the working spelling is `layer.defaults.agent.review_rounds`; `--layer project` with the §5 spelling is refused at re-read (probe: `agent: is not a project layer key`). 17 generic-writable agent.*/git.* keys are affected.
- docs/settings-commands/audit.md (432 lines) is stale against the code: it says the project layer has no local source file and `fugaro update` publishes neither the policy nor the layer (now init_policy_publish.go and init_layer_stage.go do both), says only clone_urls and credentials.* lack a writer (clone_urls now has `project clone-url`; credentials.*, craft_credentials, craft_pools, crafts, model_grades and binaries still have none).
- settings_set.go:275-279 and spec §4.4 hand `credentials.*` to the generic path, and settings_set_test.go:904 asserts `credentials.fallback` is allowlisted, but the registry has no `credentials.*` row so the write answers "no setting has that name" (probe). `clone_urls.*` is the same (the registry row is the block `clone_urls`, refused as family `project clone-url`).
- internal/cli/accounts_pool.go:20-21 and :286-288 say pools are created "here or in the published node"; `project policy publish`/`update` never write craft_pools/craft_credentials/crafts from local (project_cmd.go:1288-1290 keeps `old.*`), yet credsvc/pool.go:109 and runner/poolchoice.go:150 read them only from the node. `accounts pool add|rm` therefore edits a local list nothing consumes at the credentials service; the `pools.*.owner/allowed_users/legacy_open` members have no writer at all although docs/project-layer.md (v5 paragraph) says publish refuses an ownerless pool.
- internal/cli/project_cmd.go:1281-1287 comment ("MC4 is where the operator's config becomes their writer") is still the state: MC4 (publish of crafts/credentials/pools from local config) has not landed.
- plugin/skills/working/SKILL.md:129 tells the agent `settings set KEY VALUE --layer L` writes `local`, `project` or `repo`, without mentioning the `layer.` spelling for project keys or that most agent keys' `--layer project` fails.
- Registry owner labels vs behaviour (user-visible in `fugaro settings` OWNER column and in refusals): `triage`, `verifier_accounts`, `bitbucket_*`, `batch.secrets`, `secret_*`, `providers.*` (except `.models`), `model_prices.*` (except input/output), `agent.model`, `agent.recipe`, `agent.levels.*.model|effort`, `agent.crafts.*`, `model_grades.*`, `pools.*.owner|allowed_users|legacy_open`, repo `rigor.*`, `issues.nudge_*`, `layer.jobs.*.paused`, `orchestrator.*`, `mobile_allow.*`.
