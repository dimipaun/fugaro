# `fugaro pair`, the consumer's enforcement and the sweeper's prompt rule — the review checklist (mobile P6.6, P6.7, P6.13; T1–T8)

**Status: shipped with T8's extension of the parity corpus's use. Every line below is either proved
by a named test on this branch or marked as a line no test in this repository can prove — and the
second kind is written down rather than left out, because a claim nobody can check is exactly the
one a reviewer has to check by hand.**

This is the checklist `docs/mobile/pairing-cli-plan.md`'s T8 names. It is not a summary of the plan:
it is the list of claims a reviewer of T1–T7 must confirm, each with the test that proves it, so a
review can be a reading of this file plus the tests it names rather than a re-derivation of the whole
design. Run the named tests with `GOFLAGS=-p=2 go test <package> -run '<filter>' -count=1` from the
repository root; every test here is hermetic — no network, no cloud, no clock, no real keychain —
over the fakes this repository already has (`internal/gcpfake`, the keychain's stand-in store) and
`t.TempDir()`.

## Two things a reviewer should know about T8 itself

- **The plan names `shared/mailbox/parity.test.js` as "the generator"; the writer is
  `shared/mailbox/parity.generate.mjs`, and `parity.test.js` is the reader that re-derives every
  answer by calling the live module.** The split is deliberate and the reason is
  `shared/mailbox/mutation-proof.sh`: it applies a mutation to `index.js` and restores `index.js`
  and nothing else, so a test file that regenerated the corpus would leave the mutated module's
  answers in the working tree. T8 does not touch either file.
- **T8's corpus work is a use, not a regeneration.** The corpus is P4.1's T8's and `shared/` is
  nobody's in this plan, so T8 adds `TestParityCorpusHoldsThePairingExpiry` — the corpus now also
  holds the pairing work's `PromptTTLMs` and the boundary `PromptExpired` draws — and rewrites not a
  byte of `internal/mailbox/testdata/parity.json`.
