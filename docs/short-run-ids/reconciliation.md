# Short run IDs everywhere: reconciliation

**Checked against `origin/main` at `e2e22f8b8`, 2026-11-08.** Where this file disagrees with [spec.md](spec.md), this file wins. Numbers: decisions **D1700-D1709**, checks **440-449** (the highest taken on `main` and in open PRs are D1659 and Check 430).

The spec has four parts: show only the last four characters of a run's ID (1), accept short IDs as input (2), lengthen the display when two shown runs collide (3), make the console's live tab follow `fugaro watch` (4).

## Headline: what the spec proposes, and what the repo already has

| Spec concept | What the repo has |
| --- | --- |
| Short ID = last four characters | `internal/watch/render.go` `shortRun` (the TUI table), `internal/plan/state.go` `runSuffix` (`plan status`, "after the last dash"), `console/src/renderer/screens/graph.ts` (`row.run.slice(-4)`, `runForSuffix`) and `console/src/renderer/graph/model.ts` (`RUN_SUFFIX_RE`). Three implementations of one rule (F2). |
| Accept a full run ID or `<slug>/<run-id>` | `internal/runstore/list.go` `Locate`, reached through `internal/cli/cloud.go` `locateRun` by `logs`, `cancel`, `diagnose`, `artifacts` and `run --retry`; it already reports an ID found in several repositories as `ErrAmbiguous` (F4). |
| Resolve active runs first, then recent | The active set is what `fugaro watch` reads (`internal/watch/build.go`, the budget database's agent entries); "recent" is `runs ls`'s 7-day window (`lsDefaultWindow` in `internal/cli/runs.go`) over `runstore.ListRunIDs` (F5, F6). |
| Interactive "ask the user to choose" | `stdinIsTerminal` and `agentMarker` (`internal/cli`) already tell a terminal from an agent's session (F7). |
| Console live tab like `watch` | The live tab is the approved Flight Deck table (`console/src/renderer/screens/live.ts`), fed by `fugaro watch --json` (`live.watch` in `console/src/main/ipc.ts`) (F13). |

## Findings

**F1. Wrong. A run ID is not `<long-name>-xxxx`.** `internal/task/task.go` (`runIDRE`, `NewRunID`) fixes the form `YYYYMMDD-HHMMSS-` plus **four lower-case hex digits** (`20261108-115248-3bb2`). The short ID is therefore the 4 random hex digits: 16 bits. The spec's collision example (`x3f9a` vs `b3f9a`) cannot occur; extending the suffix by one character after the four reaches the **dash** (`-3bb2`), and a second reaches the last digit of the time (`8-3bb2`). *Consequence:* the collision rule extends the suffix one character at a time from the end, dash included, and every extension is itself a valid "unique ending" input (D1701 sets the minimum length at four, so extensions are longer than the minimum by construction).

**F2. Exists. Three helpers already cut the last four characters.** `watch.shortRun` (rune-safe, "owner spec 2026-10-22, item 1"), `plan.runSuffix` (cuts after the last dash, falls back to the whole string) and the console's `slice(-4)` in `graph.ts`. They agree on valid IDs and differ on invalid ones. *Consequence:* one Go helper in `internal/task` (beside `NewRunID`, `ValidRunID`, `BranchRunID`) and one console helper in `console/src/shared`; the three call sites move onto them (CLAUDE.md "search before you write a helper").

**F3. Wrong. `fugaro watch` does not show short IDs everywhere.** Only the TUI abbreviates (`shortRun` in `internal/watch/render.go`). The plain, non-terminal output (`internal/watch/plain.go`, `RUN` and `FINISHED` columns) prints `run.Run` whole, and `runs ls` prints `<slug>/<run-id>` (`internal/runview/runview.go`, `Row.Run`). *Consequence:* "as `fugaro watch` already does" is only half true; the plain renderer and `runs ls` are in scope of part 1, and so are the other places that print an ID (F10, F14).

**F4. Exists. `Locate` resolves a bare full ID and already knows ambiguity.** `runstore.Locate` takes `<slug>/<run-id>` or a bare ID, checks `runs/<slug>/<id>/task.json` in every repository and returns `ErrAmbiguous` listing the `slug/id` pairs when two repositories hold the same ID. It does not take an ending. `locateRun` (`internal/cli/cloud.go`) is the single door: `logs`, `cancel`, `diagnose`, `artifacts` and `run --retry` all call it, so the change for part 2 is one function and its resolver, not five commands. `followup --run-id` and `review` validate a run ID's shape (`task.ValidRunID`) and do not look it up; they are not "commands that take a run ID to find" and keep full IDs (they mint or name IDs; D1705).

**F5. Gap. There is no suffix index, and the platform lists by time.** Run IDs sort by launch time; `runstore.ListRunIDs` lists `runs/<slug>/` from an offset (`since`), and its cost "depends on the runs minted since then" (its own comment). Finding an ending means listing every repository's runs in the window and filtering client-side. The runs bucket deletes objects after `runs_days` = 90 (`deploy/terraform/gcp/roots/installation/variables.tf`, `modules/installation/bucket.tf`). *Consequence:* the search window is a decision (D1702); the cost of a 90-day listing is UNVERIFIED.

**F6. Gap. "Active" must be defined.** The only live source is the budget database's agent entries that `watch` reads. `locateRun`'s caller already builds the budget client (`budget.rtdb_url` in `internal/cli/cloud.go`). *Consequence:* the resolver takes the active set as an input and the CLI supplies it from the same read `watch` uses; if that read fails the lookup falls back to the recent window and says so on stderr (never a silent narrowing).

**F7. Gap. The spec's "ask the user to choose" has no one to ask in an agent's session or with `--json`.** `stdinIsTerminal` and `agentMarker` exist. *Consequence:* D1700.

**F8. Rule. `--json` and every wire shape keep full IDs, and the console depends on it.** CLAUDE.md "A field never changes meaning" and `console/docs/json-contract.md`: `watch --json`'s `run`, `runs ls --json`'s `run`/`run_id`, the run record and `plan status`'s `run` (already four characters) do not change; no field is retyped. The console's door to Run detail (`wireRuns` in `console/src/renderer/entry.ts`) reads **the drawn text of the `live-run-id` cell** and passes it to the CLI. If the cell shows four characters, the door would pass a suffix. *Consequence:* the cell keeps the full ID in an attribute set from the sanitized field and the door reads that; the console always sends full IDs to the CLI, so no console path ever needs the CLI's ambiguity prompt.

**F9. Gap. Some places must keep the full ID and are not "display".** The branch `fugaro/<run-id>` (`task.BranchRE`, `BranchRunID`: a follow-up continues a run through it), the hidden PR marker (`gitprov.ReportMarker`), bucket paths, `task.json`'s `run_id`/`previous_run`, `--run-id` idempotency and the backlog item's `filed_in: run:<id>` (`internal/backlog/write.go`) are identifiers machines read. The spec's carve-out ("logs and machine-readable output") covers them. *Consequence:* D1705 lists them; a test pins that they stay whole.

**F10. Exists. The agent-written text that carries IDs is mostly written by code, not by the agent.** `internal/runner/prflow.go` writes the PR title fallback (`Fugaro run <id>`) and the status line (``Run `<id>` (... `fugaro diagnose <id>`)``); `internal/runner/report.go` writes the report heading (``### Fugaro run `<id>` ``). The agent's own standing instructions are in `internal/runner/prompts.go`, and the user's agent reads `plugin/skills/working/*` and `parallelism`. *Consequence:* the code-written text is changed in code (and the `diagnose` hint stays a command a reader can paste, now with the short ID); the "never print the full ID" sentence goes into both the job prompts and the plugin skills. Both are **security-tier** paths under the owner's review routing (prompts and plugin skills always get the security reviewer).

**F11. Rule. The prompt rule must not break the commands that need an ID.** The plugin's launch and follow-up references tell the agent to choose its own `--run-id` and to read `run_id` from `--json` output. The rule "Never print the full ID" applies to what the agent *writes for people*; it still passes IDs to commands. *Consequence:* the sentence says so ("pass the short ID to fugaro commands"), and the plugin tests that pin every command the skills name are re-run; the sentence only ships after part 2 is in (task order).

**F12. Gap. "Run or task ID": a task has no ID of its own.** `task.Spec` carries the run's `run_id`; plan task IDs (`internal/plan`, `plan status`) are names the plan's author picks. *Consequence:* D1703.

**F13. Rule. The live tab is an approved design, and it differs from `watch`.** `watch` shows `RUN TITLE STAGE ROUND AGE SPENT BY FLAGS`, ordered by start time then ID (`internal/watch/build.go` `sortRuns`). The live tab draws RUN, title with the rigor chip, pipeline, models and auth, spend, age and state (`runRow` in `live.ts`): the Flight Deck redesign, whose steps edit `flight-deck.css`, `screens.css`, `live.ts` and `run.ts`. *Consequence:* D1704 (how far to follow watch). The spec's "when watch changes, the live tab follows" is a process claim that needs a test to hold: a parity test on `watch --json` fixtures (SR10).

**F14. Gap. "Daily reports" and "issue files" are two code paths with their own ID columns.** The periodic digest (`internal/digest/render.go` prints `r.ID` in its run table; `digest.Run.ID` is the record's full ID) and the backlog (`internal/backlog`, `fugaro backlog`; its file names and titles are built from text a run writes, and the checked-in `docs/backlog/` items already carry full IDs in their names). *Consequence:* human renderings use the short ID; the machine fields (`digest` JSON, `filed_in`) stay whole; the digest submit path (`runs_digest_submit.go`) redacts run IDs already and is checked, not changed. UNVERIFIED: exactly which free-text fields a run fills with its own ID (SR11 finds them by test).

**F15. Gap. Collisions are per display, not per bucket.** Spec part 3 says "runs shown together". The renderers that print a set (watch TUI/plain, `runs ls`, digest, the live tab) compute the shortest distinguishing endings over exactly the rows they print. A detail view and `--json` print the full ID. A short ID printed in one command's table and typed into another is checked by part 2 (D1700 handles a collision at the lookup).

**F16. Gap. Old IDs stop resolving by their short form.** With D1702 a short ID older than 7 days does not resolve; a PR or report that says `fugaro diagnose 3bb2` a month later fails with "not found in the last 7 days; pass the full ID". The PR's branch name and the run record still carry the full ID. See open item O1.

## Decisions

| # | Question | Recommendation and reason | Alternative and its cost | Owner's answer |
| --- | --- | --- | --- | --- |
| **D1700** | A short ID matches several runs and the CLI is not on a terminal (agent, script, `--json`): what happens? | **Refuse as a user error, listing each match with the shortest suffix that tells them apart; never pick one. On a terminal, show a numbered list and let the person choose.** Why: a wrong guess cancels or diagnoses the wrong run, and an agent can retry with a longer suffix. | Pick the newest: silent wrong-run risk. Always refuse: contradicts the spec's "ask the user to choose". | **2026-11-08: the recommendation.** Why: never a silent wrong run; the pick list is for a person at a terminal. |
| **D1701** | Minimum length of an accepted ending? | **Four characters, everywhere** (what is displayed). Why: a stray one- or two-character ending that is unique today names another run tomorrow, and `cancel` is destructive. | The spec's literal "any unique ending": a 1-character ending could cancel a run. Four for mutating commands only: two rules to document. | **2026-11-08: the recommendation (deviates from the spec's literal text).** Why: the displayed form is four characters, and a shorter ending is a typo as often as a choice. |
| **D1702** | Which runs does an ending resolve against? | **The active runs (the live feed), then runs of the last 7 days (`runs ls`'s window).** A unique active match wins over a finished run with the same ending; older runs need the full ID. Why: no suffix index exists, a 90-day listing of every repository on every lookup is the cost (UNVERIFIED), and the full ID always works. | The whole 90 days: slow, many bucket reads. Widen on a miss: a second slower listing, one more rule. | **2026-11-08: the recommendation.** Why: bounded cost; the full ID is the fallback. |
| **D1703** | Does "task ID" mean anything beyond the run ID? | **No.** A task has no ID of its own: `task.json` carries the run's ID; plan task IDs are author-chosen names and stay as written. The agent rule says runs by short ID and plan tasks by name. | Shorten plan task IDs: a new wire field (a plan task's ID cannot be retyped), for names that are already short. | **2026-11-08: the recommendation.** Why: no second ID to shorten. |
| **D1704** | How far does the live tab follow `watch`? | **Short IDs with the collision rule, `watch`'s ordering (start time, then ID), `watch`'s status wording, and the BY column; keep the Flight Deck layout (pipeline, models, rigor chip); a parity test on `watch --json` fixtures makes "watch changes, the tab follows" real.** Why: the Flight Deck table is an approved design that other console work edits. | Rebuild to `watch`'s eight columns: discards the approved table and collides with the Flight Deck steps in the same files. Only short IDs: leaves "follows watch" undelivered. | **2026-11-08: the recommendation (deviates from the spec's "same columns"; see O2).** Why: the approved design stays, the data and wording follow `watch`. |

### Resolutions (one defensible answer, not asked)

- **D1705. What stays full.** The branch name, the hidden PR marker, bucket paths, `task.json`, `--run-id` and `--retry` idempotency, `--json` everywhere, `filed_in`, the details views (the head of `diagnose`, the console Run screen's detail section) and an explicit "copy ID" action (F9, F8). A test per item pins that it stays whole.
- **D1706. One rule, one helper per language** (F2): `task.ShortRun` and `task.DisplayRuns` in Go; the console helper in `console/src/shared`. The collision extension is computed over the rows a renderer prints.
- **D1707. The console sends full IDs only.** The live row keeps the full ID in an attribute from the sanitized field; the door and the copy action read it (F8).
- **D1708. No operator step.** Nothing is deployed or migrated, so `fugaro update` needs no new behaviour and the release's `### For operators` is the usual "run `fugaro update`". The plugin skills change in the same PR as the CLI (CLAUDE.md: a CLI change that touches a documented command changes the skill).
- **D1709. Fallback sentence.** A lookup that finds nothing in the window says "no run ending ... among the active runs and the last 7 days; pass the full ID", and the active-feed failure case says the feed could not be read (F6, F16).

## Open tensions and open items for the owner

- **O1 (tension, D1702 against spec part 1).** The runner writes a PR status line with a pasteable `fugaro diagnose <short>`. It resolves for 7 days. After that the reader has the PR's branch (`fugaro/<full id>`) and the full ID in the run record, but the printed hint fails. Options: accept (the hint says "or the full ID from the branch"); or let `diagnose`, `logs` and `artifacts` also accept a `fugaro/<run-id>` branch name. The plan takes the first and asks the owner to rule.
- **O2 (tension, D1704 against spec part 4 and its acceptance line "matches in content and layout").** The live tab will match `watch` in IDs, ordering and wording, not in column set. If the owner wants literally the same columns that is a rebuild of the approved table, planned separately.
- **O3.** The minimum length (D1701) means a 3-character ending, which the spec allows, is refused with "give at least four characters".

## UNVERIFIED

- The listing cost of a 7-day (and a 90-day) cross-repository scan; one bucket "list with prefix and start offset" per repository is the known unit.
- Whether `fugaro watch`'s active read can be reused by a command that has no `--repo`, without a second RTDB connection (the CLI caps concurrent connections; `watch` holds four).
- The number of print sites in `internal/cli` that format a run ID (a grep finds 19 formatting calls naming a run ID or `.ID`, concentrated in a few files); SR11's sweep test finds the rest.
- Which free-text fields of a backlog item or a report a run fills with its own ID (F14).
- How the live tab orders rows today (`live.ts`), against `watch`'s order; SR10's parity fixtures settle it.
