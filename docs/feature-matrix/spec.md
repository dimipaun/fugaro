# Fugaro Spec: Feature Matrix

## Summary
Produce a user-facing feature matrix for Fugaro, derived from status.md, kept as a markdown file in the repo and published as a web page refreshed on every release.

## Motivation
Fugaro is built through spec-driven development. Each spec produces an implementation plan with tasks, and status.md gives a bird's-eye view of every spec, grouped as Done, Parked / To do, Nearly there, and Work in progress. That view is organised around specs, not around what the product does. Some specs are purely technical, some are go-to-market, and some user features are split across three or four specs. Prospective users evaluating whether they need Fugaro care about capabilities, not implementation details.

## Audience
Primarily new users evaluating Fugaro. Secondarily existing users (currently one) wanting to know what works today.

## Matrix columns
Keep it simple. Each row has:
- **Feature**: a capability named in the user's language.
- **Explanation**: one or two sentences on what it lets the user do.
- **Status**: Available or Coming soon. (Optionally Planned for items not yet started.) Internal states such as Nearly there or Parked are not exposed.
- **Tier**: which product tier includes the feature.

## Derivation from status.md
1. Read status.md and all referenced specs.
2. Exclude specs that are purely technical/internal (refactors, infra, hardening) or go-to-market, unless they produce a user-visible capability.
3. Merge specs that contribute to the same user feature into a single row.
4. Map status: a feature is Available only when all contributing specs are Done; otherwise Coming soon (or Planned if no contributing spec has started).
5. Write the feature name and explanation from the user's point of view.

**Stability**: keep a hand-maintained mapping file from specs to features, so feature names and groupings don't shift between releases when the agent regenerates the matrix. The agent flags new specs that aren't mapped yet.

## Outputs
- **FEATURES.md** (or docs/feature-matrix.md) in the repo: the source of truth.
- **Public web page** generated from the markdown file.

## Refresh cadence
On every release, regenerate the matrix from the current status.md and republish the web page as part of the release process.

## Out of scope
- Comparison against competing tools.
- Exposing per-spec or per-task progress publicly.

## Open questions
- Final list and names of tiers.
- Whether the merge/mapping of specs to features is maintained by hand in a mapping file or regenerated by the agent each release.
- Hosting location for the web page.
