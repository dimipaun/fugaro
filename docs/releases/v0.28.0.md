- **A review is checked against the task the pull request was written for.** A review is given the task of the run that opened the pull request and can say that part of it is unmet or that the change differs from it, `fugaro review --code-only` reviews the code alone with no task, and `--spec FILE` judges the pull request against the task in that file, which is how one no run produced is reviewed against something; both flags are on `fugaro run --recipe review-only --pr N` too, `fugaro review show RUN` prints the one line saying what the review was judged against, and the key `agent.review_against_task` — a repository's, and the project's published policy — is what switches the default off.

### For operators

1. Run `fugaro update`: it is the whole upgrade, and the job images are rebuilt there, which is what lets a review read the task. Until an image is rebuilt, a review launched onto it runs code-only and the launcher says so in one line; publishing the policy key `review_against_task` makes a CLI older than this release refuse launches with its own sentence naming the upgrade and `fugaro update`.

### Known limits

- A CLI older than this release refuses a review artifact a newer job image wrote: the artifact's reader is strict, and the `against` record the newer image adds is a field it does not know. The CLI and the images are the two halves of the same upgrade, and `fugaro update` is the one command that moves both.
