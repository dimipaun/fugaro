- **Review rounds follow the rigor mode, and a repository that configures nothing now runs more of them.** Each mode supplies its own default first-line and senior round counts — POC 1/1, Startup 2/2, Pro 3/3, Critical 3/5, Hotfix 1/1 — so an unconfigured repository, which runs at Pro, now runs 3 first-line and 3 senior rounds where it ran 1 and 2, which costs more per run under the same per-run ceiling; `agent.first_line_rounds` and `agent.review_rounds` in `fugaro.yaml` or the project layer set another number, up or down.
- **The credentials service speaks HTTP/2 end to end, and an ordinary `fugaro update` moves it to the new image.** From this release the service serves HTTP/2 cleartext as well as HTTP/1.1 and Cloud Run is told so, which keeps a large git push off the HTTP/1 body limit, and `fugaro update` re-pins an opted-in installation's credentials image to the release's signed, verified digest instead of carrying the old one forward.
- **`fugaro update` publishes what your local config states.** The policy stage writes the budget block, model-price overrides, base branch, routing switch and review floor your local config carries into the published policy node, and a new Layer stage seeds the project's one local layer file (`projects/<project>.layer.yaml` in your config directory) from the published layer and publishes your edits to it, refusing with a three-way view and offering a re-seed when someone else published since you last did.
- **`fugaro settings` shows every setting, the value a run gets and the layer that decided it.** It reads the offline layers only (defaults, the project layer's cache, the local config, the environment and the checkouts this machine remembers), writes nothing, never prints a sensitive value, and takes keys or globs with `--changed`, `--grep`, `--layer`, `--all-repos` and `--json`.
- **Faster reads.** `fugaro runs ls --limit N` reads only the newest N runs rather than the whole window, `--state` lists the runs in one state, and `fugaro report` no longer reads the whole day before its window to catch runs minted just before midnight.
- **Smaller fixes.** `budget set`, `budget kill`, `budget resume`, `accounts clear`, `project policy publish`, `project repos add` and `rm`, `project sync` and `pair` refuse a budget database the installation has not adopted, with the same check and remedy `fugaro update` uses; the account name `bitbucket-token` is refused as `agent.oauth_token` and as a task's `oauth_token`, not only as an account name; remembered checkouts skip temporary directories and linked worktrees and forget a path missing for 30 days; and the coordinator's stored view names each repository's provider.

### For operators

1. Upgrade the CLI, then run `fugaro update` in each checkout.
2. If the installation opted into the credentials service: run `fugaro update`. It will re-pin the credentials service's image and redeploy the service on the new image for an installation that opted in under an earlier release; the plan is shown and confirmed as every other installation-root apply is, and nothing else is asked of you. (An installation that never opted in plans as it always did.) The re-pin verifies the image's cosign signature, so `cosign` has to be on the `PATH`, and an update that cannot reach the registry now fails before the first apply rather than carrying the old image through.
3. Round counts changed for every repository that does not set them: one at Pro (the default) now runs 3 first-line and 3 senior rounds where it ran 1 and 2. To keep the old counts, set `agent.first_line_rounds: 1` and `agent.review_rounds: 2` in `fugaro.yaml` or in the project layer.
4. The first `fugaro update` of this release adopts the published policy and layer generations it reads; from then on it publishes local edits to both, and when someone else published past the generation it recorded it shows the three-way state and offers to re-seed the local file (with a backup) instead of overwriting.

### Known limits

- The review-levels work is groundwork: a task's `review_levels` block is decoded and validated but nothing acts on it yet, and a recipe's `adversarial` step (review level 3) parses but no runner runs it — the launch refuses it against an image older than 0.15.0, and a 0.15.0 run stops at planning with a message saying so.
- Shared images are not in this release: `checkout: shared` is still refused, although the refusal's message says they arrive in 0.15.0; the lockfile reduction that will key them is in the code and changes nothing a build does.
- Bitbucket brokering is not in this release: a Bitbucket run's job still holds its own token, and the git proxy through the credentials service and the flip to it come later.
- That HTTP/2 lifts the large-push limit end to end rests on the design's reading of Cloud Run and has not yet been confirmed by a live push larger than 32 MiB.
- `fugaro settings` reads only; changing a setting through it comes in a later release.
