- One base image for every project: the `go`, `web-node` and `java-services` images are gone, replaced by a single language-agnostic `fugaro-base` (Debian, `mise`, Claude Code and the other agent harnesses, a broad tooling kit, `graphify`, built for amd64 and arm64). A project declares its runtimes in a `mise.toml` (or `image.tools` in `fugaro.yaml`) instead of choosing a language image; `base:`, `image.node` and `image.jdk` are now refused with a message that points at `docs/base-image-migration.md`, and a 0.6 CLI refuses the new `fugaro.yaml`, so this is a breaking release.
- Recipes grow up: a starter catalog with a "use when" line each (`fugaro recipes ls --verbose`), a coder that can be the reviewer, a review mode for existing pull requests (trusted authors only: `review.allow_forks` is removed), a bounce between coder and reviewer, check steps that gate a run, and `commands.lint` / `commands.fix` with autofix commits before the review. The routing skill picks a recipe from the catalog, and `fugaro run --attempts N` runs a best-of-N batch under one budget.
- `fugaro runs ls` lists runs (the old `fugaro ls` prints a pointer to it), and the run registry now carries the last action and token count. A workflow can say how its repository is provisioned with `workflows.<name>.checkout: baked | clone`; `clone` is accepted by the schema but refused at launch until 0.7.1, because the runner side is not released yet, and `fugaro init --repo` and `fugaro image refresh` refuse to deploy a clone workflow.
- The runs bucket is hardened: launchers read it and write only under `runs/`; operators keep full control. It takes effect only when an operator applies the Terraform (`fugaro init`), and `fugaro doctor` gains a `runs-bucket-iam` check that fails closed.
- Provider models (a non-Anthropic model through OpenRouter) report real cost, so the budget caps count what a run actually spent (0.6.7), and a DeepSeek coder and reviewer has run end to end. The README's "Why Fugaro" is rewritten around four reasons.

### For operators

1. Upgrade the CLI: `brew upgrade dimipaun/tap/fugaro`.
2. Migrate each repository before merging anything else: remove `base:`, `image.node` and `image.jdk` from `fugaro.yaml`, declare the runtimes in `mise.toml` (the `/fugaro:setup` skill does it), merge, then run `fugaro image refresh` in the checkout. It copies `fugaro-base` (published by this release's tag) into your registry, moves the daily image check onto it and rebuilds each workflow's image; it asks before every billable build. Until the 0.7.0 tag has published `fugaro-base`, `fugaro image refresh` refuses with a clear error. A shared config published by an older Fugaro that still lists `go`, `web-node` or `java-services` is accepted with a warning and cleaned the next time someone publishes.
3. The old per-language images (`fugaro-go`, `fugaro-web-node`, `fugaro-java-services`) stay on ghcr.io forever as history, but no release after 0.6.x refreshes them.
4. To get the bucket hardening, run `fugaro init` for the installation in your own terminal and read its plan: it deletes only the launchers' old `objectAdmin` grants, behind its own banner and confirmation. Until then nothing changes, and a one-person installation plans no change at all.
5. Not yet verified live: the cold-start time of a run on the new base image (the 0.6 image measured about 12 seconds on the sandbox; the owner repeats it after migrating) and the bucket hardening's live Check 32 (run on the `fugaro` installation, never on `belong`).
