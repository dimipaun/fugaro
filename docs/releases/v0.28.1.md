- **Switching a repository's Claude account now leaves a job for its runs to launch on.** After moving a repository onto another account, `fugaro run` was refused with "job … does not exist; create it with fugaro update", and `fugaro update` applied nothing, because `update` treated the repository as running on the project's shared jobs while `run` still launched its baked workflow on a job of the repository's own. `fugaro update` now keeps applying the repository's own jobs for a repository with a baked workflow, so the job for the account the repository now names is created.

### For operators

1. **Per installation** — run `fugaro update` once, at your own terminal, from the checkout of each repository whose Claude account you changed on 0.28.0 (`fugaro update --repo`). It creates the repository's job for the account it now names, and it asks only the confirmation it already asks ahead of an apply. If the plan retires the job of the account you moved away from, it says so and names the one flag that carries the retirement out (`fugaro update --repo . --retire`).
2. It waits for no run, and it says so in one line when runs are running: the count, and that it waits for none of them and changes nothing they hold.

### Known limits

- A repository whose workflows are all `checkout: clone` still runs on the project's shared jobs, as in 0.28.0; only a repository with a baked workflow keeps its own jobs until the shared job carries the tools such a workflow declares.
- A Bitbucket profile's project job still carries its account in its name, so moving that profile to another account is refused as in 0.28.0.
