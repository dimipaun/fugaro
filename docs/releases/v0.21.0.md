- **A run's default time budget is now three hours, up from ninety minutes, and a stage gets one hour instead of forty.** A security-reviewed task with three review levels fits the default stage window, so a long task no longer has to be relaunched with a longer limit to finish.
- **A repository that wants a different budget still says so in `fugaro.yaml`**, and `fugaro run --total-timeout` still overrides one run's limit alone; the engine refuses a value above 24 hours.
- **An existing installation takes the new defaults with `fugaro update`**, with no other step.

### For operators

1. Run `fugaro update`.

### Known limits

- A run already in flight keeps the budget it started with; the new default reaches runs launched after the update.
- A repository whose `fugaro.yaml` writes its own `timeouts` keeps them, including one that pins the old ninety minutes on purpose.
- A stage that runs longer than about 50 minutes outlives the run's git credential. The runner refreshes a GitHub installation token before each stage but never asks for more than 50 minutes, which is all GitHub will give, so the agent's `git` and `gh` calls late in a longer stage fail until the next stage's refresh. The new 60-minute default stage is inside that window; a workflow that must not have it sets `timeouts.stage` to 45 minutes or less. Runs on Bitbucket are unaffected, and the previous 40-minute default stage was below it.
