- **The review-range fix is cheap at any branch count.** The runner's work to find a run's own commits (`ls-remote`, the object check and the ancestry check behind the workflow-file guard) now takes the same few git calls however many branches origin has; it no longer puts every branch on a command line, so a repository with tens of thousands of branches cannot hit the argument limit.
- **It says what the review covered.** The pull request status section and the run report now read `review covered commits after <sha> (n commits); this PR also carries m commits from other branches`, and when a fix round moved the branch off the narrowed commit the prompt for that round names the range it really reviews.
- **It needs git 2.44 or later in the job image and says so.** On an older git the run does not narrow its review range and logs one warning; the base image's git is checked by a test.
- **A run records the backlog items it closed.** `result.json` gains an optional `backlog_closed` list (up to 64 ids, same shape as `backlog`), and the pull request status line reads it.
- **The coordinator stops wasting its read budget.** A pull request the host refuses three ticks in a row is retried once a day instead of every tick, and a success clears it.
- **The release-streams file is stricter.** `docs/release-streams.yaml` now refuses a `next` name that is not the first unspent name, and the plan graph's stream list comes from the same place.

### For operators

1. **Per installation:** the runner changes live in the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`) to get them. Nothing is needed per repository, and no CLI flag or config changed.

### Known limits

- A first-run agent can still push its own commits to another branch on origin and have them left out of its review; GitHub still refuses workflow-file changes without the workflows permission.
- The narrowing note can miscount when a run merged its base branch in after narrowing (it counts the merged commits as the run's own); the review range and the guard are not affected.
- `gitops.HeldBy` does not validate its head list itself; its only callers pass SHAs that already passed a full-SHA check.
- "Narrower" is judged by commit count, not by files or lines, and `changed_files` still lists a branch's inherited files.
