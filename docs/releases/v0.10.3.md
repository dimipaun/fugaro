- **`fugaro setup` says what to ask for when it cannot create the project or link billing.** A refused project creation or billing link used to end in a raw cloud API error. It now stops with one plain line: your account may not create projects in your organization, or lacks the billing role, who to ask (your organization's admin), and the one `gcloud billing projects link` line for the billing case. Any other error is printed exactly as before.
- **The setup page is short, and describes one path: a new project.** `docs/gcp-setup.md` now starts from install, log in and have ready (an account that can create a project and link billing), with what `fugaro setup` checks for you and what to ask IT when it refuses. The old adoption and second-Firebase-project sections are gone from the page.

### For operators

1. **Per machine** — upgrade the CLI on every machine that runs Fugaro: `brew upgrade dimipaun/tap/fugaro`.
2. Nothing in your cloud project changes by upgrading alone, and no checkout needs `fugaro upgrade` for this release.

### Known limits

- **The refusal messages have not been run against a real organization policy.** They are tested against fake cloud responses (403, 400 and a refused operation); the wording may be tuned once someone runs setup under a real organization.
- **The command still offers what the page no longer documents.** The setup wizard's "adopt an existing project" answer and the flags that exist for it are removed in the next minor release; this release only changes the documentation and the refusal message.
