- **One default base branch for a project.** A top-level `base_branch:` in the installation config (and in the published project policy) is now the branch every repository's runs are cut from and its pull requests target; a repository's own `fugaro.yaml` `git.base_branch` overrides it, and `main` remains the last fallback.
- **One Bitbucket token for many repositories.** A `project_secrets` entry's `allow_data_to` list accepts a wildcard inside a segment (`myworkspace/*`), so one workspace or project access token set with `fugaro secrets set bitbucket-token --project-wide` serves every current and future repository it matches; the help text and the git-providers and security pages now say what that token reaches and that the agent holds its long-lived value.
- **Governance warns before a daily cap.** A run warns once a daily budget cap reaches 80% (with a no-colour marker in `fugaro watch`), and `fugaro watch` shows the governance status; a cap of 0 is understood on all three surfaces.
- **Diagnose reads back more.** `fugaro diagnose` (and `--json`) print the run's stages, the findings a rigor mode tolerated and its score, and the run record says what review read beyond what implement wrote.

### For operators

1. **Per installation:** the runner changes live in the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`) in your own terminal, so the images are 0.12.1 or later; a run launched from an older image drops the project base branch with a warning and is cut from the installation's base branch.
2. **Behaviour change, per repository:** a repository's committed `fugaro.yaml` `git.base_branch` now wins over a local `repos.<r>.base_branch` entry (the order was the reverse). If your local entry differs from the committed file, align them.
3. **Optional, per project:** to set the project default, add a top-level `base_branch:` to the installation config and publish the project policy again (`fugaro project policy publish`, in your own terminal).
4. **Optional, per project:** for one Bitbucket workspace token, add `allow_data_to: [myworkspace/*]` to the `bitbucket-token` entry, then `fugaro secrets set bitbucket-token --project-wide` and `fugaro update --repo` per repository, in your own terminal.

### Known limits

- The workspace and project token path for Bitbucket is documented but not yet live-checked (Check 180); shared jobs for Bitbucket and the broker proxy that would remove the long-lived token from the agent come in later releases.
- The wildcard matches inside one segment only: no bare `*`, no wildcard owner, at most two `*` per entry.
- The infra image and check specs read the project default from the local config, not the published policy, so a teammate without the entry builds from the installation's branch; set `repos.<r>.base_branch` locally as a workaround.
