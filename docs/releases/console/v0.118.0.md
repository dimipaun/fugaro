# Fugaro Console 0.118.0 "Plum"

Console 0.117.0 redesigned only the Graph's canvas and left the rest of it, and the whole Coordinator screen, in the old look; Spend opened on 30 days, a run opened from Live gave no sign the click had been taken until its record arrived, the Graph could not say which of an installation's repositories to read a plan from, and the Coordinator showed what was going on without saying what needed you. Plum finishes the Graph and Coordinator redesigns, makes the Coordinator a list of what is waiting on you, lets you open a pull request from its number, and adds crash reports you can turn on.

- **The Graph's toolbar, inspector and legend:** the stream tabs are one segmented control, and the filter draws only the chosen stream instead of leaving empty bands where the others were. The inspector shows the selected task with an **Open run** button, and the legend under the canvas explains the cards' borders and edges.
- **Pick the checkout from a dropdown:** an installation with several repositories offers one entry per enrolled repository whose checkout the CLI has checked, in the Graph's card and in the installation's issue view; it never offers agents' worktrees or missing directories, and with only one usable checkout it picks that one by itself and says so. When there is none, the Graph says so on a calm card.
- **The Coordinator in the new look:** one panel per repository with its name first, a strip of counts (collisions marked in red, with the word beside the figure), the stale marker as a banner, and each pull request as a row with its runs under it.
- **What is waiting on you:** the Coordinator opens with an action queue and the fleet's totals. Each item has one button: a pull request ready for review or merge (**Open run**), a halted or failed job (**Retry**), a plan task ready to launch (**Launch**) or a budget alert (**Open Spend**). Retry and Launch open the launch confirmation you already know, filled in; nothing starts until you confirm it there.
- **Pull request numbers open the pull request:** on the Coordinator, a pull request's number is a button that opens it on GitHub or Bitbucket in your browser. The console builds the link itself from the provider, the repository and the number, and never follows a link stored in a document.
- **Spend opens on the last 7 days, by day.** The 30-day, 90-day and 12-week windows are still in the picker, and the CLI's own `report` still defaults to 30 days.
- **A run opened from Live answers at once:** clicking a job's id on Live draws the run screen in the same moment, with a busy mark until its record arrives. On the run screen, the busy mark covers only the record and its diagnosis, not a log window that has already loaded, and leaving the run stops both of its reads.
- **Crash reports, off unless you turn them on:** **Send Crash Reports (applies at the next launch)** is a new checkbox in the console's menu, on macOS and Linux. It is off by default, and nothing is sent unless you tick it. When it is on, a crash report goes to Sentry, hosted in the European Union, and holds only the error's type and the app's own frames it was thrown from: no message, no path, no user name, no environment and no host name. The setting takes effect at the next launch, both on and off.
- **Download the build you need:** the `.dmg` (macOS, signed and notarised), or the AppImage or the `.deb` (Linux, **unsigned**: an AppImage is not code-signed, there is no Linux signing key and none is planned; the SHA-256 in `console-sha256sums.txt` is what proves the bytes, and that file is signed with the Sigstore bundle beside it). There is no Windows download.

### For operators

- On macOS, console 0.117.0 offers this update by itself: press **Restart to update** when the notice names 0.118.0. On Linux, download the AppImage or the `.deb` from this release's page.
- Crash reporting is **off by default** and stays dormant until a user turns it on in the menu: an upgrade sends nothing.
- The step that uploads the console's debug symbols to Sentry after each build is staged at `docs/pending-workflows/console-release-symbols.yml`, not running. Once copied in, it does nothing until the owner adds a `SENTRY_AUTH_TOKEN` secret to the `console-release` environment; this release's build uploads no symbols.

### Known limits

- Crash reports are not yet readable against the uploaded symbols: once the symbol upload runs, the files are uploaded but not yet effective, because the reports the console sends do not yet carry what Sentry needs to match them to the uploaded source maps.
- The pull request buttons open only `github.com` and `bitbucket.org`; on any other host the number stays plain text.
- On the Project screen Kill, Revive and Add cap are drawn but disabled, Halt fleet, Halt project and Reap stay disabled, and the Graph inspector's Pause task is drawn disabled: launching is still the console's only write.
- The Caps today panel does not show per-repository compute spend yet.
- The console reads a day of runs and draws the newest rows only; it does not yet ask the CLI for a limited listing.
- Launching needs Fugaro 0.11.2 or later, and the leased split on the cap bar needs Fugaro 0.13.0 or later.
- Windows comes in a later release.
- The Fugaro Subscription Terms that the licence refers to may not be published yet.
