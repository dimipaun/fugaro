# Fugaro Console 0.124.0 "Ugli"

Ugli shows a plan's estimate on the Graph screen, lays the graph out top to bottom so a wide stream no longer
needs sideways scrolling, and makes the Live screen's sparklines and run rows behave on a busy day. A section
that cannot be read now offers a Retry. The estimate needs **Fugaro 0.26.0** or later; the console also builds
on Windows through WSL, but there is still no Windows download.

- **The Graph screen shows each plan's estimate.** Under a plan's heading in the list drawing it prints the
  CLI's own sentence, for example `ready in 40-70 min, $3.00-$5.00`, or `no history yet for 3 tasks` where the
  cost could not be computed. A CLI older than 0.26.0 prints no estimate and the screen draws nothing in its
  place; when the installation's reduced mode is on, the dollar figures are withheld and the minutes stay.
- **The graph lays out top to bottom, and wide levels stack.** A level of more than four cards is cut into rows
  of four, so a stream fits the window's width instead of running off to the right.
- **Live sparklines are drawn in place and readable.** Each sparkline is one fixed-size box that keeps the newest
  samples, a bar no longer carries a percentage written in low-contrast text (the rate is in its tooltip), and a
  repository's run rows scroll inside a bounded box instead of lengthening the page.
- **A section that was refused or timed out has a Retry.** It reads that one section again, and an empty section
  says so in a plain sentence instead of drawing nothing.
- **A write refreshes what it changed.** After a settings change, a roadmap move or a run launch, the tabs that
  show the changed data are cleared and read again at once rather than showing the old figures until you leave.
- **Run records carry the rigor level under its new name.** The console reads a run's level from `level` and falls
  back to `mode`, so runs recorded before and after the rename both draw.
- **Under the hood, nothing to see yet.** The console reads the pending steps a management command saved
  (`fugaro apply --status --json`) and passes `--no-apply` on a settings write to a CLI that registers it
  (0.26.0 and later), saving the change and leaving its follow-up steps to be read back; both are in this build
  and 0.123.0 carried them without saying so. No screen draws the pending steps yet.
- **Download the build you need:** the `.dmg` (macOS, signed and notarised), or the AppImage or the
  `.deb` (Linux). The Linux artifacts are unsigned: an AppImage is not code-signed, there is no Linux
  signing key and none is planned; the SHA-256 in `console-sha256sums.txt` is what proves the bytes, and
  that file is signed with the Sigstore bundle beside it.

### Known limits

- **The estimate needs Fugaro 0.26.0 or later.** Against an older CLI the Graph screen draws no estimate line.
- **The Graph and Live screenshot goldens have not been re-recorded** (the owner's Check 710), so the recorded
  images still show the earlier left-to-right graph and the old sparklines; the console's read timings (Check
  711) and Check 712 have not been run either. CI skips the goldens, so nothing fails, but a layout the pictures
  would have caught has been checked in the unit suites and not by eye.
- **The graph pane may still scroll sideways.** This release lays the graph out top to bottom and bounds a
  level's width; the follow-up that makes the pane scroll vertically only is not in it.
- **The pending steps are read but not drawn.** No screen shows them yet.
- **There is no Windows download.** The Windows installer is unsigned and is packed at release time only,
  attached to nothing, and the WSL route has not been confirmed on a real Windows machine.
- **The licence screens are as in 0.123.0.** The subscriptions plan's lapse-state screen is not in this
  build, and the licence key entry and seat screens that are here are unchanged from 0.123.0; this build's
  licence keyring is still empty until the owner's signing keys exist, so no key verifies in a real build.
