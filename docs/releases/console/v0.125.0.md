# Fugaro Console 0.125.0 "Watermelon"

Watermelon groups the Project tab's settings into collapsible sections with a search box, edits a setting in one
window that shows the change before it is written, lets the Graph screen scroll top to bottom only, and draws
the Coordinator's waiting runs as they arrive. Most of what is new in the main process and the Manage lists
waits on a Fugaro release that carries the commands behind it, so against **Fugaro 0.26.1** the visible changes
are the first four below. The console also builds on Windows through WSL, but there is still no Windows download.

- **Settings are grouped, and searchable.** The Project tab's settings section files the rows under ten
  collapsed sections (each opens on a click) instead of one long list of dotted keys, shows each row's label and
  description when the CLI sends them, and has a search box that narrows the rows already read. A CLI that sends
  no labels still draws every row, by its key, and a key no section names falls under `Other`.
- **One window for a setting change.** Editing a setting opens a single window with the value's own control,
  checks the value before the OK button is enabled, shows the change the CLI would make, and writes it only on
  the second yes. A reset to the built-in default is a choice in the same window.
- **The graph scrolls top to bottom only.** The Graph screen's pane no longer scrolls sideways: the picture is
  drawn at the pane's width and scales down to fit, and the pane scrolls down for a longer plan.
- **The Coordinator's queue fills in as the runs arrive.** Where the CLI can stream its run list, the waiting
  runs are drawn a batch at a time instead of after the whole list is read; a stream that stops early says so
  and offers the section's Retry rather than showing a shorter list. A CLI that cannot stream is read as before.
- **A write control your role cannot use says why.** Where the CLI can report your role, a control that needs a
  higher one (for example Halt fleet, which needs the admin role at project scope) is drawn disabled with a
  tooltip naming the role it needs and your own. When the role cannot be read, every control is drawn as
  before and the CLI's own refusal is what you read after the click.
- **Under the hood, nothing to see yet.** This build carries the Manage section's shell and its lists (models and
  keys, repositories, images and recipes, budget, members, roles and accounts), the setup wizard's main-process
  half, and the nine new operations the console may ask the CLI for. None of them is on a screen yet: the Manage
  section is not mounted in the Project tab, and the wizard's operations answer that they are not available.
  No secret is drawn by any list, and every add, revoke or removal is a command to copy and run in your own
  terminal.
- **Download the build you need:** the `.dmg` (macOS, signed and notarised), or the AppImage or the
  `.deb` (Linux). The Linux artifacts are unsigned: an AppImage is not code-signed, there is no Linux
  signing key and none is planned; the SHA-256 in `console-sha256sums.txt` is what proves the bytes, and
  that file is signed with the Sigstore bundle beside it.

### Known limits

- **The Manage lists and the setup wizard are not on a screen.** They are built and tested, and no tab mounts
  them yet. When they are, the Members and Roles lists draw every address redacted: the follow-up to the
  people-and-access lists, whose Member column uses the `label` text class, which redacts an address.
- **The newer CLI reads have no floor yet.** The role read, the run, spend and budget streams, the image and
  recipe lists and the setup plan are asked of no CLI until the Fugaro release that carries them is named, so
  with 0.26.1 the role-gated tooltips and the streamed queue do not appear and the screens behave as in 0.124.0.
- **The screenshot goldens have not been re-recorded** (the owner's Checks 710 and 712), so the recorded images
  still show the earlier Graph, Live and settings screens. CI skips the goldens, so nothing fails, but a layout
  the pictures would have caught has been checked in the unit suites and not by eye.
- **The console's unit tests can time out on a loaded machine.** They pass when run alone or with
  `--maxWorkers=2`; a timeout under load is the machine, not the code.
- **There is no Windows download.** The Windows installer is unsigned and is packed at release time only,
  attached to nothing, and the WSL route has not been confirmed on a real Windows machine.
- **The licence screens are as in 0.124.0.** The subscriptions plan's lapse-state screen is not in this
  build, and this build's licence keyring is still empty until the owner's signing keys exist, so no key
  verifies in a real build.
