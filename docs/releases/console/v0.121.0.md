# Fugaro Console 0.121.0 "Raspberry"

Raspberry adds five read-only sections to the Project tab that show what the CLI does on a managed
project — whether the project is managed and who admitted what, the accounts a run's stages use, the
published policy node and what the CLI says is wrong with it, what the last plain `fugaro update`
retired, and the credentials service's state — and every one of them needs **Fugaro 0.21.0** or later,
because that release is the one whose documents they read.

- **The Project tab now draws the managed project itself.** Five sections sit on the project screen
  beside the panels that were already there: **Managed state**, **Review account keys**, the policy
  panel, **The last update's retirements** and **Credentials service**. Each makes its own read of its
  own command and paints the moment its own answer arrives, so a slow one never holds the others back,
  and a section that cannot read says so in the CLI's own words and names the command it ran rather
  than drawing an empty figure. Nothing in the five waits on a sibling, and the jobs list is still not
  part of the first paint.
- **Whether the project is managed, and who admitted what.** The Managed state section draws the two
  marks as the CLI reads them — managed or not managed, the CLI's own reason when it is not, and the
  version and generation the marks carry — and, for a project that is managed, the audit trail beside
  them: the day it covers, how many records that day holds, and the newest record's time, command,
  verdict (admitted or refused), the identity the write ran as and its plan digest. The section's own
  field set is bounded on purpose: the argv the write ran as stays in the CLI's record and is not
  drawn. There is no "revoked": the marks' own answer plus the last record's verdict are what a screen
  can honestly say.
- **The accounts a run's stages use, as names.** The review account keys section lists the project's
  default account and the account each stage is set to, with the key and the stage each row belongs to
  and `unset` for a key nothing decides. A row the CLI's own read marks sensitive is not drawn at all —
  no key, no value, no row — so a token cannot reach the screen, and an account is a name by
  construction.
- **The published policy, and what is wrong with it.** The policy panel no longer says it cannot read:
  it reads `fugaro project policy show --json` and draws the node's own members — the accounts, each
  with the repositories its token may be used by, the allow-list, the base branch, the routing switch
  and the image catalogue — with the six `policy-*` checks `fugaro doctor --json` reports about that
  node, each in the CLI's words and saying which of the two documents the line came from. It claims no
  diff between publishes.
- **What the last plain update retired.** The retirements section draws the machine's own record of the
  last `fugaro update` on that project: each retired resource's address, kind, why it went and whether
  it was kept or protected, the secret's **name** where one is named and never a value, the time the
  retirement settled and how many runs were in flight while it did. **Nothing retired by the last
  update** and **no update recorded yet** are two different sentences, so a project that retired
  nothing is never drawn as a project nobody has updated.
- **The credentials service's state, in doctor's own line.** The Credentials service section draws the
  `credentials-service-deployed` check `fugaro doctor --json` returns, with its severity, its problem
  and its fix, verbatim. A CLI whose doctor does not report that check says exactly that instead of the
  section drawing "off" — nothing here re-derives a state the CLI has already decided.
- **Still read-only.** The five sections add no third write and no control that changes anything: every
  control is a read, a refresh or an expand. Launching (rule 11) and the settings pencil (rule 12) stay
  the console's only two writes, and a value one of these sections shows — the project's default account
  among them — is drawn without a pencil.
- **Download the build you need:** the `.dmg` (macOS, signed and notarised), or the AppImage or the
  `.deb` (Linux, **unsigned**: an AppImage is not code-signed, there is no Linux signing key and none is
  planned; the SHA-256 in `console-sha256sums.txt` is what proves the bytes, and that file is signed
  with the Sigstore bundle beside it). There is no Windows download.

### Known limits

- **The five sections need Fugaro 0.21.0 or later.** That release is what prints `fugaro managed status
  --json` and the retirement record inside it. On an older CLI each section draws that CLI's own
  refusal, and the managed state, the trail and the retirements have nothing to draw.
- No section writes, and none of them is a control for anything else: a project that should be managed
  and is not is flagged with `fugaro managed flag`, and the console only says so.
- The audit trail is the newest records of the current day, plus the previous day when today holds none.
  There is no date control and no paging: the section shows what the CLI prints and nothing older is
  reachable from the screen.
- Nothing on the screen claims what the last `fugaro update` changed in the policy. That change is
  printed by the update and recorded nowhere, so the section draws the node and the checks and says so
  rather than guessing a diff. The runs in flight at a publish are not recorded either; the number the
  retirements section draws is the one the last update's own record carries.
- The retirements come from the machine's own record of its last plain `fugaro update` for that project.
  A record this console cannot read — a shape it does not know, or a document that carries no record at
  all — is refused with the read's own sentence rather than drawn as an empty set.
- A credential is drawn by name and never by value, a settings or policy row the CLI marks sensitive is
  not drawn, and doctor's own sentences are drawn as the CLI wrote them, with a credential a child
  happened to echo still redacted.
- Windows comes in a later release.
- The Fugaro Subscription Terms that the licence refers to may not be published yet. This build
  carries the console's offline licence-key verifier, but nothing asks for a key yet and its keyring
  is empty until the owner's signing keys exist: every licensed release is still honour-based, and key
  enforcement arrives with the key service.
