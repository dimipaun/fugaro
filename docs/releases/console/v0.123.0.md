# Fugaro Console 0.123.0 "Tangerine"

Tangerine adds a Members view, lets you move a task to another release by dragging it (behind a preview
and a confirmation), and gives the Live screen a spend-rate gauge, a second sparkline and two cap bars. The
Members view and the drag need **Fugaro 0.24.0** or later; the gauge and the cap bars read what **0.23.0**
and later already print. The console also builds on Windows, through WSL, but there is still no Windows
download.

- **A Members view, read-only.** It lists the project's members and the roles each holds, read from
  `fugaro user ls --json`, so what it shows is what the CLI would print. It has no control: granting and
  revoking stay in the CLI. Against a CLI older than 0.24.0 the view says which version it needs instead
  of asking.
- **Drag a task to another release, behind a preview and a confirmation.** On the Graph screen, dragging
  a task card into a release box (or out of one, to unassign it) now asks first: a sheet shows the task,
  the release it is in, the release it is going to and the exact command, and nothing runs until you
  confirm. One preview authorises one write, and the move can be undone as the inverse move, previewed the
  same way. The move changes the project's roadmap record, so it is the console's third write after
  launching a run and editing a setting, and it is refused after a licence has lapsed like they are. It
  needs **Fugaro 0.24.0** or later, the release that carries `fugaro coordinator roadmap move`.
- **A spend-rate gauge, a one-hour sparkline and two cap bars on Live.** The gauge shows the current spend
  in dollars per hour, and its red zone starts at the rate that would use up the day's remaining headroom
  before the UTC day ends, so the same rate is calm in the morning and alarming at night. A second sparkline
  shows the last hour beside the five-minute one, each labelled with its window. The two bars show spend
  against the day's cap and the runs that are not queued against `max_parallel`; a cap nobody set is drawn
  as unknown rather than as a full bar. They need **Fugaro 0.23.0** or later for `max_parallel`, and a
  gauge or bar the console cannot read says so instead of drawing a shape.
- **The console reads the project key's state.** A reader for `fugaro licence status --json` is in the
  build, so a later release can draw the project's licence beside the key screen. Nothing draws it yet
  (Known limits).
- **No confirmation flag any more.** The CLI dropped `--yes` and `--non-interactive`, and the console no
  longer passes one: a change that needs confirming is confirmed in the console's own sheet, and the
  console never answers a question the CLI no longer asks.
- **Updated components.** Electron 45.3.1, `@sentry/electron` 8.4.0 and `elkjs` 0.12.1.
- **Windows, through WSL, with no download yet.** The console's Windows route runs the Linux CLI inside a
  WSL distribution, and the release tag now starts a job that packs an unsigned Windows installer so a
  broken pack shows at release time. That installer is not attached to this release: **there is no Windows
  download**, and this release carries macOS and Linux only. The Windows unit suite passes again.
- **Download the build you need:** the `.dmg` (macOS, signed and notarised), or the AppImage or the
  `.deb` (Linux). The Linux artifacts are unsigned: an AppImage is not code-signed, there is no Linux
  signing key and none is planned; the SHA-256 in `console-sha256sums.txt` is what proves the bytes, and
  that file is signed with the Sigstore bundle beside it.

### Known limits

- **The Members view and the drag need Fugaro 0.24.0 or later; the gauge and cap bars need 0.23.0.**
  Against an older CLI the Members view says which version it needs, and the Live screen draws the figures
  it can read and marks the rest unavailable.
- **There is no Windows download, and the Windows pack has not been run by hand.** The Windows installer is
  unsigned (there is no Windows signing key and none is planned, so Windows SmartScreen would warn that the
  publisher is unknown), it is built at release time only and attached to nothing, and the owner's by-hand
  dry run of that pack (Check 119) has not been done. The WSL route has not been confirmed on a real
  Windows machine.
- **The project key's state is read but not drawn.** The reader for `fugaro licence status --json` has no
  screen yet, so the Project tab shows nothing new about it.
- **Nothing is refused for a lapsed key yet.** The lapse gate now covers three operations (launching a run,
  editing a setting and moving a task), but this build's licence keyring is still empty until the owner's
  signing keys exist, so no key verifies in a real build and every licensed release stays honour-based.
- The one-hour sparkline is kept only while the console runs and is empty after a restart. When the
  installation turns on the reduced mode, the gauge, its red zone and the runs cap bar are withheld; the
  day's money figures are not.
- The Fugaro Subscription Terms that the licence refers to may not be published yet.
