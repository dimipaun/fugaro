- **The credentials service now says in its own log why it refused a call.** For every refusal it writes one log line naming the failing read (the repository's admissions, the shared policy, the credential bundle or the state) and the class of its error, never a credential, a key or the error's own text, so an operator can tell why a run was refused by reading the service's log instead of guessing from `state_unavailable`.

### For operators

1. Run `fugaro update` once per installation, on your own machine. It redeploys the credentials service behind its own confirmation, which is the whole upgrade; nothing else to run.

### Known limits

- This release adds logging only: it changes no refusal and fixes no state-read failure itself, so a call the service refused on 0.23.0 is refused the same way, with its cause now in the service's log.
