- **Launching a plan task, following up a pull request and listing runs no longer make one Cloud Run request per past run.** On a long history these made thousands of `GetExecution` requests a minute, answered "not found" because Cloud Run had already deleted the executions, and used up the project's per-minute read quota, so launches failed with "Quota exceeded ... Read requests per minute per region" (HTTP 429). The one executions listing now answers for the whole window, and a run it does not hold is shown without an execution.
- **A Cloud Run read refused for quota is retried before the command fails.** Reading jobs and executions now waits 2, 4, 8 and 16 seconds (or the server's `Retry-After`, up to 30 seconds) and tries again, up to five tries, instead of failing the launch in three seconds. Launches and cancels are never retried.

### For operators

1. **Per installation** — run `fugaro update` as usual after `brew upgrade`. Nothing in this release changes an installation; it is a fix to the CLI's own reads.
2. It waits for no run, and says so in one line when runs are running.

### Known limits

- A listing of one named run, and a listing that asks only for live runs, still read the execution they are about, as before.
- Only reads are retried on a quota refusal; a launch that hits one still stops with the refusal.
