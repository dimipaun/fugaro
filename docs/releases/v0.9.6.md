- `fugaro setup` and `fugaro update` replace `fugaro init`: `setup` is the first run, which creates the installation or adopts one that already exists, and `update` re-converges an installation after a CLI upgrade; `fugaro init` now only says which of the two to run.
- `fugaro setup` asks its questions once, in a fixed order, each with a suggestion that Enter takes and a flag that answers it (the GCP project's ID, the region, whether to create the project or adopt an existing one, and the project's name), and a run nobody can ask names every missing flag in one error instead of one at a time.
- A cloud run's review stage now compares the branch with the base the run actually works on instead of with `main`, so a run on a long-lived branch no longer reads the whole branch against `main`, a follow-up uses the pull request's current base, binary files reach the reviewer as one line each, and a very large diff is flagged to the reviewer up front; runs on such branches cost a fraction of what they did.
- `fugaro --version` and `fugaro -v` print the version, like `fugaro version`.
- The `working` and `parallelism` skills warn about the review cost of runs on long-lived branches and teach a daily look at the most expensive runs.

### For operators

1. **Per machine** — upgrade the CLI on every machine that runs Fugaro: `brew upgrade dimipaun/tap/fugaro`.
2. **Per repo checkout** — run `fugaro upgrade`: it pins the plugin to this release, updates it in Claude Code and refreshes the repository's job images. The cheaper review stage reaches your runs only after this refresh, because the runner that does the review is the one in the job image; it builds images, which costs money (`--yes` confirms each build).
3. **Per installation** — wherever a document or a script of yours says `fugaro init`, say `fugaro setup` for a first run and `fugaro update` after an upgrade; `fugaro update --help` lists the flags, and it refuses by name the flags that only `setup` takes. This release changes no cloud resource by itself.

### Known limits

- **The setup wizard is not finished.** `fugaro setup` and `fugaro update` work as described, but the questions that suggest a project ID, pick a region apart from the Firestore location, find your billing accounts and ask for a first repository belong to the next release, so for now the flags the old command took keep their names and still have to be typed.
- **`fugaro init` no longer does anything.** It refuses and names the two commands that replaced it, so a script or a CI job that calls it fails until it is changed.
- **The credentials service, the managed deployer and the Batch backend are not in this release.** They are built on their own branch and ship with the next one.
- **Cloud runs on branches other than `main` keep their old review cost until step 2 above has run** for the repository, because the images still carry the previous runner.
