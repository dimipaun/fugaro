- **Adding a repository to a project is one command now.** `fugaro project repos add <provider/owner/name | owner/name>` enrols it whole: it reads the provider, the default branch, the workflow list and the image entry from the repository's own checkout and its `fugaro.yaml`, and the GitHub App ID and the account from the project's other repositories, prints the whole list of what it will change — this machine's `repos:` entry, its repo-to-image mapping, the published `allow_repos`, the publish, and the repository's job set with its `roles/run.invoker` grant — and asks once before doing it. The confirmation is the project's name typed at your own terminal: no flag stands in for it, so a pipe, `--json` or a coding agent's session is refused rather than answered. Each step is idempotent: a repository already enrolled converges to the same state, and a step with nothing to do says so. A value it cannot read it refuses with the one command that supplies it, never guessing one. The image mapping is merged into the map the published node holds and never written over it, so enrolling one repository cannot take another's mapping away. The older allow-list-only write is still there as `--allow-list-only`, which is also the only way to write `*`, the list's own every-repository entry. Nothing in the command asks a run to finish, and nothing rewrites what a run in flight holds.

### For operators

1. Per installation — the same `fugaro update` is the whole upgrade. Enrolling a repository is a CLI command and a published-node write, so no step runs after a deploy, no record needs a backfill and no repository's own root has to be re-applied.

### Known limits

- **The job step needs a checkout of the repository on the machine you run the command from.** Without one it is left to `fugaro update --repo` in a checkout, and the command says which step it left and where.
- **The first image build stays outside the confirmation, because it is billable.** An enrolment that needs an image the project does not have yet names `fugaro image build` as the way to build it; the confirmation covers only what the enrolment itself writes.
