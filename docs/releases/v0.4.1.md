- New `fugaro init --anchor` writes the `gcp_project:` line into a checkout's `fugaro.yaml` without a full converge. It first checks that every workflow's image was built from a base image new enough to read the line, refuses with one ordered fix per workflow when one was not, and shows the diff before writing. The `init` summary now points at it for checkouts that lack the line.
- `fugaro.yaml`'s JSON schema now accepts `gcp_project:`, so editors and the schema check in CI no longer flag the line.
- The setup skill asks which models to use for the coder and the reviewer as an open question, explains the three roles (coder, reviewer, and the background model Claude Code uses for its own housekeeping), and no longer guesses from the repository's domain.
- The docs now say that the Claude Code plugin may need a manual install (`/plugin marketplace add dimipaun/fugaro`, then `/plugin install fugaro@fugaro`), and give the correct rollout order for the `gcp_project:` line: plain `fugaro init` or `init --anchor` writes it, `init --repo` does not.

### For operators

For a repository whose `fugaro.yaml` still lacks `gcp_project:`, in its checkout and your own terminal: `fugaro init --base <kind>` from outside the checkout (a custom base image in your local config is never replaced: remove its `base_images.<kind>` entry first), `fugaro init --repo` in the checkout, `fugaro image build --repo <owner/name> --workflow <name>`, then `fugaro init --anchor`, and merge that change last. `--anchor` names whichever of these steps is still missing.
