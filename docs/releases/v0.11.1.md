- **A run can ask for a stricter rigor mode.** `fugaro run --mode <mode>` and `--path <glob>` let a launch raise the mode for that run (never lower it below what the layers set); the run record, `fugaro runs ls`, `diagnose` and the pull request body show the mode and that it came from the request.
- **Follow-ups close what they fix.** A follow-up run on a pull request now closes the backlog items an earlier run filed for it once its last senior review ships, instead of leaving them open or filing a duplicate. A rigor area whose `match` is blank is refused with a clear error, and a reviewer score that is not a number names the field in the error.
- **A launch checks the image it will run on.** `fugaro run` and `fugaro validate`, from a checkout, now warn or refuse when the repository sets `rigor:` (or the project layer sets `defaults.rigor`) and the base image is older than 0.11.0, and an explicit `rigor: null` counts as set.
- **The coordinator's GitHub token is narrower.** It now asks for pull-request and metadata read only, is revoked at the end of the command (and of each sweep tick), and `fugaro coordinator status` exits 1 for a missing or malformed App credential and 2 for a host failure.
- **The coordinator's background sweep ships off.** `fugaro update --firebase-project <id> --coordinator` is the only way to create its account, grants, job and schedule; nothing is created without it.

### For operators

1. **Per installation, to use `--mode` or `--path`:** move the job image to 0.11.1 first (`fugaro image refresh`, or `fugaro update --base base`); a launch with either flag onto an older image is refused.
2. **Per installation, to use `rigor:`:** the base image must be 0.11.0 or later; a launch from a checkout now says so before any money is spent.
3. **Optional, owner only:** the coordinator sweep is opt-in. Run `fugaro update --firebase-project <firebase-project-id> --coordinator` at a terminal (it refuses `--yes`, an agent session and a run without a terminal) only after you have read `docs/coordinator/implementation-plan.md` (P5) and are ready to run its proposed live check; there is no opt-out command in this release.

### Known limits

- The coordinator sweep has never run against a live installation; it reads at most 200 pull requests per 15-minute tick over a 30-day window, and bogus pull request numbers can still use some of that budget.
- A launch from outside a checkout (`fugaro run --repo X`) is not checked against the base image for `rigor:`; only `fugaro update --repo` is.
- `--mode hotfix` and any request at or below the layers is accepted and has no effect, with no message yet.
- The thresholds table still acts on nothing: readiness is unchanged in every mode.
