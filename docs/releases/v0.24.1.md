- **`fugaro update` now rebuilds a catalog image that is still built from an older base.** After 0.24.0 an installation could keep job images built from the previous base while the published policy had moved on, and every launch was refused with `update` reporting nothing to do. The images stage now rebuilds each catalog entry whose image predates the base it just pinned, behind its own confirmation, and names a repository whose checkout it could not cover.
- **A launch judges the catalog entry's image, not a per-repository record.** A repository that runs a catalog image was refused as if it ran an old image of its own, even after its catalog entry was rebuilt. The launch now reads the catalog entry's own build record.
- **A report run's reviewer can no longer halt the run at the per-run cap.** The periodic run review (`run-digest`) reserved its reviewer's largest possible output against the cap and could halt a repository whose cap sat below that reserve. The reviewer's output is now bounded so the reservation fits.
- **`fugaro troubleshoot` says why a diagnosis failed.** When the diagnosis agent ends in an error, the error's own text (redacted, one line) now follows the failure instead of a bare "error".
- **The image build's bake note is one line, and silent unless a bake was asked for.** A build that bakes no checkout used to print a long note every time; it now prints one line, and only when you asked for the bake.

### For operators

1. Once per installation, on your own machine, run `fugaro update`. It is the whole upgrade for this release: it rebuilds any catalog image still built from an older base, and it asks before each billable build. Nothing else is required.

### Known limits

- **A repository with no image-map entry still falls back to its own per-repository image.** The catalog image is used only for a repository the project's image map names (or whose workflow names a catalog entry), so a repository that runs neither keeps being judged by its own record.
- **The report reviewer's bound is one constant.** It is sized for the periodic run review and is not yet a setting a project can change.
