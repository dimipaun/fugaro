- **Run reviews you can commit.** `fugaro runs digest` writes a period's report for this repository (day, week, month or year) as a redacted, deterministic Markdown file, run IDs and numbers only, no emails, task text or log excerpts, and flags recurring patterns from the reports already committed; the `working` skill now teaches the daily, weekly, monthly and yearly review around it.
- **Runs record where the work went.** Every stage's record carries its model calls and distinct sub-agents, and the cost report and `fugaro diagnose` show the cache read and write token totals.
- **Rigor modes act, for repositories that set them up.** With a `rigor:` block, the mode bounds the fix rounds (floor two, Pro three, Critical ten), a raised mode decides readiness and says so in the reason, the pull request body names the mode and the findings it tolerated, and the run record keeps them; Hotfix keeps only the security gate. A repository without `rigor:` behaves exactly as before.
- **The coordinator view needs no key.** `fugaro coordinator status --from-store` reads the view the scheduled coordinator job stored, with a runs-only fallback, so it works from a console or any terminal without the GitHub App's key.
- **Context compression is wired in but still off.** `fugaro run --no-compression` and the runner's supervised sidecar are in place for a later release; `agent.compression` is still refused, so no run changes.

### For operators

1. **Per installation:** the runner changes live in the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`) in your own terminal. Nothing is needed per repository, and no config key changed.
2. **Optional:** to use the stored coordinator view, opt in with `fugaro update --firebase-project <id> --coordinator` in your own terminal; the coordinator sweep stays dormant until you do.

### Known limits

- `agent.compression` is refused: the sidecar, the flag and the image gate exist, but nothing starts compression until a later release lifts the key.
- A rigor mode's thresholds only apply in a repository with a `rigor:` block; unconfigured repositories keep today's behaviour, and the round ceiling never lowers below two.
- `fugaro runs digest` reads the run records (90 days) and the committed reports; it does not schedule itself, and committing the report is a normal pull request.
- `coordinator status --from-store` shows the last stored view and labels it as such when the coordinator has been turned off.
