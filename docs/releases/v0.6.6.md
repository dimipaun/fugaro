- Runs that use a non-Anthropic model through OpenRouter (a provider model on `agent.auth: api-key` with the budget gateway on) now get past their first model call: Claude Code sent a `context_management` field and a first-request `safeguards` key that the gateway refuses on provider routes, so the runner now starts Claude Code with `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` and `MAX_THINKING_TOKENS=0` for such stages (and writes them into the managed settings, so a repository's own `.claude/settings.json` cannot undo them). Claude-model stages are unchanged, the gateway's refusals are unchanged, and no `fugaro.yaml` key was added.
- This is the first fix from the first live provider-model run, so a provider-model run can still meet further, undiscovered incompatibilities between Claude Code and OpenRouter's endpoint (for example the `system`-role message Claude Code sends mid-conversation); `docs/multi-model.md` §7 and the live checklist's Check 25 now record what Claude Code was measured to send and what is still open.
- In a run with a provider coder and a Claude reviewer whose background model is not pinned, the background model defaults to the provider's, so the Claude reviewer stage also runs without thinking; pin `agent.models.background` to a Claude model to keep it (documented in `docs/multi-model.md`).
