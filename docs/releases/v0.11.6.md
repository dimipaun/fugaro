- **The base image publishes and signs again.** GitHub's runners moved to a newer Ubuntu, which broke the base-image publish for 0.11.4 and 0.11.5; the workflow now pins its runners, so `fugaro image refresh` and `fugaro update` can resolve this release's signed base image.
- **A run records its model calls and sub-agents per stage.** `result.json` gains the number of model calls and distinct sub-agents each stage made, and the gateway's stage report counts them; nothing acts on the numbers yet.
- **Hotfix keeps only the security gate.** In a repository that set up `rigor:`, a Hotfix run blocks on security findings and unscored ones; data-loss and top-impact findings are filed as advisory.
- **Rigor thresholds decide which findings block.** In a repository that set up `rigor:`, the mode's thresholds now decide which findings keep a run from being ready and which are tolerated and filed; a repository without `rigor:` behaves exactly as before.
- **Releases are less fragile.** The release script rewrites the two released-version doc lines itself and retries transient GitHub errors.

### For operators

1. **Per installation:** the runner changes live in the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`) to get them. Nothing is needed per repository, and no flag or config changed.

### Known limits

- The `agent.compression` key is reserved: it is read and refused until a later release lifts it.
- 0.11.4 and 0.11.5 have no signed base image; upgrade to this release to refresh job images.
