- Teammates need no setup: `fugaro init` publishes an installation's non-secret settings to its runs bucket, and anyone allowed to launch runs can use `fugaro run`, `ls`, `diagnose` and the rest in a checkout whose `fugaro.yaml` names `gcp_project:`, without running `fugaro init` themselves.
- `fugaro init --firebase` now adopts a Firebase project that already holds a previous installation's database, web API key, token signer and minter role, instead of failing with "already exists"; it refuses look-alikes and any foreign member who could mint run tokens, so moving an installation no longer needs hand-edited Terraform state.
- `fugaro init --name` creates a second project when you already have one, `init` says so when an installation-level flag will also onboard the checkout's repository, and it warns when `XDG_CONFIG_HOME` points at a temporary directory.
- The classifier that decides which Terraform plans `init` applies under one confirmation now accepts an import only when that stage's own discovery found it, for the installation, repository and Firebase stages alike.
- The README is rewritten with safety first: the agent never runs on your machine, and it lists plainly what a run can and cannot reach (the network is unrestricted, and on GitHub a run holds the App's private key). From this release, GitHub releases carry these highlights above a changelog without commit hashes, and are normal releases, no longer marked pre-release.

### For operators

1. Upgrade the CLI (`brew upgrade dimipaun/tap/fugaro`), and every teammate's CLI and every CI job that runs `fugaro` against a repository, before any repository merges `gcp_project:`: older versions refuse the key as unknown.
2. In your own terminal, run `fugaro init --publish-config` once per installation to publish its shared settings (it works for installations whose runs bucket has the default name `fugaro-runs-<gcp-project>`, and refuses inside a coding agent's session).
3. Rebuild each repository's job image (`fugaro image build --repo <owner/name> --workflow <name>`) so it carries the new binary.
4. Run `fugaro init --repo` in each checkout: it asks, then adds `gcp_project:` to `fugaro.yaml`. Merge that change last.

Adopting an existing Firebase root works while the installation's GCP project stays the same; moving to a different GCP project is still refused by the existing database check (see "Known limits" in `docs/design/adopt-firebase-root.md`).
