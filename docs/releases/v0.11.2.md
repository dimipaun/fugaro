- **A run can carry the plan task it implements.** `fugaro run --plan-task <plan>/<task>` records the id on the launch record, and `fugaro runs ls --json` and `fugaro watch --json` show it as `plan_task` (a task id is checked for shape at launch and again when read back, and a misshapen one is dropped). It is what the console's coming dependency-graph screen joins runs to plan tasks with.
- **The plan graph document names its release stream.** A graph written by the planning skill can say whether it is CLI, console or mobile (`stream`, schema version 2); version 1 documents still read unchanged. `docs/release-streams.yaml` is the one file that names the three streams, their names and their tag prefixes.
- **A rigor mode that changes nothing says so.** `fugaro run --mode <m>` prints one line when the request is not higher than the mode the layers already resolve (`--mode hotfix` always does), instead of being silently ignored.
- **Smaller fixes.** The coordinator's sweep now removes intent records it cannot decode (a bounded number per tick), and `fugaro backlog` refuses a hand-written item whose `filed-by` is an email address.
- **The setup guide is one short page.** `docs/gcp-setup.md` is now 43 lines: what you need, `fugaro setup`, `fugaro doctor`, and the three common refusals; the managed-label and rollback steps live in `docs/design/managed-projects.md`.

### For operators

1. **Per installation, before anyone uses `--plan-task`:** move the job image to 0.11.2 (`fugaro image refresh`, or `fugaro update --base base`); a launch with the flag onto an older image is refused.
2. **Per installation, before anyone uses `--plan-task`:** update the console to the release that accepts the `plan_task` key (the next console, 0.112.0 "Melon"). A released console (0.110.0 and 0.111.0) refuses a runs list that has a key it does not know, so one launch with `--plan-task` would break its Live and Runs screens for that project. The flag is opt-in, so nothing changes until someone uses it.

### Known limits

- The plan graph screen, the coordinator project view and the rigor mode in the run screens are not in this release; they ship in the console's own release.
- A launch from outside a checkout is still not checked against the base image for `rigor:` (only `fugaro update --repo` is).
- Review findings on the streams file (the next-name rule is not enforced, the mobile stream is pinned at its placeholder version) are tracked for a later release.
