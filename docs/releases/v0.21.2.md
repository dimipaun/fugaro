- **`fugaro update` no longer fails when two run at once.** A second `fugaro update` on the same machine for the same installation now stops at once and says which one is running, instead of both rebuilding the same working directories under each other.
- **The plugin step no longer fails on a version mismatch.** The plugin is now taken from the release tag of the CLI you have installed, not from the repository's default branch, so a freshly installed `fugaro` and its plugin agree.
- **An apply Google had not caught up with is retried.** Google's APIs can lag a moment behind a resource they just created, which made `fugaro update` stop with a "does not exist" error that a second run then cleared. The installation, repository, compute and Firebase steps now wait and run the step again, planning and checking it afresh each time, up to three times.
- **`fugaro update` says once that runs in flight are unaffected.** When runs are running, the update prints one line: it asks no run to finish first and rewrites nothing a run holds, and it names the steps that can still reach one.

### For operators

1. Upgrade the CLI and run `fugaro update`, as for 0.21.1. There is nothing else to run.
