- The base image is no longer copied into your registry: it is served through an Artifact Registry remote repository over ghcr.io, and `fugaro init --base`, `fugaro image refresh` and `fugaro upgrade` pin only an image whose release signature they have verified with `cosign`, which must now be on your `PATH`.
- `fugaro init --repo --retire` retires what a `fugaro.yaml` change removes (a workflow variant, a named Claude account) without a hand-run `terraform state rm`: it shows the plan, asks you to type the project's name twice, and never deletes a secret or a secret version.
- One global per-run cap now bounds every repository that has none of its own (`fugaro budget set --global --per-run P`), and `fugaro budget show` says where each cap comes from; it needs the new rules, deployed with `fugaro init --firebase` (see the operator steps).
- Provider-routed models are priced from a catalog built into the binary (5 models, 91 endpoints, checked 2026-10-14) at the ZDR tier's cheapest end, printed by `fugaro budget prices` and charged at the dearest end once the file is 30 days old, while your own `model_prices` still win; the `require_zdr` and `price_policy` switches are refused in this release and arrive in a later one.
- A secret can be stored once for the whole project with `fugaro secrets set NAME --project-wide`, and `anthropic-api-key` is no longer needed when every model of an enforcing `agent.auth: api-key` repository is served by a provider allow-listed for it.
- Smaller: `result.json` records each stage's model cost, `fugaro budget preview` gives a worst-case ceiling for a batch (and a `typical:` line from your own runs), derived image builds no longer print mise's cache `Permission denied` warning, and the hidden `fugaro ls` pointer is gone (`fugaro runs ls` is unchanged).

### For operators

1. Upgrade the CLI (`brew upgrade dimipaun/tap/fugaro`, or this release's archive with its cosign check), and install `cosign` on your `PATH` (`brew install cosign`, or your distribution's package): `fugaro init --base` and `fugaro image refresh` refuse without it, and `fugaro doctor` names it on every run.
2. If you use the budget backend, deploy its rules **before** any runner image moves: with the new CLI, `fugaro init --firebase <firebase-project-id>` (add `--print-vars` first to see what it writes; `docs/gcp-setup.md`'s "Turning the shared budget on" section has the read-only check of what landed) writes the new per-run-cap rules as the last write of its database step. Also point Application Default Credentials at your installation's project — `gcloud auth application-default set-quota-project <gcp-project>`, with the Cloud Billing API enabled there — because `init` and `doctor` read billing through that quota project and name it when the API is off.
3. Then `fugaro upgrade` in each checkout (its cloud step is `fugaro image refresh`): it now pins the release's base image through the installation's registry remote repository at the digest whose signature it verified, and rebuilds each workflow that is not yet on it. It asks before every billable build, and the base image must move before any repository's image does, which that command keeps in order.
4. For project-wide secrets, in this order: (a) in the installation root, `fugaro init` with no `--repo` plans the project's secret containers as creates only — one per eligible name, no destroys, no replacements and no update to an unrelated resource — and applying it is your step, not something a repository's job can do; (b) then `fugaro secrets set NAME --project-wide` for each name stored once for the project (the value is read from stdin, and it takes no `--repo`; a value stored before (a) is adopted by that apply rather than conflicting); (c) for a repository that adopts a project-wide name while its own copy still has a version, that copy must be disabled before the repository uses the project's — `gcloud secrets versions disable` needs `secretmanager.versions.disable`, which is project-owner-only; (d) then `fugaro init --repo` in its checkout plans replacements of the per-repository IAM addresses, which Terraform's guard refuses until each removal is named with `--allow-delete`.
5. If a plan ever tells you it would retire resources, use a binary built from this release: `fugaro init --repo --plan-only` first (it prints the predicted retirements and, when Terraform's `prevent_destroy` blocks the plan, refuses with "Rerun with --retire"), then `fugaro init --repo --retire`, as `docs/gcp-setup.md`'s "Changing auth, or removing a workflow, secret or provider" section describes. An older binary keeps failing on `prevent_destroy` the way it does today and needs that page's manual `terraform state rm` route.

Two notes. `checkout: clone` is **not** usable in this release: the runner side is in the tree (the blobless `--filter=blob:none` clone, the `mise install` provision stage, the prefetch), but the switch that turns it on has not been flipped, so its job cannot exist at all — `fugaro init --repo` and `fugaro image refresh` refuse to deploy or move a clone workflow's job, and `fugaro run` refuses a clone launch on a job image with no release tag or one older than this release, telling you to use `checkout: baked`. `checkout: baked` workflows are unchanged, and the flip lands after its own live check. And the two items 0.7.0's notes left unverified have since been checked live on the sandbox installation: the runs bucket's launcher grants (Check 32) and the one base image's cold start (Check 41, ~10.5 s median against the old image's ~11.7 s).
