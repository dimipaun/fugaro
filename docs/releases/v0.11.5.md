- **`fugaro plan status` shows every plan next to its runs.** `fugaro plan status --json` joins each plan's task graph to the runs and pull requests behind it, so the console and your own agent can see what is done, running or blocked.
- **The planning skill writes the graph for you.** The `parallelism` skill now saves a plan's dependency graph as a small file next to the plan, tagged with the release stream it belongs to.
- **The review note counts exactly.** The count of commits a pull request carries from other branches is right after a fix round merges a base that moved on, and a head that is not a commit is never treated as already on origin.
- **Releases name themselves.** The release script reads the CLI stream's current version and next name from `docs/release-streams.yaml` and refuses a version that is off the line.

### For operators

1. **Per installation:** the runner changes live in the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`). Nothing is needed per repository, and no flag or config changed.

### Known limits

- The base image for 0.11.4 was never published as a multi-architecture image (a change in GitHub's runners broke the publish step), so local image builds on the 0.11.4 CLI cannot pull it; upgrade to 0.11.5 to get a CLI whose base image matches. The fix to the publish workflow is staged under `docs/pending-workflows/` and still needs copying in by hand.
- Until that workflow fix is copied in, 0.11.5's own signed base image may fail to publish the same way.
