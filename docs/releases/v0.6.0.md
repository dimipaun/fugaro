- `fugaro image refresh --yes` confirms every step unattended, including each billable build, so the cloud step can run from CI or a script instead of needing a real terminal.
- `fugaro upgrade [PATH...]` and the `/fugaro:upgrade` skill move a checkout to this release in one command: it pins the plugin, updates it through the `claude` CLI, and refreshes the job images. `--local` runs only the parts a coding agent's own session can do, `--check` reports drift without changing anything, `--yes` confirms the cloud step unattended, and `--allow-fork` moves a hosted fork's marketplace pin instead of `dimipaun/fugaro`'s.
- A project can now publish a project layer (`fugaro config show`, `layer`, `init` and `publish`) holding project-wide defaults and named workflow profiles, so a repository's `fugaro.yaml` can shrink to a few lines naming the project and, when needed, a profile; `fugaro ls`, `diagnose` and `doctor` all show the layer and profile a run used, and `fugaro run` only embeds a layer on a job image built from this release's base, refusing older ones by name. Until the 0.7.0 bucket IAM hardening ships, `config publish`'s `--executable-changes` gate is a CLI check, not a permission: any launcher can still write the project layer object directly.
- A run whose container was killed or crashed no longer blocks `fugaro run --pr N` for the rest of its branch lock's lifetime: the CLI now clears a lock once the backend reports its execution over, instead of waiting out the full expiry, and `fugaro cancel` says when a lock is still held on an already-finished run.
- `fugaro watch` shows finished runs with a cursor and a run detail view, filters them with `a` (acknowledge) and `x` in the interactive screen or `--all` and `--keep`/`--keep-count` on the command line, and lists the ones ready for review separately; `fugaro logs --url` prints a run's Cloud console link instead of its logs.
- `SECURITY.md` now states Fugaro's trust model and its known limits in one place, including that every launcher still holds broad write access to the runs bucket until the 0.7.0 IAM hardening ships.

### For operators

1. Upgrade the CLI (`brew upgrade dimipaun/tap/fugaro`).
2. Run `fugaro upgrade` in each checkout (it pins the plugin and refreshes the job images). This is required before any run can carry a project layer: a layered `fugaro run` is refused on a job image older than 0.6.0.
3. For projects adopting layered configuration, run `fugaro config publish` from an operator's own terminal; add `--executable-changes` when a profile carries `commands`, `image.apt`, `image.setup` or `image.skip_build_scripts`.
4. Then merge each repository's minimal `fugaro.yaml`. Do this only after every CLI and CI pin that touches the repository is on 0.6.0 or later: the strict parser refuses a file with new keys like `profile:` on an older release.
