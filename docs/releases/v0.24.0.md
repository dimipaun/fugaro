- **Credentials, pools and crafts replace the one fixed setup.** A project names any number of credentials of its own — an OpenRouter key, an Anthropic key or a Claude subscription account, beside the built-in Vertex — groups them into an ordered pool, and gives each of a run's four crafts (the coder, the first-line review, the senior review and the security review) the model it runs and the credential or pool its calls go out on; a craft that sets only one half keeps the other half it inherits.
- **Three commands carry the new vocabulary, each one write or one read.** `fugaro accounts add --type claude-oauth` declares a name as a typed credential beside the account it already wrote, `fugaro accounts pool add|rm|ls` declares, removes and reads the ordered pools, and `fugaro craft ls` shows, per craft, the model and the access it resolves to, the layer each half came from and whether what it names serves anything — offline, and by name, never by value.
- **`fugaro update` reads an existing installation's account keys as the new ones, in place.** The named accounts become typed credentials and the per-stage account keys become the crafts' accesses, on the installation's own config, so the same credential serves every run it served before, with nothing to type and nothing to delete.
- **A pool spreads across its members, and a pool of subscriptions stays inert until the owner says otherwise.** The credentials service serves an OAuth member before an API-key one within a run, and a pool that asks for round-robin starts each run on the next member; two or more Claude subscription credentials in one pool serve nothing until the project's subscription-spread switch is on, and it ships off.
- **A repository selects among the project's credentials and can never add one.** A `fugaro.yaml` names a credential or a pool a craft's calls go out on, and an access naming a credential the project does not hold is refused before the first call; the writes that declare a credential, a pool or a pool's members are the owner's, at their own terminal, and a coding agent's session is refused.

### For operators

1. Run `fugaro update` once per installation, on your own machine. It is the whole upgrade for this release: the migration of `claude_accounts` and the per-stage account keys into credentials and crafts happens in place, on the installation's own config, on the first write this release makes to it — nothing to type, nothing to delete, and no second command.
2. It asks what it has always asked and nothing new: the Terraform confirmations it prints, and the image rebuild it offers. Where `fugaro creds set` refuses a bundle because the deployed credentials service cannot read it, the answer is this same `fugaro update`, which redeploys the service.

### Known limits

- **A craft's model half is written, validated and shown, and it is not yet what a run runs.** `fugaro craft ls` prints the model each craft resolves to, while a run still takes its models from `agent.models` and `agent.levels`; a craft's access is the half a run resolves today.
- **A pool's members are served by the two halves of a run, and one pool cannot cross them.** An OpenRouter or Vertex member is served by the run's own gateway and a Claude OAuth or Anthropic-key member by the credentials service, so a pool that mixes the two can fail over only where the credential is chosen again, which is a stage boundary.
- **A credential whose type authenticates with a key is not declarable by a command yet.** `fugaro accounts add --type` serves `claude-oauth`, the type whose token that command stores; an OpenRouter or Anthropic-key credential is written in the config's own `credentials:` block, and a key that belongs to the project rather than to a credential goes in through `fugaro secrets set` as before.
- **A run is served from the published node's own craft blocks.** The credentials service reads the project's crafts, credentials and pools from the published policy, and `fugaro project policy publish` keeps those members as they are: no command of this release writes them from your config, so what a pool your installation declares changes today is `fugaro craft ls` and the launch, rather than which member serves a call.
- **No live check has been run on any of it.** A pool's failover on a real installation, the spread of round-robin over several runs and the convergence of `fugaro update` on an installation at the previous version are the owner-run checks of this work, and they have not been run.
