- **A run can end ready with a reviewer's smaller findings written down instead of fixed.** A new step between the review and the fix weighs every finding the mode's table would have blocked — against the task the run was given, and in `startup` and `pro` only — and either keeps it for the fixer or records it as a follow-up, so a pull request whose leftovers were all deferred becomes ready with them still open. A repository switches the step off with `agent.triage: false` in its own `fugaro.yaml`, and the owner's switch for the whole project merges tighter-only, so off wins wherever it is written.
- **Some findings are never the step's to move.** A security or data-loss finding, an impact of 5 outside `hotfix`, a finding the reviewer left unscored, and one only the owner can settle always hold the pull request as a draft, and none of them is ever a follow-up. A triage call that fails or cannot be read blocks everything the table blocks, so a broken judge is never a quieter one.
- **The deferrals are in the pull request and in the run's report.** The status section carries a **Deferred (follow-ups)** list — one line per finding the run left open, with the one-line reason it was left, which is the judge's for a deferral, the mode's table's for a finding it tolerates and the review cap's for a leftover — beside the sentence naming the command that files them, and the run's record gains the verdicts of every round and the deferrals that took effect.
- **`fugaro followups RUN` turns the deferrals into tasks once the pull request is merged.** It prints the plan and writes nothing by default, `--launch` files it — one task per group, at most `--max` of them (10 by default), each carrying the parent run and the findings it settles and each marked as debt — and it refuses while the pull request is still open, because the base a follow-up is cut from has to carry the parent's change.
- **`fugaro runs ls --debt` lists the work a review left behind**, and `fugaro runs ls --json` carries `follow_up_of` on each of those runs so a script can walk from a follow-up back to the findings it settles. A run that reaches its review cap no longer drops what the round left either: in `startup` and POC it finalizes ready with the leftovers deferred, and in `pro` it stays a draft and records them.

### For operators

1. Run `fugaro update` once per installation, on your own machine. It is the whole upgrade for this release: the published policy learns the `triage` stage name and `agent.triage` as it normally converges, the job images are rebuilt behind their own confirmation, and nothing here runs after a deploy or needs a backfill.

### Known limits

- **The floor rests on the reviewer's own labels.** What makes a finding undeferrable is the class and the impact the reviewer wrote, so a coder that can steer a reviewer's wording can have a real correctness finding deferred where the mode's table blocks it today. The owner accepted that for this release; a bound on the judge's reach is a later change and no wire format moves for it.
- **Nothing wires the follow-ups to a scheduler.** `fugaro followups` is a command a person runs after the merge: a deferred finding does not queue work by itself, and a pull request waiting on one is not unblocked by anything here.
- **Fugaro still does not merge.** A ready pull request is the end of the run's part of the work, and a merge is a person's — or the coordinator's — step, exactly as it is for a run that ends ready with no deferrals at all.
