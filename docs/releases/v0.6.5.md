- A repository can now use several named Claude accounts instead of one: you define accounts in your own local config (`claude_accounts`, never published), store each token with `fugaro secrets set claude-oauth-token-<name>`, and pick one per run with `fugaro run --token NAME` or per repository with `agent.oauth_token` in `fugaro.yaml`; each account gets its own job, `fugaro ls` and `diagnose` show which account a run used, and `fugaro doctor` checks that every allowed account has a stored token and that a repository's chosen account is allowed.
- When a run fails because its Claude account hit its usage limit, the plugin skills can now relaunch the work on another account the repository is allowed to use (`fugaro accounts ls` lists them; an explicit `--token` on a follow-up now switches the account, one account at most once per task, and the skill stops when all are tried). The exact usage-limit wording Claude Code prints has not been verified, so a missed match simply means no automatic switch.
- `fugaro` now tells you when you are behind the latest release: at most once a day it checks the latest stable GitHub release (in the background, never slowing or failing a command) and prints one line on stderr with the `brew upgrade` command, only on a terminal and never in CI or the runner; `fugaro doctor` always reports it as a warning, and `FUGARO_NO_UPDATE_CHECK=1` or `update_check: false` in your local config turns the nag off.
- Named accounts are opt-in: a repository that configures none behaves exactly as before.

### For operators

1. Upgrade every CLI and CI pin first (`brew upgrade dimipaun/tap/fugaro`), then run `fugaro upgrade` in each checkout to rebuild the job images: a named-account run is refused on a job image built before 0.6.5 (its runner would reject the new `oauth_token` field), and an older CLI refuses the new `agent.oauth_token` key in `fugaro.yaml`.
2. The secret-name prefix `claude-oauth-token-` is now reserved: a workflow `secrets:` entry in `fugaro.yaml` that uses it (other than through `claude_accounts`) is refused by this release (rename the secret and run `fugaro secrets set` again).
3. To adopt named accounts, add them to your local config's `claude_accounts` (with the repositories each may serve), store each token with `fugaro secrets set claude-oauth-token-<name>` in your own terminal, then run `fugaro init` per repository so each allowed account gets its own job; removing an account later plans deletes that need `--allow-delete` / `--allow-job-delete`.
4. Not yet verified against live infrastructure: minting a second account's token with `claude setup-token` and how Claude Code reports an expired or revoked token (`docs/gcp-live-checklist.md`, checks 34 and 36).
