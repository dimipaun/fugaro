- **`fugaro setup` asks everything first, then applies.** The wizard collects every answer before it changes anything: the project's name, a GCP project id that defaults to `fugaro-<name>`, the region, and a pick from the billing accounts you can use (listed at a terminal only), and it asks whether to onboard the checkout's repository.
- **`fugaro update` brings an existing installation up to date**, with its own stages, its refusals and a non-interactive contract; `--yes` covers every ordinary step, and creating a project, linking billing and typing a secret still need you at a terminal.
- **`fugaro init` is gone.** It prints which of the two commands replaces it; the README, the setup skill, the website and every message now say `fugaro setup` and `fugaro update`.
- **A missing Cloud Billing API is explained, not cryptic.** When the quota project has the API disabled, setup says so, names the project, and offers to enable it behind a typed confirmation that `--yes` never covers.
- **Several accounts or models can share a run's work through the credentials service**, an opt-in service that keeps the model credentials out of the job (the GitHub App key too, once it is wired): `fugaro creds set` and `fugaro creds ls` manage its one bundle, `agent.auth: cascade` selects it, and a run records which credential answered and what was subscription work rather than billed.
- **Running on Cloud Batch got safer to read:** a Spot-preempted run is shown as failed, the reaper has its own command, and `validate` and `doctor` check a Batch setup.

### For operators

1. **Per machine** — upgrade the CLI on every machine that runs Fugaro: `brew upgrade dimipaun/tap/fugaro`.
2. **Per repo checkout** — run `fugaro upgrade` (pins the plugin to this release, updates it in Claude Code and refreshes the repository's job images). Replace any script or CI step that runs `fugaro init` with `fugaro setup` (first run) or `fugaro update` (every later one).
3. **Per installation** — run `fugaro update` once. The credentials service is **off** and stays off until you turn it on; nothing changes in your cloud project unless you do.

### Known limits

- **The credentials service ships dormant and is not wired end to end.** No job is given the service's address yet, the service's account has no realtime-database role yet, and opting in with `--provision-credentials` removes a per-repository job's own model credentials with nothing replacing them: do not opt in until 0.10.1, which wires it. `agent.auth: cascade` also needs a published `budget.allowed_models`.
- **The service's audit trail is partial:** identity and pairing refusals before a call is admitted are not audited, and the audit line is written before the answer streams.
- **Some run-dollar readers still split on the model basis** (`runs stats`, the budget preview, the halt text) rather than on the notional part, which only matters once the service carries subscription work.
- **The base image's tool downloads do not retry**, so a flaky network can fail an image build; rerun it.
- **Cloud Batch stays opt-in and owner-run** (`--provision-batch`), and its owner-run live checks have not been run.
- **The live checks written for this release have not been run:** 27, 68, 91, 92, 94, 95, 96, 99 and 111 are owner-run and follow the release; what they find is fixed in 0.10.1.
