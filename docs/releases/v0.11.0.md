- **Rigor modes.** A repository or project can set how careful its runs are (POC, Startup, Pro, Critical, Hotfix) with `rigor.default` and named `rigor.areas` in `fugaro.yaml`, or `defaults.rigor` in the project layer; the narrowest layer wins. The mode is read from the repository's default branch, never from the branch under review, and `fugaro runs ls`, `fugaro diagnose` and `result.json` show it.
- **Every repository now runs at Pro by default.** A run's per-run cap is 85% of the deployed cap (Startup 70%, POC 55%, Hotfix 40%, Critical 100%); a cap you set in the project policy, project layer, repository or branch is used exactly. Add `rigor: {default: critical}` to keep today's full cap.
- **Reviewers score findings, and runs can file what they leave open.** Each finding now carries likelihood, impact and fix cost (1 to 5) and a class. A repository that opts in with a `rigor:` block gets its unshipped last review round filed as one Markdown item under `docs/backlog/`, committed in the run's own pull request (new commands `fugaro backlog add`, `index` and `list`); repositories that have not opted in file nothing.
- **A first coordinator view.** `fugaro coordinator status` joins each repository's pull requests with its run records and shows work in flight, its target release, and pairs of work that touch the same file or service; `fugaro coordinator report` records an intent for a branch, a release, files or services. It is advisory and never blocks anything, and GitHub is read with a read-only installation token minted per repository.
- **`fugaro watch` is tighter.** The VERIFY and MODELS columns moved into a run's details, and finished runs show the same short id as the rest.
- **The licensing is stated in one place.** `LICENSING.md` says the core stays MIT and that `ee/` is reserved for later organisation features with no licence file yet; the CLI archive now ships its third-party notices.

### For operators

1. **Per installation:** after upgrading the CLI, run `fugaro update --firebase-project <firebase-project-id>` from the 0.11.0 binary. It deploys rules generation 4, which adds a read grant on `coordinator/` for signed-in readers. Until you do, `fugaro doctor` warns `policy-rules-skew` (and `doctor --strict` exits non-zero); runs, a published policy and the mobile app are unaffected either way.
2. **Per installation, before any repository or the project layer uses `rigor:`:** move the base image to 0.11.0 (`fugaro image refresh`), then run `fugaro update --repo .` in each repository. A runner older than 0.11.0 refuses a `rigor:` block, so `fugaro update --repo` refuses to deploy such a repository onto an older base image and `fugaro run` refuses to launch one: nothing is paid for before the runner reads the file. One `defaults.rigor` line in the project layer breaks every repository of the project that is still on an older image.
3. **Per repository:** every repository now resolves Pro, so its per-run cap is 85% of the deployed cap. Check that your caps still fit, or pin `rigor: {default: critical}`.
4. **Console:** upgrade the console to 0.111.0 together with the CLI; an older console shows its skew state for run lists written by 0.11.0 runners.
5. Do not run `fugaro update --firebase-project` from an older CLI after generation 4 is deployed (it is refused; the fix is `fugaro upgrade`), and do not set `coordinator_account` or create a `fugaro-coordinator` account by hand.

### Known limits

- **The thresholds table is not wired yet.** Readiness is unchanged in every mode: all findings still block, and a POC or Hotfix run is reviewed like Critical. The scores are recorded only.
- `fugaro run --mode` and `--path`, sensitive-path floors and the mode in `fugaro watch` are not built.
- Items filed for a draft pull request are not closed when a follow-up fixes them, and repeated follow-ups can file duplicates; items carry the finding count, not the finding text.
- **The coordinator is a first cut.** The aggregation job and the later parts are not built, nothing reads intent records yet, the writer account's grant is off, only budget admins can record an intent, the coordinator's GitHub token is not revoked after use and asks for contents and issues read (wider than the view uses), and `status` lists only the pull requests that runs name.
- `ee/` is reserved and empty: no enterprise feature and no enterprise licence text ship in this release.
