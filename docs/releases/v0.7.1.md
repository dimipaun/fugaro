- New `fugaro budget preview --recipe NAME --runs N [--repo R] [--json]` answers "could this batch blow my budget?" before you launch it: a read-only, rough worst-case ceiling for the N runs (N × the smaller of the per-run cap and the recipe's stage bound × `agent.max_budget_usd`), set against the repository's headroom under the caps today, with a warning when the ceiling could exceed it and one verdict line at the end. It is a ceiling, not a forecast, and an unset cap is reported as unbounded rather than guessed at.
- `result.json` now records the model cost of every stage (`model_usd`, and the stage's `model`), so a run's bill can be read stage by stage instead of as one figure; the per-stage figures add up to the run's `cost.model_usd` except for spend that settles after its stage ended, which appears as `model_by.unattributed`. Old records still parse.
- `fugaro ls` is gone for good: after 0.7.0 kept it as a hidden pointer to `fugaro runs ls`, it is now an ordinary unknown command (exit 2). `fugaro runs ls` is unchanged.
- The base image creates `~/.cache/mise` as the `fugaro` user, so the mise cache a derived image's build mounts there stays writable by the user a run runs as: runs stop printing mise's `failed to write cache file … Permission denied` warning on every command that reads its cache. The image's runtime selftest now checks that directory exists, is a real directory owned by `fugaro` and is writable.
- Fugaro's own repository no longer names a base: its `go` workflow runs on the one Fugaro base image, with its runtimes from `mise.toml` instead, and its cloud loop on `agent.auth: api-key` with a DeepSeek coder and reviewer through OpenRouter; `docs/dogfooding.md` is the worked example of that setup, including the two secrets it needs.
- One lesson from dogfooding is worth copying if you run a provider model: Claude Code applies `--max-budget-usd` against its own cost estimate, and for a non-Anthropic model that estimate is Sonnet-like, about 25 times what the gateway charges for DeepSeek, so a per-stage `agent.max_budget_usd` that looks enormous in real dollars still ended two runs at $0.13 and $0.22 of actual spend. The gateway's per-run and daily caps remain the hard stop.

### For operators

1. Upgrade the CLI (`brew upgrade dimipaun/tap/fugaro`, the release archive, or `go install github.com/dimipaun/fugaro/cmd/fugaro@v0.7.1`).
2. Then run `fugaro upgrade` in each checkout (its cloud step is `fugaro image refresh`): the mise-cache fix and the per-stage cost in `result.json` both live in the job image, so a run only gets them from an image rebuilt from this release's base image. It asks before every billable build, writes no `fugaro.yaml`, and leaves a custom or development base image alone.
3. `fugaro doctor` should show its usual clean lines. This release adds, removes and changes no `fugaro.yaml` key and plans no cloud resource, so there is no new rollout order to sequence; `gcp_project:` and the 0.7.0 bucket hardening keep the orders their own releases documented.

Two notes. `checkout: clone` is **not** in this release, even though 0.7.0's notes said it was refused "until 0.7.1": the runner side (generic-tool plan Task 17, PR #342) and the switch that enables it (Task 18) are still unreleased, so a workflow that sets it stays refused at launch and `checkout: baked` workflows are unchanged. And the two items 0.7.0's notes left unverified have since been checked live on the sandbox installation: the runs bucket's launcher grants (Check 32) and the one base image's cold start (Check 41, ~10.5 s median against the old image's ~11.7 s).
