- **A run's review stays on the run's own work.** When a run starts on a long-lived branch but was launched without `--ref` (so the runner believed its base was the default branch), every review round used to diff the whole integration branch, which cost hundreds of model calls and hid the run's own change. The runner now takes the range from the run's own commits, read from what origin really holds (`git ls-remote`), so the review prompt, the review input, the size note and the workflow-file guard all use one range. If origin cannot be read, nothing is narrowed.
- **`fugaro run` takes its base from the branch you launch it from.** With no `--ref`, a checkout on a branch that origin also has runs from that branch, and says so on stderr (`using --ref X: this checkout is on X; pass --ref main to run from the default branch`); an explicit `--ref` always wins. The launch line now reads `branch fugaro/<id> cut from <ref>` and `--json` carries `ref`. A task that cuts its own branch (`git checkout -b X origin/Y` where Y is not the run's ref) gets a warning.

### For operators

1. **Per installation:** the review-range fix lives in the runner inside the job image: refresh it with `fugaro image refresh` (or `fugaro update --base base`) to get it. The launcher half needs only the new CLI (`brew upgrade dimipaun/tap/fugaro`).
2. Behaviour change to know about: launching from a pushed feature branch without `--ref` now runs from that branch instead of the default branch; pass `--ref main` for the old behaviour.

### Known limits

- Narrowing needs the integration branch's commits in the job's checkout (a fetch of the branch is enough); "narrower" is judged by commit count, not by files or lines.
- A first-run agent can still push its own commits to another branch and have them left out of its review; GitHub still refuses workflow-file changes without the workflows permission.
- The run record's `changed_files` and the rigor path matching still list the integration branch's files; checkpoint pushes during implementation use the earlier bounds.
- The guard asks origin once per check, so it scales with the number of branches; batching it is planned.
