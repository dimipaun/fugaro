- `fugaro image refresh` moves a repository onto this release's base image in one command, run in the repository's checkout in your own terminal. It copies the base image, points the daily image check job at it, and rebuilds the workflow images that need it, with a confirmation for each cloud change (each build is billable and typed) and no Terraform. It stops with a one-line fix on a development or hand-pushed base image, and it ends by naming `fugaro init --anchor` when `fugaro.yaml` still lacks the `gcp_project:` line. The `init --anchor` and recipe image refusals now name it instead of a four-step sequence.
- Work is no longer lost when a run's container dies. While a run works, new commits are pushed to its own branch within about a minute (fast-forward only, never forced), a draft pull request opens at the first push marked "work in progress, not verified", and every stage boundary pushes at once. Readiness is unchanged: a pull request is ready only with a passing test on the final commit and a `ship` review. Only commits are saved, not uncommitted changes.
- Checkpoints go through the same guards as the final push: a commit touching `.github/workflows` and any commit containing a known secret value stop checkpoints for that run, and a failed checkpoint is a warning, never a run failure. Set `git.pr.checkpoints: false` to opt out; every push to a draft pull request runs your repository's CI (at most 60 pushes an hour).
- The agent is now told to commit early and never to end its turn waiting for background work, because a headless run ends the moment the agent stops and loses whatever was still running.
- `fugaro watch` shows runs that have launched but not started as `queued` rows with their age, and warns when one has not started after 10 minutes. It reads the runs bucket, so it needs a launcher or operator role: a plain Firebase Viewer sees a note that queued runs are unavailable.
- A rare race that could put a budget lease on the wrong day around midnight is fixed: the database clock now follows the newest request, not the last response to arrive.

### For operators

1. Upgrade the CLI (`brew upgrade dimipaun/tap/fugaro`), and every CI job and teammate's CLI that runs `fugaro` against a repository, before any repository sets `git.pr.checkpoints:` in `fugaro.yaml`: older versions refuse the key as unknown. Leaving it unset keeps checkpoints on and breaks nothing.
2. Run `fugaro image refresh` in each repository's checkout, in your own terminal. It is interactive by design: it needs a real terminal, has no `--yes`, `--json` or `--plan-only`, and cannot run in CI. Checkpoint pushes only apply to runs whose job image was built from a 0.5.1 base, so refresh each repository once to get them.
3. **Not yet verified against the real Cloud Run API:** the direct update of the check job (the raw job is read, only the image and the `base_images` in its spec are changed, and it is written back with its etag). Nothing has exercised it outside tests with a fake. Run the sandbox-only live check, Check 30 in `docs/gcp-live-checklist.md`, on a sandbox repository before relying on it. The command's own prompt says the same.
4. On hosts without draft pull requests, the pull request opened at the first push is an ordinary one and may request code-owner reviewers on unverified work: set `git.pr.early_draft: false` there (branch checkpoints still happen). If your CI is expensive, set `git.pr.checkpoints: false`.
