- **A run that reviews on your Claude subscription now starts on the job that holds its token.** A project with a provider-served coder and a Claude account for the review stages launched on a job that mounted no token, so the review stopped with "needs CLAUDE_CODE_OAUTH_TOKEN". The launch now picks the account the review stages name, and follow-ups and retries are held to the same rule.
- **A person at a terminal can change settings and publish layers on a managed project without the coding agent's restrictions.** `fugaro settings set`, including the review floors, and `fugaro config publish` bind a coding agent's session and leave a person alone; settings also finds the right project when a checkout matches several.
- **A coding agent's session can no longer lower the review floors through `fugaro config publish`.** The publish door now refuses lowering review rounds, turning a review level off, or moving the first-line review off an explicit `on`, as the settings door already did.
- **A plain `fugaro update` on a managed project retires the project's own derived resources itself.** Service accounts, IAM members and Cloud Run jobs (even deletion-protected ones) that a removed workflow leaves behind go without a typed confirmation or a second command; buckets, secret containers, registries and databases are never touched, and a coding agent's session is still refused.
- **A policy write no longer stops on runs in flight on a managed project.** The update notes how many runs are in flight and writes; an unmanaged project keeps the refusal.
- **The dogfood review reads the pull request head through the credentials service's read mint**, and its review stage runs on an Opus model.

### For operators

1. Upgrade the CLI and run `fugaro update` in each checkout, as for 0.20.2. To use the Claude subscription review, name the account with `fugaro settings set stages.review.claude_account <name>` first; `fugaro update` publishes it.

### Known limits

- Everything in v0.20.0's known limits still stands: the cloud review is built and not admitted, repository-image removal and G3 to G13 are not in, and the credentials service is still opt-in.
- A plan that retires resources in the same update as other changes asks the typed confirmation if the other changes are outside the review's cover.
- Shared project jobs still do not carry a mixed run's account: the fix covers the per-repository jobs.
- `fugaro config publish` does not yet hold a coding agent's session to the settings door's key list (recipe, reviewer model, level models).
