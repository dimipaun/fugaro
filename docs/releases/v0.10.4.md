- **`fugaro setup` creates a fresh project, and only that.** The wizard no longer offers to adopt an existing GCP or Firebase project, and the flags that existed for adoption are gone. A project that setup did not create is refused with a plain line saying so; an installation that already exists is updated with `fugaro update`.
- **Missing billing pauses setup instead of failing it.** When the billing account cannot be linked, the project stage reads "done, billing pending", the stages that need billing read "waiting for billing", your local configuration is written, and setup prints one block to forward to whoever administers billing, with the real project id and the exact rerun command. Running `fugaro setup` again once billing is linked completes the installation.
- **A project setup creates is managed by default.** It carries a creation label, so a rerun after a billing pause resumes it and marks it managed once you type its project id at your own terminal; never under `--yes`, `--non-interactive`, `--json` or in an agent session.
- **Plainer messages.** `--firebase-project` now says its value is the installation's own project id, and the warnings about an unmarked project and the quota project say what to do next.

### For operators

1. **Per machine** — upgrade the CLI on every machine that runs Fugaro: `brew upgrade dimipaun/tap/fugaro`.
2. Nothing in your cloud project changes by upgrading alone, and no checkout needs `fugaro upgrade` for this release.
3. **Per installation** — to mark a project you own as managed without rerunning setup, use `fugaro managed flag <project-id>` in your own terminal.

### Known limits

- **Project creation under an organization policy has not been run against a real organization.** The refusal and billing-pause paths are tested against fake cloud responses.
- **`--create-project` still exists.** It makes setup create the project named by `--gcp-project`; making its sibling options work on their own and removing the switch is planned.
- **A plain rerun of a finished installation does not mark a project that has no marker.** Use `fugaro managed flag`.
