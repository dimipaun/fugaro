- **A switched repository's secrets no longer sit in the container the agent runs in.** On a repository whose credentials-service switch is on, the Anthropic key and the account's token, the workflows' own `secrets:` and the build's git credential and build secrets are fetched from the installation's credentials service instead of being mounted, and a repository you do not switch keeps every mount, before and after this release.
- **`fugaro runs ls` answers the two questions you ask most without reading your whole history.** `--pr N` and `--state running` read a small index of a pull request's runs and the executions the cloud is still running, where before they read every run of the window — 23 s for one row and 20 s for none on a project with a history; a pull request with no index entry yet is read the old way, with one line on stderr saying so, the rows and `--json` are unchanged, and `--json --stream` prints the rows one per line followed by a line that ends the feed.
- **`fugaro tell RUN "text"` sends a message to a run that is going.** The message reaches the next coder stage and nothing else, `--now` stops the coder stage where it stands and resumes it with the message, `--wrap-up` asks the run to commit what it has and stop, and the run's report, `fugaro runs show` and `fugaro diagnose` list every message with what became of it.
- **A review is now checked against the task the pull request was written for.** The in-run reviews read the task, a finding that the change leaves part of it unmet or differs from it blocks at every level but hotfix, `fugaro review --code-only` keeps the old code-only review, `--spec FILE` reviews a pull request no run produced against the task in that file, and the key `agent.review_against_task` (a repository's, and the project's published policy) switches it.
- **`fugaro troubleshoot` diagnoses a failure on a machine with no Claude login.** The command's third tier sends the same redacted evidence the local diagnosis would have sent to your own Cloud project, where one bounded diagnosis job answers; the rules tier and the local login still answer first, a cloud answer prints what it cost, and the job never runs on the person's own credential — the model call is signed for the project by its credentials service and the login never enters the container.
- **Smaller changes in how you configure and launch.** A rigor area rule is written with `level:` (the old `mode:` still loads), a ceiling set with `fugaro settings set` lands in the project layer by default and a refused write names the command that does write it, `fugaro models add` and `fugaro image add` take `--dry-run` and print what they would change, `fugaro run --commit-reports` hands the stored periodic reports in for the run to commit into the designated repository, and `fugaro run --retry` on a run that already started refuses instead of exiting 0.
- **A shared project job gives up its model credentials where the credentials service serves its profile.** The profile's shared jobs mount no Claude credential any more, neither the account token nor the Anthropic key, while a provider's key stays mounted until the keys-through-service plan's own flip, and a profile no repository of yours is switched for keeps every mount and every accessor.
- **Every setting names the command that owns it, and a write with no `--layer` lands where the key's merge rule says.** `fugaro settings` prints that owner for every key, a `settings set` with no `--layer` writes a ceiling into the project layer and every other key into its narrowest layer, and a repository key written at the project layer takes the short spelling (`agent.max_budget_usd --layer project` is `layer.defaults.agent.max_budget_usd`).

### For operators

1. **Per installation** — run `fugaro update` once, at your own terminal; it is the whole upgrade, and it asks nothing more than before except the confirmation it always asks ahead of rebuilding the job images. Upgrading is `fugaro update`, and it waits for no run: it says in one line when runs are going, and a run that bootstrapped under the release behind keeps its records, its ledger and its counters.
2. What `fugaro update` does in this release, beyond the usual: it reads your local config first and names each catalog entry the release would refuse, applying the fix itself where it loses nothing (a pinned branch whose file the default branch also has); it deploys Firebase rules generation 9, which gives a paired device a read of a run's outcome and a run a read of its own credential route; it deploys the credentials service if that is not deployed yet and writes each repository's workflow-secrets record; and it plans one new lifecycle rule on the runs bucket, deleting a message object under `tokens/` whose name ends `.msg.json` 7 days after it is written, where before this release it was kept for ever.
3. `fugaro update` writes the pull-request index for the last 90 days of runs: one entry per run whose own records say it opened, followed or reviewed a pull request, under the run's own prefix, created only where one is missing, so a second update writes nothing. It waits for no run — the entries go beside what a run in flight holds and nothing it holds is rewritten — and until it has run, `--pr N` reads a pull request the old way.
4. **Per repo checkout** — run `fugaro update --repo <owner/name>` from the checkout of each repository whose secrets you want brokered. That run is what applies the flips: the repository's job account gives up its accessors on the Anthropic key, the account's token and the workflows' own secrets, its build account gives up its accessor on the git credential and the build secrets, and the run, the build and the daily image check ask the installation's credentials service instead. **A repository you do not run it in keeps every accessor and every mount, before and after this update**, and so does a repository whose root is re-applied with the credentials-service switch off; a run that started before the re-apply keeps the mounts it bootstrapped with. A switched repository needs a job image whose runner reads the service, and a launch on an older one is refused before any execution exists, naming the release and `fugaro update`. A launch that carries `--commit-reports`, `--spec` or a `level:` spelling needs the 0.27.0 base image and is refused the same way; the images stage of `fugaro update` moves it, behind its own confirmation.
5. A budget mode `off` is refused at publish while a switched repository holds an `api-key` or `oauth` auth, because that repository's jobs would hold no mount: lower the mode and re-apply the root first.

6. **Per installation, the shared-job half** — the same `fugaro update` applies the shared-job flip (B5.7), and it is done when it returns: a profile the credentials service serves has no Claude credential on any of its shared jobs afterwards — neither the account's token nor the Anthropic key is mounted, and neither is readable by their accounts — while a profile no repository of yours is switched for keeps every mount and every accessor, before and after. A provider's key is not taken: nothing serves one until the keys-through-service plan's own flip, so every shared job keeps the provider keys it mounts. The drop is the **profile's** and not one repository's: a shared job is one job per profile, provider and Claude account, so one repository of that profile switched takes the mounts off every repository sharing the job, and a repository you have not switched shares the switch of the ones you have. The address its runs are served with follows the same answer, and that is the other half of this flip: a launch on a shared job is handed the service's address wherever the profile is one the service serves — whatever a repository's own record says, and whether or not the launch could read its `fugaro.yaml` (a launch from outside a checkout, which is every desktop-console launch, reads none) — so a repository of a switched profile makes its model calls at the service instead of stopping at a mount the profile's switch has already taken away. Step 2's `fugaro update --repo` in one repository's checkout is what puts the profile on the service; a profile no repository of yours has switched keeps its mounts, and its runs read their own credential as before.

7. **Per installation, for the settings this release gives commands** — run `fugaro update`; the first update publishes the pools, crafts and credentials your local config states to the policy node, additively, and deletes nothing; it asks nothing.

8. **While runs are running** — the update says so in one line: the count, and that it waits for none of them and changes nothing they hold.

### Known limits

- On a switched repository the launch is judged on the workflow as the document declares it, so a workflow that declares a repository-level secret your project's published policy does not admit — a name the flip never mounts and the service never has a value for — still needs the 0.26.0 base image or newer, even though nothing was taken from that job.
- Workflow secrets are fetched by a run of the repository's own job. A review run mounts no secret of its own and is untouched by the flip, and a run on a shared project job reads the secrets its profile mounts: the Claude credentials are no longer among them once the shared-job flip has run, and the GitHub App's key and the profile's provider keys stay.
- A cloud diagnosis runs inside a repository checkout, scoped to that repository; run from outside one, the command prints the evidence with that reason rather than a diagnosis.
- A message sent with `fugaro tell` is read at a coder stage's boundary or, with `--now`, at the agent's next quiet point; a review-only job, a merge judge and a rebase run take none, and a message no stage read is recorded as undelivered.
- A pull request no run produced has no task to be judged against until you hand one in with `--spec`.
- The workspace service, the paired-device identity service, the orchestrator's issue sync and the model-crafts activation are in the tree but are not switched on by this release, and the owner-run live checks of this release have not been run.
