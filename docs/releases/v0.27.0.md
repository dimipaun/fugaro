- **`fugaro troubleshoot` diagnoses a failure on a machine with no Claude login.** The command's fourth tier sends the same redacted evidence the local diagnosis would have sent — the log, `fugaro doctor`'s output, the effective configuration with secrets removed and a reference to the Fugaro source at the version that failed — to your own Cloud project, where one bounded diagnosis job reads it and answers; the answer is checked against the CLI's own command tree exactly as a local one is, so a command it prints is shown as runnable or as unchecked either way, and the run it came from is printed beside it.
- **The tier that spends is asked for last, and it prints what it cost.** The rules tier and the local login still answer first, so a broken cloud is explained rather than met with a second failure, and the pre-flight asks the launch path's own gates before anything is uploaded: a job image older than 0.26.0, a credentials service that is off and a budget that is spent each end with the reason and the command that fixes them. A cloud answer prints the figure the diagnosis run's record holds.
- **A cloud diagnosis never runs on the person's own credential.** The job is the review-only variant `fugaro review --pr N` already uses, which mounts no credential of its own: the model call is signed for the project by its credentials service, the person's login never enters the container, and no installation secret is read into the CLI.
- **Upgrading is `fugaro update`, as it always is.** The cloud tier starts the job image this release builds, and until that has run the command's own pre-flight refuses a diagnosis against the older image, naming the release and the fix.

### Known limits

- A cloud diagnosis runs inside a repository checkout, scoped to that repository; run from outside one, the command prints the evidence with that reason rather than a diagnosis.
