- **A run's reviews now go through levels you configure, and the hardest one runs.** `fugaro run --review-levels <file|->` passes a levels block at launch, and `agent.levels` in `fugaro.yaml`, in the project layer or in the task itself gives each of `l1`, `l2` and `l3` its own `model`, `effort`, `focus` or `none`, with `agent.adversarial_rounds` setting level 3's round count. The levels a run gets are resolved once — the rigor mode's own row, the merged configuration, the task's block and the owner's floor last — a floor that requires a level a layer wrote `none` is refused rather than overridden, level 2 may not run level 1's model, and a pair left unset warns; `fugaro validate` and every launch apply the same resolver. The runner routes each level's own model, gives a level's effort to a Claude stage only (a provider-served level carrying an effort is refused before anything is written), and runs level 3 as a real stage, bouncing a round that does not ship back through the cheap first-line loop. It all needs an image built from this release: `reviewLevelsSince` and `adversarialSince` are both 0.16.0, and a launch or a configuration that asks for a level on an older image is refused by name.
- **The independent review's identity and its signed verdict are in place, and this release launches none of it.** The credentials service gains a review caller class with its own read-only token set and its repository pairing, a sign route that marks one signature per review run, a verify route with a verifier caller class, a review-signing key with a current and a `-previous` rotation window (written by `fugaro creds set --generate`), and a `verifier_accounts` policy key that is empty by default and refuses every caller, carried by `FUGARO_VERIFIER_ACCOUNTS`; the runner writes a versioned verdict artifact (`review.json`, its `.sig` and `review.md`) from a read-only review stage that loads no configuration from the head it reviews and mutation-checks the head in its own worktree without pushing. This is groundwork: nothing in this release starts a cloud review job, and the cloud senior reviewer ships later.
- **`fugaro accounts add` sets a Claude account up end to end.** It writes the account's repositories and its profile into your local configuration, then converges the installation — stores the token, clears a 401 or usage-limit mark, runs the publish and deploy stages and reads the result back — so nothing is left to run by hand; `--claude` runs Anthropic's own login on your terminal first and then asks for the token in one hidden paste, and both halves refuse inside a coding agent's session, `--yes` included.
- **`fugaro models` and `fugaro settings` change things, not only show them.** `fugaro models ls`, `search` (with `--json`) and `add`, `rm` and `use` read the price catalog and set a repository's coder, reviewer or background model; `fugaro settings get`, `set` and `unset` write a setting, aim at an installation with `--project` or `--config`, and ask for the project's name to be typed before a widening — a budget, governance or agent ceiling going up, an add, or an unset — where `--yes` answers that typed form outside a coding agent's session and never inside one.
- **The coordinator's CLI reads what the fleet holds.** `fugaro runs ls --limit` and `--after` page a listing while the totals stay the whole window's, `fugaro coordinator show` prints one pull request as the host has it, and `fugaro coordinator intents` prints what each repository has declared; the coordinator's two writers and a launch's declaration now ask the one budget-database ownership check every other writer asks.
- **Smaller changes.** Each review records the model, effort and head it ran with, shown as recorded in the status line and in `fugaro diagnose` and never taken as an input to a decision; `fugaro runs ls` and `fugaro report` read a run's objects from a local cache and re-read only what changed, and `fugaro runs summary` counts a period's runs and spend from the budget database without reading a run object; and a policy publish that loosens the published node asks for the typed project name.

### For operators

1. Upgrade the CLI, then run `fugaro update` in each checkout. It re-pins the plugin and the job images and, for an installation that opted into the credentials service, redeploys that service on this release's image; its plan is shown and confirmed as every other apply is, and an installation that never opted in plans as it always did.
2. Ask for `--review-levels`, or set `agent.levels`, only after that update: a job image built before this release refuses the levels and names `fugaro image refresh`, which the update has already done, so nothing else is asked of you.
3. Nothing starts the cloud senior reviewer in this release, so there is nothing to deploy for it: the credentials service's review identity and the signed verdict artifact are groundwork.

### Known limits

- The independent cloud review is groundwork: nothing launches a review job in the cloud, no command and no recipe starts one, and the review job's own deployment and its launcher come in a later release.
- `verifier_accounts` is empty by default, and the verify route refuses every caller until an owner lists the accounts that may verify a review's signature.
- The Bitbucket read consumer is a bundle entry the credentials service can hold, and nothing reads it yet.
- The project image catalog is a design only; the build that consumes it comes in 0.17.0.
- A level whose model is served by a provider route may not carry an effort: it is refused before launch, because a provider stage runs with thinking off.
