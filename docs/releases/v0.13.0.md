- **Licensing updates.** Governance, `fugaro report` and the coordinator now ship as business-licensed parts of the one released binary, under the Subscription terms, while the core, `fugaro runs digest` and `fugaro diagnose` stay MIT.
- **A repository can bound its own runs.** A `governance:` block in `fugaro.yaml` sets a stage timeout, per-stage budgets and token ceilings, the review ratio, a fan-out cap and what each expectation tier is expected to cost and take, the project layer may only tighten it, `fugaro run --tier` dispatches a run at one tier, and a `--pr` follow-up keeps the tier its pull request's runs recorded.
- **A stage that runs past its own timeout stops the run, and you can read why.** It records a checkpoint report and opens a draft pull request, and `fugaro diagnose` prints that checkpoint (its trigger, why it stopped and the spend estimate) with the ways on from it.
- **More of the money is readable.** `fugaro budget show --compute` adds each repository's compute dollars from the runs bucket, the JSON of `fugaro watch` and `fugaro budget show` carries the money leased and not yet spent, `fugaro report --by mode` groups a period by the rigor mode its runs carried, and a model call whose service tier Fugaro cannot price is charged conservatively and warns instead of failing the stage.
- **A report run is a run that only reports.** A run of a report recipe writes the period's reports and skips implement, `fugaro runs digest --submit-draft` prints a redacted learning (no repository name, no run id) with the command that opens the issue form and sends nothing at all, and the digest flags a stage that ran one command five or more times.
- **Smaller changes.** A `--pr` follow-up may only raise the rigor mode its pull request ran under, `fugaro doctor` names every Secret Manager reader Fugaro did not create and who may deploy the credentials service, and a GitHub run's commits are now authored by the installation's GitHub App bot account instead of an address no account owns.

### Known limits

- Of the `governance:` block, the stage timeout is the one key this release enforces: the stage budgets, the token ceilings, the review ratio, the fan-out cap and the tiers' expectations are read by a later release, so a run is not bounded by them yet.
- An installation on an older image keeps refusing `governance:` until its images are refreshed (`fugaro update` or `fugaro image refresh`), and that is not a required step.
- A build of Fugaro without its business-licensed parts answers `fugaro report` and `fugaro coordinator` with "part of Fugaro Subscription Edition; this build does not include it", and its image ignores `governance:` with one warning; the released binary and images carry them.
- The bot-account authorship of a GitHub run's commits is not yet live-checked.
