- **Licensing updates.** Governance, `fugaro report` and the coordinator now ship as business-licensed parts of the one released binary (the Subscription terms, in `ee/`), while the core and the `fugaro runs digest` and `fugaro diagnose` commands stay MIT.
- **A repository can bound its own runs.** A `governance:` block in `fugaro.yaml` sets a stage timeout, per-stage budgets and token ceilings, the review ratio, a fan-out cap and what each expectation tier is expected to cost and take, the project layer may only tighten it, `fugaro run --tier` dispatches a run at one tier, and a `--pr` follow-up keeps the tier its pull request's runs recorded.
- **A stage that runs past its timeout stops the run, and you can read why.** It records a checkpoint report and opens a draft pull request, `fugaro diagnose` prints that checkpoint — the trigger, the runner's words for the stop, the spend the run had reached — with the ways on from it, and `fugaro doctor` now names every Secret Manager reader Fugaro did not create and who may deploy the credentials service.
- **More of the money is readable.** `fugaro budget show --compute` adds each repository's compute dollars from the runs bucket, the JSON of `fugaro watch` and `fugaro budget show` carries the money leased and not yet spent, `fugaro report --by mode` groups a period by the rigor mode its runs carried, and a model call whose service tier Fugaro cannot price is charged conservatively and warns instead of failing the stage.
- **A report run does the work it is for.** A run of a report recipe writes the period's reports and skips implement, `fugaro runs digest --submit-draft` prints a redacted learning — no repository name, no run id — with the command that files it as an issue and sends nothing, and the digest flags a stage that ran one command five or more times.
- **A follow-up keeps its own standard, and a run's commits are the app's.** A `--pr` follow-up may only raise the rigor mode its pull request ran under, and a GitHub run's commits are now authored by the installation's GitHub App bot account, so the host links them to the app rather than showing an address no account owns.

### Known limits

- Of the `governance:` block, the stage timeout is the one key this release enforces: the stage budgets, the token ceilings, the review ratio, the fan-out cap and the tiers' expectations are read by a later release, so a run is not bounded by them yet.
- An installation on an older image keeps refusing `governance:` until its images are refreshed (`fugaro update` or `fugaro image refresh`), and that is not a required step.
