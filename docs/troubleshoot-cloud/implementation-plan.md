## Conventions

`CLAUDE.md` and the rules it loads: `.claude/rules/terraform.md` does **not** apply (no Terraform change: the review-only variant and the runs bucket's lifecycle rules already exist); `.claude/rules/credentials-service.md` does not apply (no file under `internal/creds/`, `internal/credsvc/`, `SECURITY.md` or `website/content/security.md` is touched — and the tier reads no credential value at all, which is F13's point). Hermetic tests only: `internal/gcpfake`, `internal/testutil`, a `file://` `blobx` bucket, `t.TempDir()`, an injected environment and an injected backend; no network, no real home, no cloud. **No secret-shaped literal** in a test, doc or fixture: build sample secrets from fragments. Run targeted tests, never a whole package: `internal/cli` and `internal/runner` are each about 25 minutes in full, so every Command below names its tests, and `GOFLAGS=-p=2` on a loaded machine. Docs are tested: change a doc, run `go test ./internal/cli/ -run Docs -count=1` and keep every pinned fact. Comments explain why, never what. A wire or JSON shape a reader outside the binary consumes (`fugaro troubleshoot --json`, the recipe format, the run record, the task) gains fields only; no field is retyped and none changes meaning. No agent runs a live step of any check; Check 620 is owner-run. `docs/status.md` is **not** touched by this plan: the folder is new, so no row is removed and none is added (T5).

## Checks (reserved Checks 620–629; 620 used, all OWNER-RUN)

- **Check 620, the cloud tier end to end.** D2408's three parts, as one script: `bash scripts/live-checks/check620.sh` on a sandbox installation, never `belong`. It measures what no hermetic test can: that the launch path's own gates refuse the tier on a real installation (a job image older than the published policy), that the tier falls back to evidence only when it is made unavailable (the credentials service's switch off), and that a real diagnosis answers, prints what it cost, records the run and leaves no bundle behind. **You** run it, and **no agent runs any step of it**.
- **Checks 621–629** are reserved and unused.

## Release actions

- **The release notes carry one line** for the new tier (T-TC9), and **no `### For operators` step**: the whole upgrade is the one documented command, `fugaro update`, which rebuilds the job images behind its own confirmation — and the pre-flight (T-TC6) is what a person meets until it has run, with the reason and the fix rather than a second failure. No secret, no policy version, no node shape and no image contract changes, so no migration is owed and no installation is broken by the CLI that ships first.
- **Nothing in this plan runs after a deploy**: the review-only variant the tier runs on, the runs bucket's lifecycle rules over `inputs/` and `artifacts/`, and the launcher's own grant are all already deployed.

## Considered and declined

- **A new `mode: diagnose`.** Declined, D2402: it duplicates or bends the upload, record and read-back path for a name.
- **A third job variant (`-diagnose`).** Declined, D2403: Terraform, IAM, a credentials-service class and golden plans for a distinction the service does not need.
- **Uploading the source tree in the bundle.** Declined, D2404 (U1 may reverse it): the same bytes are fetched from the same public tag archive by the same function.
- **Carrying the evidence inside the task.** Declined, D2405: user text would enter a shape the console, the history and the plugin read, and the task's size limit would become the diagnosis's real bound.
- **A pre-flight built out of `fugaro doctor`'s checks.** Declined, D2401: a second implementation of the launch's judgement, and the two would drift.
- **Asking for `admin` because the tier spends.** Declined, D2406: the resolver's own table puts launching at operator, and an operator already spends by launching a run.
- **A reserved run scope for an installation-level diagnosis.** Declined, D2409: a new scope in the bucket, a special case in the runner's checkout and in every reader of a run reference, for the case the rules tier exists to answer.
- **A `live` build-tag Go test instead of a script.** Declined, D2408: the subject is a machine with no login, and the script harness is where a person-shaped precondition lives now.
- **A `fugaro troubleshoot --cloud` flag that forces the tier.** Declined: the tier order is the design (D2400), and a flag that skips the pre-flight is a flag that launches into the path that is broken — the second failure the whole tier order exists to prevent.
