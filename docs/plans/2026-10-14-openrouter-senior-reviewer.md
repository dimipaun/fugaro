# A senior reviewer through OpenRouter: implementation plan

**Goal:** put a **stronger senior reviewer inside the cheap-coder loop**, served by a provider route rather than by Anthropic directly, in the two phases the design's §10 sets: **Phase 1**, a non-Claude senior (GPT, Gemini, a larger DeepSeek or Qwen) — which works with the code as it is, so it is documentation, two missing tests and one live check; and **Phase 2**, the owner's approved opt-in that lets a provider route claim **one explicit `anthropic/<id>`**, which is the small change to M10's "Claude goes direct" rule that the design's §4 rules in and §9 lists the tests for. No code in this plan has been written or run; this is a design-to-code plan. **This PR (the one that adds this plan) is docs-only: no Go, Terraform or product-behavior file in this plan's "Files" lists is touched by it — the one exception is `docs/gcp-live-checklist.md`, Tasks 3 and 10, which IS one of the two files this PR itself edits, since reserving Checks 45 and 46 and writing their not-yet-run steps is itself a docs-only act. Tasks 1 onward are future work, gated on the owner approving the design's open questions (§8) — which the owner has already answered for Phase 2 (the ruling of 2026-10-14) and not for Phase 1's question 1, whose answer Check 45 is meant to inform.**

**Spec:** [docs/design/mixed-credentials.md](../design/mixed-credentials.md). Its owner rulings of 2026-10-14 (§1, §4, §8) are settled: an explicit opt-in is enough, the route entry lives in the local operator config or the shared project layer, a repository may choose the model but never add or enable a route, and `allow_data_to` still decides which repositories may send code. Its Path A (Claude behind the gateway with an Anthropic key) is **not** in this plan: the owner has no Anthropic key, so §10 puts it behind whichever credential exists. This plan is §10's Phase 1 (non-Claude senior through OpenRouter) and Phase 2 (the opt-in), and Path B (the OAuth reviewer stage, §5 and §10 phase 3) is deliberately absent.

**Depends on:** release 0.7.x on `main` (the M10 route table, the budget gateway, `internal/pricing`, the first-line review and the project layer are all merged). [docs/design/provider-price-catalog.md](../design/provider-price-catalog.md) is **not** a prerequisite but is coupled on two points, both stated at the task that touches them: its D8 and its §11 Phase 2 add the three `anthropic/<id>` catalog rows, which can only compile once this plan's Phase 2 has relaxed `CheckModelPattern` and `IsAlias` (P11), and its generator's `pricing.IsAlias` call site must pass the claimed IDs once this plan's Task 5 changes that signature. Nothing in this plan depends on the config-transitions work behind Check 42 or the registry design behind Check 43.

## Decisions (veto any before execution starts)

- **P1. Phase 1 ships no product code, and a task that finds itself editing Go outside `_test.go` stops and reports.** Everything a non-Claude senior needs exists and was verified above: the route table, `CheckProviderPolicy`, the pins, the price table, the gateway, `allow_data_to`, the ≥4-byte placeholder key, and `first_line_review: auto` already turning the cheap first line off for a provider-served reviewer. Phase 1's deliverables are one user-doc section (Task 1), the two tests nothing covers (Task 2) and Check 45 (Task 3). *Veto alternative:* fold Phase 1 into Phase 2 — rejected: the design's whole recommendation is that the non-Claude senior is the cheapest test of the idea, and it needs no opt-in, so nothing may gate it.
- **P2. Phase 1's test work is exactly two tests, and this plan names the four tests that already cover the rest so a task does not write them again.** (a) `internal/gateway`: one stage, one Claude call and one routed call, asserting `rep.ByModel` for **both** models, `rep.ByRoute` for the routed one only, and `rep.Used` as their sum at their own rates — the one assertion missing from `TestRouteByModel`/`TestRouteRecordedPerCall`/`TestNoFeeOnClaudeCalls`, which between them already prove the routing, the path prefix, the unchanged body, the credential header, the `route` log field and the fee split. (b) `internal/runner`: a **provider-served reviewer** run (the reverse of `TestProviderStageDisablesThinkingVars`, which has the provider on the coder): the thinking variables on the reviewer stage and absent from a Claude coder's, `first_line_review: auto` producing `implement, review` with no `review_first`, and `tier: senior` on every review. **No test in the repository has a provider reviewer today** (the config-level table and the runner-level `TestFirstLineAutoOnlyForProviderCoder` at `internal/runner/firstline_test.go:247` both put the provider on the coder). *Veto alternative:* rely on the config-level table alone — rejected: it proves the predicate, not that the review stage's model call actually reaches the provider fake with the right pins.
- **P3. The opt-in is one literal `anthropic/<id>` entry in a route's `models`, and the entry itself is the whole permission.** `CheckModelPattern` accepts an entry overlapping `anthropic/*` only when the entry contains no `*` and is spelled like an ID; `anthropic/*`, `anthropic/claude-*` and every bare `claude-*` entry stay refused, so a provider can never claim the direct path as a class. *Veto alternative:* a `allow_claude: true` boolean on the provider — rejected by the owner's ruling ("one explicit `anthropic/<id>` and not a pattern"): a boolean enables a class nobody enumerated, and it hides which model was opted into.
- **P4. `pricing.IsAlias` grows the claimed IDs as an explicit argument: `IsAlias(model string, claimed []string) bool`, with `nil`/empty meaning today's behaviour exactly.** No variadic parameter and no package-level state: the compiler then visits every one of the six call sites, which is precisely the list the design's §4 names, and a call site nobody revisited is a compile error rather than a silent refusal. The claimed IDs are honoured only after the ID's own spelling passes the plain-`vendor/model` grammar, so a claim can never smuggle `anthropic/x[1m]`, `anthropic/x:free` or a `~`-alias spelling into the pinnable set. *Veto alternative:* keep `IsAlias` and add a wrapper the old call sites keep using — rejected: the wrapper is the same relaxed function under another name, and nothing then forces the design's list to be visited.
- **P5. The claimed IDs reach `internal/pricing` as data, computed by `internal/config`.** `internal/pricing` cannot import `internal/config` (the three edges run the other way), so the set is computed by a new exported `config.ClaimedClaudeIDs(providers map[string]ModelProvider) []string` at every place that already holds the providers map — the runner's `r.d.Providers`, the CLI's `localcfg.Config.Providers`, and the gateway's route table (which already carries the merged `Models`). Nothing in `pricing` learns what a provider is. *Veto alternative:* put the claimed IDs on the `pricing.Table` — rejected: the table is a price lookup, and the pins and the config checks consult `IsAlias` before any table exists (`internal/runner/spend.go` builds the table after the environment is read, `SpendFromEnv` at `:51`).
- **P6. The claim is *derived* from the route table every time, never stored beside it.** `config.ClaimedClaudeIDs` reads the providers map; the gateway's routes are built from the same `Models` (`runner.GatewayRoute`, `internal/runner/providers.go:84`), so a model the config accepts is a model the gateway routes, by construction. There is no second list to keep in step, and the agreement test that already exists (`TestRouteAndConfigAgreeOnBaseURLsAndPatterns`, `internal/gateway/route_test.go:762`) stays the cross-check. *Veto alternative:* an `agent.claude_routes` list of enabled IDs in `fugaro.yaml` — rejected: it puts the claim in the repository's file, which the owner's ruling forbids.
- **P7. The shared project layer carries the claim in a new **top-level** layer key, `claude_models`, next to `default_profile`.** Shape: a map from a provider name the **local operator config** defines to a list of explicit `anthropic/<id>` IDs. A top-level layer key is the only shape that a repository's own `fugaro.yaml` cannot carry: `Resolve` merges only `defaults:` into the repository's tree and decodes it with `KnownFields` into `Config`, so anything under `defaults:` must be a `Config` field — and a `Config` field is settable in `fugaro.yaml`, which is the one thing the ruling forbids. `profiles:` and `default_profile:` are layer-only for the same structural reason. *Veto alternatives, both rejected:* (a) `defaults.agent.claude_models` plus a source-aware refusal at repo scope — it would be the first `InProject`-only row in `Scopes`, and the refusal cannot live in `Validate`, which sees only the merged `Config` and not `Resolution.Sources`, so it would need a new source-aware check in both `Resolve` and `Parse` (a mechanism the codebase does not have) to say something the top-level key says by construction; (b) a right of the local config alone — rejected because the owner ruled the project lead may enable it without editing local config.
- **P8. The layer may only add explicit model entries to a route the local config already defines; it can never create one.** `base_url`, `auth`, `secret` and `allow_data_to` all still come from the local operator config, so the layer cannot make a route appear, cannot point one at another host, and cannot widen who may send code. A provider name the local config does not define is refused at config time, naming it, rather than ignored. *Veto alternative:* let the layer name a route's secret too — rejected: that is a credential decision, and the ruling keeps credentials with the operator.
- **P9. A provider-served senior turns `first_line_review: auto` off, and every document this plan writes says so.** `FirstLineOn` is on only when a provider serves the coder **and none serves the reviewer** (`internal/config/config.go:180`), so the recipe in Task 1 has no cheap first line, and a recipe step with `bounce: first_line` is unreachable under `auto` — a senior verdict of `changes` goes to the coder's `fix`. The docs say how to keep the cheap line (`first_line_review: on`) and what that costs; Check 45 records which of the two the owner ends up wanting. *Veto alternative:* change `auto` to ignore the reviewer — rejected: it is merged, tested behaviour (`internal/config/firstline_test.go:42`), and the rule is right on its own terms (a senior already reviews, so the cheap line adds a round without adding a reviewer).
- **P10. A claimed Claude model is a provider model in every respect, and nothing is special-cased for it.** Its stage gets `ProviderRouteVars` (thinking and the experimental betas off, `internal/runner/agentenv.go:62`), its background requests go wherever `EffectiveBackground` sends them (`internal/config/providers.go:377` — the coder's model when `agent.models.background` is unset), it is charged at the route's price with `route_fee_pct`, and it is subject to `allow_data_to`. That last one is the point: **the opt-in moves which host sees the code, which is exactly why the owner's ruling leaves `allow_data_to` in charge.** *Veto alternative:* exempt a claimed Claude model from the provider-stage variables so it keeps thinking — rejected: the fields Claude Code adds when thinking is on are the ones the route's field allowlist refuses (Check 25 step 4), so the exemption would trade a working call for a 400.
- **P11. The catalog's `anthropic/<id>` rows and this plan's Phase 2 land in the same release, in either order, and until they do the owner prices the claimed ID by hand.** `docs/design/provider-price-catalog.md` D8 hard-errors in its generator on an allowlisted ID `IsAlias` refuses, and its §11 Phase 2 adds the three Claude rows; after Task 5 the generator must pass those IDs as claimed (its `TestGeneratorRefusesIsAliasKey` keeps refusing everything else). Until that lands, a claimed ID needs `model_prices` in the local config — which Task 6 is what makes acceptable there. *Veto alternative:* ship the claim without the price path — rejected: a claimed ID with neither a catalog row nor an override is refused at bootstrap by `CheckPins` (`pins.go:30-32`), so the feature would look broken on the first run.
- **P12. Check 46 leads with the refusal and ends with the `cache_read` comparison, because that comparison is the only open technical question this phase has.** M10 decision 2's reason for the direct rule is the prompt-cache markers; OpenRouter forwards `cache_control` but whether Claude Code's markers **survive** the Anthropic-compatible endpoint is unmeasured (design §4). A routed Claude senior that never reports a cache read is charged at the full input rate, so the comparison is not a curiosity: it is the difference between a senior that costs list price and one that costs several times list price. *Veto alternative:* judge the phase by review quality alone — rejected: the quality question is the owner's to answer in the check, but the caching one has a **number**, and a number is what a live check is for.

## Global Constraints

From the design:
- One explicit `anthropic/<id>` per route entry, never a pattern (P3); with no such entry the "Claude goes direct" rule is unchanged and everything is refused exactly as today.
- A repository's own `fugaro.yaml` may choose the model (`agent.models.reviewer`) and can never add or enable a route (P7, P8).
- `allow_data_to` on the provider still decides which repositories may send code: the opt-in changes which host sees the code, not who may send it (§4, §6).
- The opt-in lives in the local operator config **or** the shared project layer, and in no other place (P7).
- `first_line_review: auto` turns the cheap first line **off** when the reviewer is provider-served (P9).
- No new secret: the existing `anthropic-api-key` secret keeps its ≥4-byte placeholder role, and the provider's own key is the only one that reaches OpenRouter (`internal/agent/env.go:91-104`, `internal/infra/spec.go:565`).

Project rules (carried over from this repository's existing plans):
- Every task's own test run is in the foreground, `-count=1`, and `-race` where the package's existing tests use it.
- Fakes only in tests: no real OpenRouter call, no real key; the hermetic fake upstreams in `internal/gateway/anthropicfake` are the pattern (an Anthropic fake and a second fake under a path prefix, as `newRouted` builds them).
- Docs must match behaviour: `GOFLAGS=-p=2 go test ./internal/cli -run 'Docs|Lint' -count=1` stays green throughout. Phase 2 adds no `fugaro.yaml` key (the claim is a *layer* key), so no schema row is added — but `docs/project-layer.md`'s table is kept equal to `config.Scopes` by `TestScopeTableMatchesDocs`, so a task that edits that table runs that test. A task that finds the lint refusing something stops and reports rather than loosening it.
- `fugaro verify build` / `fugaro verify test` are the only build and test entry points for this repository's own conventions; a task runs them before it is considered done.
- Checks 45 and 46 are the owner's own tasks, run once each, **sandbox project and sandbox repository only, never the `belong` project, and no agent runs any step of either**.

## Review Focus (mutation-proof notes)

1. **An `anthropic/<id>` a route does not claim becomes pinnable.** The failure this whole phase guards against: the relaxation leaking from "the IDs a route claims" to "any `anthropic/` ID". Pinned by `TestUnclaimedClaudeIDStillRefused` (Task 6) — for a providers map that claims `openai/gpt-5*` only, an `anthropic/claude-sonnet-5.5` pin fails `CheckPins`, `CheckProviderPolicy` and `model_prices` alike — and by the unchanged `want true` rows of `alias_test.go` when the claimed set is empty.
2. **A wildcard claim sneaks past `CheckModelPattern`.** Pinned by `TestClaimMustBeExplicit` (Task 4): `anthropic/*`, `anthropic/claude-*`, `anthropic/claude-*[1m]`, `claude-*` and `claude-sonnet-5-5` are all still refused, from a route *and* from a repository's `fugaro.yaml`, while `anthropic/claude-sonnet-5.5` is accepted.
3. **A repository enables a route through its own `fugaro.yaml`.** Pinned by `TestRepoCannotEnableARoute` (Task 7): a repository file carrying `claude_models:` at the top level, or `agent.claude_models:`, is refused as an unknown key, and the existing `TestRepoCannotAddProvider` cases (`internal/config/model_providers_test.go:183`) stay green untouched.
4. **The claim is accepted by the config check and refused by the gateway (or the reverse).** Pinned by extending `TestRouteAndConfigAgreeOnBaseURLsAndPatterns` (`internal/gateway/route_test.go:762`) with the claimed ID in both directions: the entry the config accepts, the gateway accepts; the entries the config refuses, the gateway refuses, with the same `ClaudePatterns` text.
5. **The claimed set is lost between the config and the price table, so a claimed ID is refused for having no price.** Pinned by `TestClaimedClaudeIDIsPriced` (Task 6): one fixture route claiming the ID, an override keyed by it, and the run's table charging the override's rates — the test fails if the claimed set does not reach `Table.With`'s `validate` (`internal/pricing/pricing.go:213`).
6. **The override env path rejects the claimed ID although the local config accepted it.** `fugaro init --repo` writes `model_prices` into `FUGARO_MODEL_PRICES`, and the runner re-parses it with `pricing.ParseOverrides` (`internal/runner/spend.go:118`), which validates again; a claimed set that reaches the local config but not that path makes the feature work in `fugaro validate` and fail in the job. Pinned by `TestClaimedClaudeIDSurvivesProvidersAndPricesEnv` (Task 6), which round-trips `ProvidersEnv` and the price env through the runner's own parsers.
7. **`CheckPins` grows a parameter and a caller keeps the old behaviour.** Pinned by `TestCheckPinsTakesTheClaimedIDs` (Task 6) at both call sites' shapes (`internal/runner/gateway.go:346`, `internal/cli/validate.go:144`): the same agent, priced, refused without the claim and accepted with it.
8. **The layer key is merged into the providers but not before the gateway's routes are built.** Pinned by `TestLayerClaimReachesTheGatewayRoutes` (Task 7): with the claim only in the layer, a run's routes carry the claimed model and the review stage's call reaches the provider fake. This is the ordering the runner's bootstrap has to get right (`r.d.Providers` is merged before `checkProviderBudget`/`checkProviderModels` and before `gatewayRoutes`).
9. **A layer claim naming a provider the operator never configured silently does nothing.** Pinned by `TestLayerClaimUnknownProviderRefused` (Task 7): the run fails at bootstrap naming the provider and the key, rather than running with the model unpinned for its route.
10. **The claimed Claude stage is treated as a Claude stage, so thinking stays on and the call is refused.** Pinned by `TestClaimedClaudeStageGetsProviderVars` (Task 8): the reviewer stage's process environment and managed settings carry `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` and `MAX_THINKING_TOKENS=0` (P10), asserted exactly as `TestProviderStageDisablesThinkingVars` asserts them for a coder.
11. **The mixed stage's charge is the sum of two models and a test only checks the total.** Pinned by `TestMixedStageChargesEachModelAtItsOwnRate` (Task 2): `rep.ByModel[claude]`, `rep.ByModel[routed]`, `rep.ByRoute[route]` and `rep.Used` are asserted as four separate numbers at rates that differ, so a mutation that prices one model at the other's rate fails on the per-model figure and not only on the total.
12. **`first_line_review: auto` quietly runs the cheap line for a provider-served senior.** Pinned by `TestProviderReviewerSkipsTheFirstLine` (Task 2), which asserts the stage list (`implement`, `review`) and the review tiers (`senior:…` only) — the runner-level witness for the config-level predicate that `internal/config/firstline_test.go:42` already pins.
13. **A document tells the owner the cheap senior needs no placeholder key.** `internal/agent/env.go:91-104` fails an `api-key` run without an ≥4-byte `ANTHROPIC_API_KEY` even when no Claude model is pinned, and `internal/infra/spec.go:565` mounts the secret for every `api-key` workflow, so `fugaro init --repo` will ask for it. The doc must say a placeholder the owner types is enough and that it is never sent to OpenRouter (the coder's and the senior's calls both carry the provider's own key). There is no test; Check 45 step 2 is the live witness, and the review is the check.
14. **Check 46 reports a caching conclusion it did not measure.** The comparison is `cache_read` (and `cache_write_5m`) token counts and `charged_micros` on the reviewer's own `model call` lines, from two runs of the same task, one direct and one routed — never "the charge looks higher, so caching must be broken". Pinned by the check's wording, which asks for the token counts themselves.
