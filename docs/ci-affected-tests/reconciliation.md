# CI selects tests from what changed: reconciliation

**Status: plan only; nothing is implemented; no task approved.** Checked against `origin/main` at `38ce5c0e2` (one commit past #3301), 2026-11-20. Round 1 of the independent review amended F2-F4, F9 and R1, R2, R4, R6-R8 and added F11-F15, R10, R11; round 2 amended F1, F2, F12, R1, R5, A3 and added R12; round 3 (the last) amended R8 (what "unmapped" means), added the sourced-shell reach to F2's consequence (CS2a) and fixed the plan's `actions: read` and CS6b statements. Where this document disagrees with [spec.md](spec.md), this one wins.

## Assumptions

- **A1.** "Selected" means a subset of the 27 shard legs of `.github/workflows/ci.yml`'s `shard` job, chosen per dispatch; the `check` (vet), `terraform` and `rules` jobs are separate and are addressed in F7.
- **A2.** There is no pull-request trigger and no push trigger (`workflow_dispatch` only, `ci.yml` lines 1-8, owner ruling 2026-11-07), so "what changed" is a range between two commits of `main` or of a branch the owner dispatches on, not a pull request's diff.
- **A3.** The selector is correct when it never selects fewer tests than a full run would have failed on; speed is second to that (spec item 4). A test that depends on the environment (the date, the runner image, a download) is bounded by the nightly full run, not by the selector.
- **A4.** The five numbered items of the spec are one capability. It has no capability map: one module, `ci-select`.

## Findings

- **F1: there is no per-commit diff to read, and #3301 already built the first one.** On dispatch the `changes` job's `docs_only` is only ever computed for `pull_request` events (`ci.yml`, `changes` job's `diff` step), so it is always `false` here. #3301 added a `live` step that takes the head of the last successful `ci` run on `main` (`gh run list --workflow ci --branch main --status success`), diffs it against `GITHUB_SHA` through the compare API and decides one boolean. The selector generalises that step's idea (a base, a changed-file list, a "doubt runs everything" rule) and replaces its mechanics (R2); its output is a matrix, not a boolean. *Consequence:* R2 (the base), and the live-script gate is replaced by the selector's own rule for `scripts/live-checks` (CS6).
- **F2: the import graph is not enough, and by a wide margin.** 85 of the 677 test files in `internal/cli` contain a `"../../` path (153 are `docs_*_test.go`), and `plugin` and `scripts` tests read repository files too; the pinned facts include source files of other packages: `plugin/images_skill_test.go` reads `internal/catalog/fetch.go` and pins a sentence of it; `images/cloudbuild_test.go` reads `.github/workflows/ci.yml` (TestCIWorkflowPermissionsScoped, which failed on the first draft of #3301 for exactly this reason). A change to `internal/catalog/fetch.go` therefore reaches `./plugin`, which imports nothing from it. A second kind of reach hides in test code that builds another package by import path: `internal/cli` tests (`init_test.go`, `update_lock_test.go`) build `internal/infra/tf/faketerraform` with `go build` and run the binary, and that package is not in `internal/cli`'s import graph, so an edit to it selects nothing that would fail. A third kind hides in non-test helpers: `internal/testutil/fixture.go` (`FixtureFiles`) walks `testdata/fixture-repo` for `internal/runner` (34 test files), `internal/e2e`, `ee/governance`, `internal/verify` and `internal/image`, and none of their `_test.go` files names the path, so a scan of test files alone never maps `testdata/fixture-repo`. *Consequence:* D3043 (a recorded read-map), CS2a (a `go build`/`go run` of a module path counts as a read of that package's closure, a non-test Go file that reads a repository path gives its reads to every test package that imports it, and a shell script a test executes brings in the files it sources, so `scripts/retry.sh` reaches `internal/cli` through `scripts/release-gate.sh`), CS2b, CS5.
- **F3: more than three packages walk the whole repository.** `ci.yml`'s own matrix comment names the slow ones: `internal/backend/gcp` (271s), `images` (201s), `plugin` (145s). Others walk too: `ee/register` and `internal/eeboundary` walk `../..`, and 37 test files walk directories. A walker has no finite file list: the read-map marks it `any` (R4), and the scan must not special-case three packages.
- **F4: the shard split is three different rules, and one of them cannot be subset.** `rest` hashes packages; `internal/runner` and `internal/issues` split by a hash of the test name (`of: 2`); the rest of `internal/cli` and `scripts` split by a hash of the test name; the live checks split by `LIVE_CHECK_SHARD`. `internal/cli`'s update tests hang when a subset of the package runs without the tests that precede them (`ci.yml`'s matrix comment), so `cli-update` takes `^TestUpdate` whole. *Consequence:* the unit the selector chooses is the package, and for `internal/cli` the two families `update` and `other`; a chosen package runs every leg of its family (R3).
- **F5: timings are written and never read.** Every shard uploads `test-times-<name>` (`ci.yml`, the `timings` step and the `upload-artifact` step): a TSV of elapsed seconds, package and test. Nothing consumes it. *Consequence:* R5, CS3.
- **F6: the release gate asks for success of three check names on the tag's commit.** `scripts/release-gate.sh` line 110: `names=("test" "terraform" "rules")`, each a GitHub Actions check run that must be `success`; a skipped run is not success, and the gate also accepts a merged pull request's head when its tree is identical (`identical_tree_checks`). A selected `test` is green with fewer tests behind it. *Consequence:* D3040, R1, CS7.
- **F7: `terraform` and `rules` are separate jobs the gate also requires.** They cannot be skipped on a selected run without failing the gate's names on the tag's commit, but the tag's commit gets a full run (D3040), so skipping them on selected runs is safe and is what the selector does when nothing they read changed (R6).
- **F8: CI is dispatch-only by an owner ruling, and a nightly run breaks it narrowly.** Ruling 2026-11-07 ("No CI on push": dispatch by hand, in batches). A `schedule:` trigger is the one addition D3041 makes; it is not a push or pull-request trigger, so what the ruling protected (a run per push) stays out.
- **F9: `ci.yml` is edited only by the owner's word, and a staged copy trips guards.** `images/cloudbuild_test.go`'s staged-copy guard admits differences inside the `shard` job only; the README's `ci.yml` section records the pattern used since 2026-11-11 (the edit is written down; the owner says "copy it" and it lands as a pull request, as #3301 did). CS6 follows it.
- **F10: selected-run semantics are observable only through the `test` check's name.** Required-check names are fixed (`test`), so a selected and a full run cannot be told apart by name. *Consequence:* R1 (the run names itself, `run-name`, and the gate reads it).
- **F11: the changed-file list #3301 reads can be wrong.** The compare API is three-dot (it diffs from the merge base), its `files` list stops at 300 files with no error, and `.files[].filename` omits the old name of a renamed file, so a test reading the old path is missed. *Consequence:* R2 (a two-dot tree diff from a full checkout).
- **F12: embedded files map to nothing.** `internal/budget/rules/rules.json.tmpl` is `go:embed`ded and named by seven docs test files (five of them by full path); the import graph sees no edge from the file to its package's importers. `go list -json` reports `EmbedFiles` and `TestEmbedFiles`. *Consequence:* CS1 (embeds are edges), CS5 (spec item 5: every embed against the map).
- **F13: the gate cannot read a run's title today.** `scripts/release-gate.sh`'s `check_state` reads check runs, which carry no `display_title`; the title is on the workflow run (`actions/runs?head_sha=`), and the check run joins to it through its `check_suite`. The gate's `test` state also combines every `test` run on the SHA, so a red selected run would block a tag, and the identical-tree fallback would let a selected `test` on a merged pull request's head vouch for the tag. The publishing workflows (`release.yml`, `images.yml`, `mobile-release.yml`, `console-release.yml`) grant the gate no `actions: read`; whether a token without it can list runs is unverified. `scripts/release.sh`'s hotfix path dispatches CI with no `full` input. *Consequence:* R1, CS7, CS7b, CS6.
- **F14: the `terraform` and `rules` jobs depend on far more than their paths.** Under their build tags the terraform job's Go tests depend on about 70 internal packages and the rules job's on about 50 (`go list -deps -test -tags terraform|firebase`); an edit to `internal/rtdb` or `internal/budget` reaches the budget-rules suite. *Consequence:* R6 (the graph is built under the union of the tags).
- **F15: a scheduled run has no `inputs`.** `run-name` and the selector's `full` flag must branch on `github.event_name == 'schedule'`, or the nightly is titled and run as selected and no full base ever exists. *Consequence:* R11.

## Resolutions (one defensible answer each)

- **R1: a run names itself, and the gate reads the title of the workflow run that owns the check.** `ci.yml` gets a `full` dispatch input and `run-name: ci (full)` or `ci (selected)` (R11 for the schedule). `scripts/release-gate.sh` lists the workflow runs of the tag's SHA, keeps the `ci` runs titled `ci (full)` (or exactly `ci`, admitted only for a SHA whose `ci.yml` has no `run-name:`, the title before CS6 names runs), reads their check suites' `test`, `terraform` and `rules` (only those three: the console's legs under `GATE_REQUIRE_CONSOLE=1` come from `console-tests.yml` and keep today's reading) and requires success from those, taking only runs of the `ci` workflow file (`.path == ".github/workflows/ci.yml"`); a `ci (selected)` run is ignored, not counted (D3040). The identical-tree fallback applies the same title rule to the pull request head's runs. The publishing workflows' gate jobs get `actions: read` (CS6 writes it down), and the hotfix path dispatches `-f full=true` (CS7b).
- **R2: the base is the head of the last successful `ci (full)` run on `main`, and the changed files come from a two-dot tree diff.** The select job checks out with `fetch-depth: 0` and runs `git diff --name-only --no-renames <base> <head>`, so the 300-file cap, the merge-base reading and the dropped rename of the compare API all go away (F11). A selected run is never a base (a miss would compound); the nightly produces a full base a day.
- **R3: the unit is the package, with the two cli families kept whole.** A package with a changed non-test or test file, or reached through the import graph or the read-map, runs every leg of its family; a package the selector did not choose is simply not in the matrix. `rest` hashing is replaced by the packer (R5) over the chosen packages.
- **R4: a package the read-map marks `any` runs unless every changed path is one the map lists as outside its reach.** Every walker is `any` (F3), and so is a package whose tests build another package by import path unless the scan lists that package's closure (F2). The map records both what a test reads and, for a walker, the paths it ignores.
- **R5: timings come from the last full run's `test-times-*` artifacts, and legs are packed by longest-first greedy.** The selector downloads them with `gh run download`; a missing or failed download means equal weights and the run stays selected. A leg's budget is the slowest chosen package; `internal/cli` families keep their own splitting.
- **R6: the import graph is built under the union of the tags (`terraform`, `firebase`, `docker`, `live`) and every job is chosen from it.** `terraform` runs when a changed path reaches a package or root its steps run; `rules` when a changed path reaches its emulator suite (F14); `check` (vet) always runs, because a build break anywhere must fail.
- **R7: a commit that changes only documents runs the packages the read-map says read a changed file, as whole families.** That is every Docs-reading package: the `internal/cli` families, `plugin`, `images`, `internal/config`, `internal/runner` and any other the map names, not a `-run Docs` filter (the repository's own docs-only list in `ci.yml` names more than `Docs`). `website`'s `npm run check` is not a job of `ci.yml` today and this plan does not add one.
- **R8: every doubt is a full run:** no last full run on `main`, a failed diff, an unmapped path (a path no read-map entry names, no graph package owns and no `ignores` rule excludes; an `any` entry does not map every path), a `go.mod`/`go.sum`/`ci.yml`/selector/read-map change, a missing read-map, an input of `full`, the schedule. The selector prints the reason on the run's summary. Staleness of the map is CS5's test, not a clock.
- **R10: the committed read-map is refreshed by a normal pull request from the nightly's artifact, never by a push from CI.** The nightly job holds `contents: read`; `ci-readmap --from-artifact <dir>` (CS2b) merges the traced reads into the committed file.
- **R12: a release dispatches its own full run.** The ordinary path of `scripts/release.sh` waits for checks on main's tip and on the bump's merge commit and nothing starts a full run there; CS7b makes it dispatch one (`-f full=true`) when the merge commit has none and wait for the run whose head is that commit, and the hotfix path does the same on its release branch, passing the flag only when that branch's `ci.yml` declares the input (an older branch refuses an unknown input with a 422).
- **R11: the nightly names itself.** `run-name` and the select job branch on `github.event_name == 'schedule'` (F15): a scheduled run is `ci (full)` and takes no input.
- **R9: the live-script gate of #3301 is replaced, not kept beside the selector:** `scripts/live-checks` and the four trees it reads become a read-map entry for `./scripts`; the `live_scripts` input is removed in CS6.

## UNVERIFIED

- The runtime trace's mechanism: whether `strace -f` is installable on `ubuntu-latest` without a cost that defeats the saving. A Go-level hook cannot see a child process a test builds and runs, so it is not an alternative; if `strace` is not practical, CS2b marks every package that spawns a build `any`. D3043 holds either way.
- That the nightly run's cost (one full run) is below the saving; the measured full run is 16 min wall, ~175 runner-minutes.
- Whether a `GITHUB_TOKEN` without `actions: read` can list workflow runs on a public repository (F13); CS7's first step measures it, and CS6 writes `actions: read` on the gate jobs either way.
- That `gh run download` of 27 artifacts is fast enough inside the selector job; CS4 measures it, and a failed or slow download means equal weights (R5).
