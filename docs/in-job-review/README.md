## What this work checked, and how

**Checked against `origin/main` at `82ba600d984a420c595cf06417af6d781c18535a`, on 2026-10-19.** `graphify` has no graph for this repository (there is no `graphify-out/`), so every claim was located with `git grep` and then read in place; every path and Go symbol cited was re-checked to exist on `82ba600` before it was written. Line numbers are never cited; a few appear inside quoted code only where the quote is the point.

Two corrections to the brief, recorded in the reconciliation itself and repeated here because they change how its findings read:

- **The repository had no `.claude/rules/` when this was written; it has had one since 2026-10-23.** The root `CLAUDE.md` (added 2026-10-23) is a short guide, and `.claude/rules/` (added the same day) holds short path-scoped rule files (terraform, console, mobile, website, credentials service) that load when an agent touches matching files. The **Rule** class therefore means a conflict with [SECURITY.md](../../SECURITY.md), [CLAUDE.md](../../CLAUDE.md), a `.claude/rules` file, a design or plan document, or a rule the code enforces, and each Rule finding names which.
- **"Agents never force-push" is not what the repository says.** The runner pushes with `--force-with-lease` on its own `fugaro/<run-id>` branch (`internal/gitops/gitops.go` `Push`, `PushExisting`, guarded by `checkRunBranch` and `tipBelongsToRun`); checkpoint pushes are fast-forward only (`gitops.PushFastForward`, which resolves `ErrNotFastForward`); the base branch is never pushed at all. The consequence matters for §8 of the spec and is reasoned out in the reconciliation §1.2 and finding #28 — and it is why §8 is a question for the owner rather than an assumption either way.

**How this folder is pinned.** There is no registry test over `docs/` in `internal/cli`: nothing pins the set of docs folders, and nothing pins a folder's documents on its behalf, so a folder that wants its documents pinned writes its own file — this one is `internal/cli/docs_in_job_review_test.go`. That is the convention and not a guarantee, in either direction — [docs/mobile/](../mobile/README.md)'s pinned documents are pinned by the test files that name them (`internal/cli/docs_mobile_plan_test.go` pins the plan's Phase 6 approval, `internal/cli/docs_voice_switch_test.go` pins the P5.3 design's claims against the files it cites); the folder is pinned one document at a time and not as a whole, so a document there that no pin names is a document nothing pins — its `spec.md` and `functional-spec-v0.1.md` carry no pin as of this writing — and `internal/budget/rules/emulator_mailbox_test.go` is the one `_test.go` outside the `docs_*` convention (the naming convention a per-document pin follows) that may name the folder (its comment pointed at `docs/mobile/functional-spec-reconciliation.md` until P6.4 reworded it) — while [docs/releases/](../releases/README.md) is covered only through the release-note precondition [scripts/release_test.go](../../scripts/release_test.go) exercises, not by a pin of its documents. It fixes the status line above word for word and the two file names, [spec.md](spec.md)'s title, status line and all ten section headings (it is the owner's text, unchanged), the reconciliation's findings as #1..#43 with no gap and one of the five class words each, its questions as Q1..Q17 with no gap and this index's own ranges (checked against what the reconciliation actually carries), the owner's answers as the sets the reconciliation marks — all seventeen answered on 2026-10-19, each in its own question's block, and the questions Q9 constrains counted from the questions themselves rather than from the summary of them, in both places the answer lists them — Q9's own answered paragraph and §5's list, each checked against the questions' own "Constrained by" lines — the two brief corrections above as statements rather than mentions, and the "no D-number, no check number" claim; it resolves every load-bearing citation in both documents against the tree; and it pins finding #40's evidence as the substance rather than a mention — the record's schema has no signature field, and the tree's only MACs are the GCP test fakes' own JWTs — so the first version of that sentence, which claimed that a grep for `hmac` under `internal/` found nothing at all, cannot come back. Every "only in" claim gets the same treatment: a sentence saying a thing appears only in one place is falsified by its own words once the document is in the tree, so each one names this document's own sentences as the second place — or, where the claim was about the record or the environment rather than about the tree, is scoped to the thing it is really about — and the pin holds each corrected form and refuses each absolute one. The same treatment is given to how a review would reach the console: the corrected sentence names `diagnose --json` and the `findings` row the console renders as severity, file and summary, the retracted route ("only if `runs ls --json` carries it") and the retracted citation (a `reviewed[].verdict` pin the console contract does not carry) are refused, and the tree fact behind it — no `Findings` field on `runview.Row` or on the watch documents — is asserted rather than stated, so one appearing fails the pin. Every `_test.go` that names `docs/mobile` is asserted to be a `docs_*_test.go` file or one of the exceptions that pin names, so a test of another subject that names the folder fails rather than quietly widening the sentence above (the first version of that half asserted the exact set of naming files and went red as soon as a third landed); the exception list is held to the one file named above, and each pin named above is held to naming a path into the folder. It deliberately cites no `console/` path — the module's console boundary allows one exception only (`TestConsoleIsOutsideTheGoModule`'s `consoleBoundaryAllowList`, plan Task 0.3 a3), so where the reconciliation cites the console's own files the pin stops at the module's edge and the prose carries the claim.
